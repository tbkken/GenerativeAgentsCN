# Skill 编写规范

Skill 和 Brain 的行为由 `SKILL.md` 描述。公共资源由用户创建或显式导入；系统启动时不填充旧技能。实验复制完整技能闭包，Run 再复制完整实验；修改公共技能不会改变已有实验或运行证据。

创建时只区分“技能”和“大脑”。生成式技能可调用子技能、脚本和接口，是否组合由正文决定，无需另建“技能包”类型；决策技能根据自然语言正文解析出的配置返回判断结果。大脑负责实验每轮的行为入口。内部类型分别为 `skill` 和 `brain`；导入导出的资源包只是文件交换形式。

公共资源的正文与附件保存在 Studio 数据库，编辑器围绕 `SKILL.md` 展示和保存内容。手写技能目录采用 `skills/<key>/SKILL.md`，大脑采用 `brains/<key>/SKILL.md`；交换包内统一使用 `skills/items/<key>/SKILL.md`，类型记录在资源索引中。

技能名称分为显示名称和稳定键。`display_name` 用于中文展示，`name` 仍为小写英文、数字和连字符组成的稳定键；正文以 `$name` 引用该键。修改显示名称不会改变技能引用。显示名称保存在 `SKILL.md`，随公共资源、实验副本及交换包一起保存；未填写显示名称时展示稳定键。

## 文件与调用关系

技能详情以 `SKILL.md` 为入口，侧栏同时展示真实文件与调用关系：

- `$skill-key`：子 Skill 的稳定键，可展开其子技能和接口依赖。
- `@interface-name`：运行时接口的稳定名称，点击可查看说明。
- `scripts/`：该技能实际携带的确定性脚本文件；正文提到文件名不等于文件已存在。

正文可直接写“先调用 `@world-perceive` 观察当前位置，再将观察结果交给 `$choose-next-action`”。标记用于确定性解析，周围的自然语言负责表达调用条件、输入来源、结果用途和停止方式。普通文字里的接口名字不声明依赖。

编辑 `SKILL.md` 时，可点击“插入接口”，在弹窗中查看可用接口的中文用途和规范名称，再选择插入。编辑器在正文光标或选区处插入 `@接口名称`，并同步更新调用关系；这一步仅编辑文档，保存后才更新资源，也不会立即执行接口。编辑脚本时不提供接口标记插入。

调用关系是正文和附件的派生视图，不是版本、继承或执行流程。编辑根文档时展示当前输入的引用，保存后以服务端结果为准；子技能内容取当前资源范围内的保存内容。缺失子技能、未知接口和非法循环必须在封存前解决。

## 文档结构

```markdown
---
name: choose-next-action
display_name: 选择下一步行动
description: 根据当前观察和持久记忆，提出一个有依据的行动建议。
---

# 选择下一步行动

## 使用时机

需要根据当前位置和已完成事项选择下一步行动时使用。

## 操作说明

1. 调用 @world-perceive 获取当前可见空间、对象和附近事件。
2. 调用 @memory-stream-search 检索尚未完成的计划，区分意图和已确认事实。
3. 如需移动，用 @world-navigate 检查真实感知或记忆中的目的地。
4. 将行动建议、参数来源和判断依据返回调用者。
```

这是适用于 2D 空间环境的编写示例，不是自动安装的公共技能。子 Skill 的输出可以成为后续 Skill 的输入，Brain 自行决定调用顺序、条件与停止方式。需要多个步骤时按真实进度推进，不按固定 Step 编排业务。

## Skill 之间的输入与结果

生成式 Skill 直接接收调用者提供的自然语言。通用执行层保留输入原文，不额外调用模型将情境抽取成结构化任务参数；普通 Skill 的结果也以原文返回调用者。任务目的、相关背景、条件与结果用途由 Brain 或调用者的 SOP 说明。

模型调用子技能时使用 `call_skill`，提供 `name`，并从以下两种输入方式中选择一种：

| 参数 | 使用方式 |
| --- | --- |
| `input_text` | 直接写给子技能的自然语言任务与材料；需要补充条件、组合多份结果或调整目的时使用。 |
| `input_from` | 填写同一调用者在本次执行中已成功完成的直接子技能调用的 `tool_call_id`；运行器取出该次返回的 `output_text` 原文，直接作为下一技能的输入。 |

`input_text` 与 `input_from` 严格二选一。引用针对一次实际调用，不按技能名称查找，也不跨参与者或跨次执行取用结果。引用传递不调用模型重新概括、抽取或转换文本；技能结果原有的空白和格式一并保留。决策技能的结构化判断结果也按其原有结果文本传递，不改写成自然语言。

`name` 是必填的调用目标，必须属于当前 Skill 明确引用的子技能；子技能返回的自然语言内容仍可自由组织。运行器在执行批次中任何工具前，检查工具封装及所有子技能调用的格式。子技能空参数、缺少目标、错误的输入类型或无效结果引用都会阻止该批次执行，不产生部分副作用。模型格式错误最多追加两次纠错请求，共享首次请求的总超时预算，并可取消；传输错误仍按模型配置的请求次数处理。接口自身的参数、权限和业务条件仍由身份绑定接口校验，拒绝结果返回给 Brain 决定后续行为，不重放已执行的调用。纠错耗尽时，Brain 回滚本轮未提交副作用，以带有失败原因的 WAIT 结束本轮，并留下 Agent、Step 和错误明细；这类格式失败不会因连续出现而终止整个 Run，也不能当作智能体主动等待或正常活动。合法 WAIT 不计入故障。

例如，Brain 按 SOP 调用 `$collect-observations`，收到该次调用的结果后，判断需要 `$explain-observations` 继续处理；调用后者时以 `input_from` 引用前一次调用的 ID，即可交付完整结果。调用顺序、分支与停止方式仍由 Brain 或上层 Skill 决定，运行器只校验并执行本次选定的调用。

这些输入方式只改变技能间材料的传递。接口、API 和脚本所需的精确参数仍按各自合同校验；身份、空间、时间、权限和世界事实仍来自运行时。自然语言中的坐标、动作或完成描述不能替代真实感知、接口校验与 World Commit。

执行保护分别限制调用深度、每次 Skill 执行的模型轮数和本轮整棵调用树的工具次数。当前运行器默认最多嵌套 8 层子技能（Brain 深度为 0）、每个 Skill 32 轮、每名参与者每个 Step 合计 128 次工具调用；格式纠错属于同一模型轮。子技能调用、脚本和接口共同计入整树工具次数，每个 Step 重新计数。这些是独立的安全上限，不规定 Brain 的业务顺序，也不限制连续 WAIT 的步数。

任一执行预算耗尽时，运行器阻止下一次超额执行，记录预算类型、上限、已用次数及目标 Skill；Brain 或对象回滚本轮未提交副作用，以带有预算原因的 WAIT 结束当前轮。预算回退计入可定位的质量明细，不累计为导致整个 Run 失败的连续错误。重复调用、无进展、取消和严重执行错误仍分别按原有保护处理。

## LLM 类型与决策问题

技能配置中的“LLM 类型”默认选择“生成式模型”（`generative`）。选择“决策模型”（`decision`）后，继续用自然语言编写完整 SKILL 正文，说明要判断什么、分类候选项或评分等级。配置时调用一次生成式模型，从整篇正文识别是/否、多分类或评分问题，并提取候选项与等级；页面只读展示解析结果，不提供人工问题表单。

在模型中心编辑一项生成式模型，勾选“用于解析决策 Skill”并保存。Studio 统一使用这项模型解析公共技能和实验内技能，Skill 详情无需再选择解析模型。这项设置及其凭据只保存在 Studio 作者侧，不写入 Skill、实验或 Run 包。切换为决策类型时触发解析，正文修改后保存前重新解析，也可点击“解析正文”或“重新解析”。核对页面显示的类型、候选项和等级是否符合正文；需要调整时修改自然语言正文并重新解析。解析失败或结果与正文不匹配时，先修正并完成解析，再保存和使用。

每个解析问题的 `instructions` 都保留完整 SKILL 正文原文；生成式模型只提取类型、候选项等结构，不改写或缩短决策指令。保存时，系统把 `llm_type: decision`、派生的 `decision_questions` 和正文摘要 `decision_prompt_sha256` 写入 `SKILL.md` frontmatter。问题和摘要由配置页生成，正文改变后必须重新解析；缺失或过期的解析结果不能入包执行。手写源码正文也须经过配置页解析、保存后再用于实验。这些字段记录正文对应的解析结果，不构成资源版本或引用锁。

运行时直接调用 Laya：调用者提供的实际情境作为 `state`，保存的问题配置作为 `questions`，返回的 `answers` 交给调用者。决策技能执行时不再调用生成式模型解析正文或转换情境，也不执行生成式对话循环。

在模型中心添加决策模型，服务地址填写 `http://127.0.0.1:5003/v1` 或完整地址 `http://127.0.0.1:5003/v1/systemone`，模型名填写 `laya-multilingual`。当前本地服务无需 API Key；保存时地址统一为 Base URL，调用使用 `POST /systemone`。在实验模型详情中选择或配置决策模型，检查实验内技能是否需要它。决策模型为可选配置；实验含决策技能时必须配置。公共试运行使用所选决策模型，实验运行使用包内决策模型；统一解析设置不改变它们。实验执行所需的模型配置、技能正文及解析结果随实验导出，并随 Run 内嵌实验保存，公共配置的后续修改不改变这些副本。

解析结果支持 1～64 个问题。编写正文时明确判断标准，解析后按以下语义核对结果：

| 识别类型 / `type` | 从正文提取的结构 | 结果含义 |
| --- | --- | --- |
| 是/否 / `noul` | 是非判断，不需要候选项。 | `noul` 是“是”的概率，范围 0～1；阈值由上层 Skill 的 SOP 决定。 |
| 多分类 / `choice` | 从正文提取 1～255 个候选项及其说明，每次选择其中一项。 | `choice` 是最可能的选项，`probabilities` 保存每个选项的概率。 |
| 评分 / `score` | 从正文提取 1～10 个按分值排序的等级说明。 | 等级从 0 开始；`score` 可为小数，`legend` 对应等级说明，`probabilities` 保存每个等级的概率。 |

`confidence` 表示结果分布的集中程度，不等于某个选项的概率。需要按概率决定后续行为时读取对应的 `probabilities`；评分也不是 0～1 的概率或已执行动作的证明。接口语义见 [Unsloth Laya 文档](https://unsloth.ai/docs/models/decision-laya)。

例如，在决策技能的正文中描述任务分类：

```markdown
# 判断下一项任务

根据调用者提供的当前观察和待办事项，判断任务属于哪一类。
候选类别为“工作”“个人生活”“信息不足”。工作相关事项归为工作，
个人日常事项归为个人生活；无法从输入确定用途时选择信息不足。
只依据输入中的事实分类，将判断结果返回调用者，由调用者决定下一步行动。
```

选择决策类型并完成解析后，核对结果为多分类，包含正文中的三个类别，再保存。是非判断可直接描述一个可以回答是或否的问题；评分任务在正文中按顺序写清各等级的含义。此处示例不包含派生参数，不能代替配置页解析。

生成式 Brain 或子 Skill 可用 `$skill-key` 引用已保存的决策技能，在取得真实感知或记忆后传入情境，读取答案并按自己的 SOP 继续。决策技能只能作为返回判断结果的子技能或独立试运行入口；Brain 和对象根 Skill 使用生成式模型。决策技能不能声明子 Skill、运行时接口或脚本，解析和实验校验会阻断这些组合。

独立试运行决策技能时，直接将输入的自然语言作为 `state` 发送给已选决策模型。正文修改后先完成重新解析和保存，再试运行并检查实际指令、情境及返回答案。切回生成式模型时，编辑器清除决策解析结果；省略 `llm_type` 的文档仍按生成式技能解释。示例不自动安装到公共资源。

## 运行时接口

| 接口 | 用途 |
| --- | --- |
| `@world-perceive` | 只读感知：2D 返回当前位置及视野内的语义、Agent、Event 与对象；1D 返回场所公开发言和当前参与者有权读取的私聊。 |
| `@world-navigate` | 仅用于 2D：只读检查目的地可达性和路径，不产生移动。 |
| `@memory-stream-search` | 搜索当前参与者的有效持久记忆。 |
| `@memory-stream-append` | 写入当前参与者的自然语言记忆。 |
| `@memory-stream-supersede` | 用新记忆替代旧记忆，保留历史。 |
| `@memory-stream-invalidate` | 将记忆标记为失效，保留历史。 |
| `@world-act` | 校验并选择本轮唯一世界动作，由 World Commit 形成事实。 |

接口由 Runtime 在进程内直接调用。模型使用函数调用提交接口名称与参数，不启动独立接口服务器，也不配置 MCP 连接。参数类型和权限由内核约束，技能正文不能扩大视野、伪造身份或绕过动作校验。

`world-act` 只向根 Brain 或对象根 Skill 开放；子技能返回候选行动。每个参与者每 Step 最多成功提交一次动作，成功后结束本轮。需要记录进度时，在动作前记录待确认意图，下一轮根据真实环境状态与事实确认完成；2D 行为还需核对真实坐标。

1D 群聊或论坛沿用同一组感知、记忆和动作接口。Skill 可以感知讨论内容后调用 `@memory-stream-append` 保存观察，再用 `@memory-stream-search` 回忆此前内容；感知本身不写入记忆。保存观察时保留来源，以便以后引用真实发言，不能把自己的理解当成别人的原文。

1D 发言、发帖、回复和私聊使用 `SPEAK`，根据感知结果中的真实会话及消息身份选择目标。论坛回复可以指向主帖或已有评论；引用私聊时必须遵守私聊可见范围。后执行的 Agent 能感知同轮前面已生效的消息，但所有正式事实仍在整 Step 结束时持久化。本轮不发言时使用 `WAIT` 并说明等待原因；不要用动作描述代替真正发言。先记录需要的记忆，再提交本轮动作。

对象绑定 Skill 后仍自动获得对象适用的接口能力；这属于对象运行时注入，与正文明确引用不同。对象只能修改自身状态、回复真实请求，私有记忆和内部状态不自动公开。

## 创建、检查与清理

1. 在技能或大脑列表创建资源，填写显示名称、英文稳定键和用途，再编辑正文。
2. 在文件与调用关系中核对引用；脚本必须作为真实附件保存。
3. 保存并重新打开核对内容。试运行时直接输入自然语言情境；生成式技能直接接收输入原文，决策技能直接使用输入作为情境。纯文本技能可独立运行，依赖仿真接口时选择已有实验及其中的 Agent。身份、场所、时间、感知限制及适用的 2D 位置从实验初始场景取得，使用当前已保存的技能闭包与独立临时记忆。
4. 在实验中导入完整闭包并检查模型；2D 检查出生位置和对象绑定，1D 检查场所成员与群聊/论坛形态，再预检与封存。

试运行保留技能开始、子技能调用、技能返回、接口执行和结束等执行事件，并显示实际模型请求与输入输出；引用原文时，调用明细包含本次 `tool_call_id`、来源 `input_from` 和实际传入文本。执行事件数量不等于模型调用次数：页面另列本次真实逻辑调用和物理尝试数，物理尝试包含重试。普通纯文本叶子技能在无工具、子技能和重试时只需一次模型调用；调用链与后续判断按实际执行计数。

试运行不读取已有 Run 的现场，不启动全部 Agent，也不生成正式世界提交；只读技能返回即可结束。验证动作落地、跨步记忆或对象响应时，仍须运行实验并核对 StepResult。

清空公共资源不会改写实验或 Run 内的独立副本。旧实验、Run 和教材导出保留原始内容与证据；重新编写后的技能需要显式导入新的实验，旧运行结果不能证明新正文的行为。
