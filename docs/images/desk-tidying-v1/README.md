目标：先让读者看懂一个角色如何观察场景、通过自然语言 Brain 决定活动，再经系统提交形成可回放事实。希望整理前后的差别能够被看见，但不能以图片切换假装世界状态变化。

## 当前第一份交付

- [场景与素材拆分方案](场景与素材拆分方案.md)：确定背景、桌面、物品、角色及状态之间的关系，再开始绘图。

## 目录约定

- `map/`：房间底图、尺寸及站位说明。
- `objects/`：透明背景的家具与整理对象素材；状态图保持相同尺寸、锚点及风格。
- `agents/`：角色定义及角色素材。
- `skill-definitions/`：Brain 的自然语言说明；按实际能力决定是否需要被动 Skill。
- `verification/`：管理台构建记录、事实核验、截图及发现的问题。

每个目录的 README 只表示预留用途，不表示素材已经完成。素材方案中的尺寸、对象和时长均为提案，页面搭建前需要完成检查。

## 工作顺序

1. 确认整理目标和可见变化的范围。
2. 画场景构图，检查桌旁站位、尺寸和物品识别度。
3. 按构图制作底图、物品状态图和角色素材。
4. 写空间语义、人物配置、Brain 与验收规则。
5. 通过管理台创建资源和实验；发现能力缺口或 bug，交给用户修复，不改源码绕过。
6. 完成短 Run，核对动作、对象状态和回放是否一致。

不修改溪谷大学实验，不把本案例设为其他实验必须通过的前置流程。
