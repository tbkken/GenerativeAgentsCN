# 地图校准与画布方案

## 先导入完整画面，再定义语义：方向正确

最终 `creek-university-l4-game-object-4480x3200.jpg` 已含草地、房间、道路和家具。可以把它当作一个完整图片素材，不必先拆几百个家具图片。文件名的 L4 只说明这是一张细节最全的图，不要求把整张图片挂在语义树的 L4。

推荐：在素材页导入最终图，建立 140×100 格的整图切片/画布，把显示素材绑定到范围 `(0,0,140,100)` 的 World。Sector、Arena 和各 Game Object 默认“不叠加素材”，只框选各自范围并写语义。这样回放底图在 World 层，模型仍读到真实的四层语义。

如果用户所说“在 Game Object 直接导入画布”是指给单个家具绑定它自己的局部图片，现有节点素材选择支持这种思路；如果指把完整校园挂到一个 Game Object，则不合适：节点素材会改变节点占格，整图会使一个对象覆盖整个校园，也可能超出所属 Arena。

四张 JPG 都不透明，不能当成四张透明增量图一起叠加；后面的图会遮掉前面的图。本稿选最终图作为唯一视觉基准，其他三张留作参考。

## 每个地点需要哪些真实可走位置

保留原稿的对象名称/ID 作为设计目录；逐个重新框定位置。不用统一缩放旧对象坐标来“自动校正”：房间布局不是等比例对应。

| Arena | 优先建立的活动位置 | 需要查询反馈的设施 |
| --- | --- | --- |
| 四栋宿舍 | 每人床边、书桌前、洗手池前、餐桌旁、出入口 | 要纳入巡检的具体配电箱/水池；没有画面或设定依据的不凭空补 |
| 教学楼 | 讲台前、两张课桌座位、入口 | 投影控制台 |
| 研究办公楼 | 教师办公位、两名学生自习位、资料书架前、会议桌周边三个相邻位置 | 公共咖啡机或明确设置的待巡检设备 |
| 中心广场 | 真实长椅附近、喷泉周边可走地板 | 公告栏如需反馈，应明确初始内容 |

| 后勤工作区 | 工作台前、工具柜前、记录位置 | 工单板不能仅凭名称拥有公共队列功能 |

对象语义范围可以含“该家具及其使用位置”，但碰撞只覆盖实体部分。比如课桌及座位范围中的椅前格应可走，使 MOVE 可以到达，再 ACT“阅读课程材料”。不要把整个对象矩形都设碰撞，随后要求模型走进它。

## 不能省掉的通行设计

图片只负责画面；空间语义只说明地点；碰撞/通行数据才决定寻路。三者都要存在。

1. 校准建筑外墙、内墙、门口、树林、水池、桌柜等实体，保留连续门洞。
2. 保留室外步道和跨道路的连续可走斑马线。机动车道边界应按实际图像描画，不能用原大矩形直接封死全部路口。
3. 南北候行点必须在道路外且能查询相应信号。原稿 2.5 格交互距离配一侧信号，不能保证另一侧能查询；要么在两端有一致的真实信号对象，要么明确合理的可见/交互范围。不得站进道路才能看到灯。
4. 同一灯的正反向显示若是多个对象，需要一致的真实状态来源。原被动文本没有这种同步机制，不把多个各自计算的结果当成已实现。
5. 验证每个人的出生点到洗漱、餐桌、门口、斑马线、教学与办公位置、食堂、返家均连通；分别核对路径长度与留出的时间。

当前新版地图编辑器的完整碰撞绘制页面链尚未证实可用，详见源码核对。这个缺口不能通过增写空间语义解决。本次不写一个未验证的全通行地图包，也不修改源码补入口。

## 校准完成的判据

每个节点在正确父节点内，名称唯一依靠稳定 ID 区分；家具/活动区叠加在图片正确位置；每个出生点都可走且地址匹配；所有日程中的地点都真实存在；可交互对象能在安全位置被感知；碰撞和路径连通结果在保存并重开后不变。通过这些检查后再更新原语义表中的坐标，不能同时保留两套互相矛盾的“最终坐标”。
