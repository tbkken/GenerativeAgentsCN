# 斯坦福小镇参考与本次取舍

用户提供目录实际可读取路径为 `D:\code\GenerativeAgentsCN\generative_agents\data\prompts`。本次参考的是这份本地项目的 prompts，不把它未经核实地称为斯坦福上游原版。

## 值得保留的方法

| 参考文件 | 好的方法 | 在本实验中的写法 |
| --- | --- | --- |
| `base_desc.txt` | 先给姓名、年龄、特质、经历、生活习惯、日常计划及当前状态 | 人物输入必须完整；这正说明当前 Runtime 只给名字和 currently 不够 |
| `schedule_init.txt`、`schedule_daily.txt` | 作息和人物身份决定一天大致安排 | 保留人物日常计划；Brain 先找当下活动和有时间的共同约定 |
| `schedule_decompose.txt` | 把大活动细化为眼前可做的小事 | 备课可以核对讲义、准备例题；只细化当前时间段，避免每轮重新生成两天全表 |
| `schedule_revise.txt` | 新事件发生后调整尚未完成的安排 | 交谈或迟到后挪动后续空闲，不改写过去，不强迫计划每项都“按时完成” |
| `determine_sector/arena/object.txt` | 只能从真实候选选择；当前位置合适就留下 | 使用感知、个人已知地址和记忆；不让模型发明地点，也不强制每层多一次 LLM 调用 |
| `decide_chat.txt`、`generate_chat.txt` | 先判断是否值得交谈，结合身份记忆，只说 1–3 句且不重复 | social 子 Skill 按需帮助；Brain 用 SPEAK 只提交本人的一句发言，不补写对方回应 |
| `reflect_chat_memory.txt`、`reflect_chat_planing.txt` | 从对话中记住有用信息及后续安排 | 重点保存真实约定与未解决问题，计划明确作为计划，避免把每句寒暄都存一次 |
| `reflect_focus.txt`、`reflect_insights.txt` | 围绕值得思考的问题，从经历中给出有依据的认识 | 反思按需，最多一两点，引用真实记忆，明确证据不足 |
| `retrieve_currently.txt` | 当前状态随经历更新 | 区分当前状态与稳定人设；不拿 currently 永久保存整个角色设定 |

## 为什么不原封不动迁移

这些 txt 是旧程序传入变量并解析结果的模板。`${base_desc}`、`${hourly_schedule}`、`${areas}`、`${memory}` 并不是新 Brain 写上就能自动获得的变量。直接复制还会残留未替换占位符。当前使用 IterationContext、工具结果和自然语言子调用，需要据此重写。

旧版“请返回 schema”是为了供旧程序消费输出；当前系统已有公共 MCP 和世界提交，不需要再加一层自造的 proposed_action/validation JSON。只在调用工具时遵守其 schema。

参考文本本身也有应修正的地方：

- `schedule_decompose.txt` 末尾固定写“总时长为60分钟”，但实际 start/end 未必一小时；按实际区间和步长细化。
- `schedule_revise.txt` 的例子把原来 08:00–09:00 早餐改成一直到 09:15，覆盖了已经发生的 09:00–09:15；不应重写过去。
- `reflect_insights.txt` 示例从一次做早餐推出“每天都会准备营养早餐”，证据过强；改成有限判断，不能从单次事件推出稳定习惯。
- “至少五种活动”“生成五个洞察”等定额不作为当前实验的硬指标，否则模型可能为了数量编造活动与结论。

## 本次改写后的组合

一个 Brain 负责连贯生活；常态自己理解眼前任务并调用 MCP。交流复杂时才请 social 帮忙，重要事件或一天收尾才请 reflection。日程、地点选择、活动细化、记忆取舍、建议检查的五份辅助文本保留为可选帮助，默认不强制调用。

这保留了小镇 prompts 的专业判断方法，同时让流程仍由自然语言 Brain 决定。不是否定计划或反思，而是避免让每一次睡觉、走路、喝水都经过相同七段调用链。
