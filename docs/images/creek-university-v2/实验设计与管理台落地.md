# 实验设计与管理台落地

## 这次想观察什么

观察四个人是否能在同一所校园里，按照各自身份安排两天生活，并根据真实位置、已知信息和彼此交流调整计划。陈明远负责课程和答疑，林晨负责项目程序，赵悦负责访谈与整理，王建国负责巡检和回应报修。让这些差异自然影响选择，不预写每一步动作或对话台词。

“Run 执行完成”只表示运行走完配置的步数。是否形成有效讨论、是否发现并处理问题、是否遵守交通规则，另按记录评价，不能混成一个完成状态。

## 对四个人物的判断

人物的年龄、经历、个性、作息和分工相互吻合，不需要重做人设。教师与不同专业的两名学生通过社会计算项目合作也合理；明确这是一门跨专业课程即可。

原稿需要改的是共同约定和录入方式：

- 林晨和赵悦第 2 天 10:30 找老师，老师却安排“教研交流”；统一成项目答疑。
- 第 1 天 15:30 两位学生讨论，老师也安排答疑，但没有统一地点；改为先讨论、再答疑，预留移动与交谈时间。
- “图书资料区”不是独立 Arena；这里指研究办公楼里的资料书架及自习位置，不新增一个不存在的建筑。
- “公共餐桌、公共水表、走廊照明”等部分可用空间没有对应地图节点。保留的日程必须指向实际建立的节点；不让模型把名称当成已存在的设施。
- 公共 Agent 页面保存身份、特质、计划和图像；坐标及常用空间在实验内配置，不能把旧文本里的坐标当成公共 Agent 的固有属性。
- 人物目标写“发现问题后说明地点、现象和需要的帮助”等生活语言。动作编码、权限校验、事实记录属于系统或 Brain 使用工具的边界，不写成人的性格或人生目标。

## 两天的共同约定

设计时间：2026-09-07 06:00 至 2026-09-09 06:00，时区 Asia/Shanghai。选择正常工作日只是本实验日期，不是系统默认值。

| 时间 | 共同约定 | 地点与信息 |
| --- | --- | --- |
| 第 1 天 09:00–11:30 | 陈明远授课，两位学生参加跨专业项目课程 | 教学楼；各自使用讲台、课桌对应的可走活动位置 |
| 第 1 天 14:30–15:30 | 林晨和赵悦汇总程序进度、访谈提纲和一个待请教的问题 | 研究办公楼会议桌旁；两人都提前出发 |
| 第 1 天 15:30–16:15 | 陈明远到会议桌旁答疑 | 学生说明真实进度；教师提出下一步建议，不代写成果 |
| 第 1 天 16:30–17:00 | 王建国到研究办公楼巡检 | 师生只有确实观察到异常才报告；没有故障则记录检查结果 |
| 第 2 天 10:30–11:15 | 三人在会议桌旁进行项目答疑 | 追踪前一天建议，不重复虚构第一次见面 |
| 第 2 天 14:00–15:00 | 学生展示阶段成果，陈明远反馈 | 教学楼；分轮发言，不能一次 SPEAK 伪造三人对话 |
| 第 2 天 19:00–20:30 | 各自在住处整理记录和次日安排 | 回顾已发生事实；未完成的明确留下，不强行宣布成功 |

这张表是 Agent 自然语言计划的共同内容，不是系统排程器。每人的个人早餐、休息、研究、巡检仍依照原人设；需要移动时提前安排。早餐优先在各自宿舍餐桌解决，避免早上先去南侧食堂、又返回北侧重复通勤。午晚餐去食堂，夜间回住处。

会面处理：提前约定的地点和时间属于人物已知计划；对方当前是否已经到达只能来自附近感知。到场后最多等待约 20 分钟，每轮判断；对方未到则保存“未遇到”，继续自习或工作，后续见面再说明。不得读取远处人物位置来追踪对方，不提供远程私聊或全校广播的虚构能力。

空间布局必须给共同讨论至少三个相距不超过最小视野的可走站位。长会议桌周边安排相邻站位；讲台离学生座位过远时，老师需走近才能进行一对一答疑。

## 时间与调用量

设计值：步长 5 分钟、总步数 576、随机种子 20260907。第 1 步时间为 09-07 06:00，第 576 步时间为 09-09 05:55；最后一步结束覆盖到 06:00。设置开始时间时保留 `+08:00`，不能把宿主 UTC 数字贴上北京时间标签。

参数片段见 `simulation-settings.json`，已通过当前配置模型校验。检查点间隔12步、保留2份；暂停/结束仍由系统强制提交完整边界。这是设计值，未启动正式实验。

当前移动预算为每分钟 4 格，5 分钟一轮最多消费 20 格路径。100 格实际路径至少需要 5 轮，即 25 分钟，另外还有进出房间、活动和谈话时间。因此不推荐把这套细生活直接压成 96 步×30 分钟：走路、查询和一句话都会各占半小时。5 分钟仍是粗粒度生活模拟，不是精确到秒的交通仿真。

4 人×576 步=2304 次 Brain 迭代。采用新 Brain 的“观察后行动”，通常至少约 2 次 Chat 请求/人/步，即约 4608 次逻辑 Chat 请求；记忆操作后的继续决策、子 Skill、被动对象回应和重试另加。旧稿强制日程、选择、审计三次子调用时，即使不查记忆，也可能约 8 次 Chat 请求/人/步，总量约 18432 次。这里是调用路径估算，不是实测。

模型为单槽本地服务，完整两天可能耗时较长。实际总耗时只能按物理请求次数、实际平均耗时、Embedding、失败重试和固化开销估算；不要以 256K 上下文推断模型吞吐，也不要通过把每步强制拆更多 Skill 来“提升可靠性”。不设置必须先跑 1–3 步的正式运行门槛。

持续上课、自习、睡眠均为普通活动：本轮写具体正在做的事，下一轮仍按当前时刻判断是否继续。睡觉也使用 ACT，不以 WAIT 冒充。当前 Supervisor 对长期同地重复活动是否过度报警列在待解决项，不能通过改写成假移动或无意义换词规避。

## 推荐 Skill 组合

常态由一个 Brain 完成理解日程、观察、回忆和行动。不把“规划、选择、校验”强制分开调用。

- 必需：`context-driven-simulation-brain`。
- Brain 可按需调用：`social-interaction-decision`、`reflection-synthesis`。只在交流难以判断或到收尾时使用；不每步调用。
- 对象观察：`object-state-observer`，只给需要真实反馈的设施绑定。
- 交通扩展预留：`pedestrian-signal-observer`、`request-button-observer`。未落实信号规则前不把它们当成交通控制器。
- 其余五个 atomic 文件已同步改成人话，作为可选帮助；默认 Brain 不引用、不强制导入。不需要额外“验证员模型”代替内核校验。

Skill 正文必须保留实际 MCP 名字。当前运行器按名字是否出现在 Markdown 中决定是否向模型暴露工具，全部改成“看看周围”“做一件事”会导致工具消失。自然语言负责流程，工具参数按运行时给出的 schema 填写；不另造提案 JSON、活动字典或回放合同。

## 地图与真实对象行为

按 [地图校准与画布方案](map/地图校准与画布方案.md) 完成底图、四层节点、可走位置与碰撞。原坐标文件只留作原始资料，不能据此宣称地图正确。

设施的初始状态必须明确。例如普通巡检设备可用 `{"operational":true,"fault":""}`；想研究一次报修可在一个明确设施上设 `{"operational":false,"fault":"投影无法点亮"}`。这只定义开场事实，不承诺一定被发现，也不由观察 Skill 自动维修。

原稿没有故障初态，不能保证会出现报修；没有真正写入和读取的工单流程，也不能把“提交工单”当作后台已经建单。文字整理记录可用 ACT，个人记录用记忆能力，告诉附近后勤人员用 SPEAK。若要公共工单队列，需另设计真实对象状态及校验，不能凭描述暗示已经存在。

动态信号、按钮联动、维修权限仍未落实。不擅自把红灯都改绿、把交通条件移除，或让王建国按固定时间维护全校信号。完整原意实验在这些问题解决前保持待定。

## 管理台录入顺序与确切边界

以下为依据前后端源码确认的操作路线；本次没有实际点击页面。出现“待解决”项时，不把下一步写成已成功。

| 顺序 | 页面及操作 | 要核对的保存结果 |
| --- | --- | --- |
| 1 | Skills 新建并保存需要的原子 Skill | 稳定名称与 frontmatter 一致；正文完整；被动 Skill 是 atomic |
| 2 | 大脑新建 `context-driven-simulation-brain` | 依赖页只有 social、reflection 两项，没有缺失；公共 Brain 保存后再选入实验 |

| 9 | 实验配置设置时间、步长、总步数及模型 | 原地图坐标、人物注入、交通、碰撞、页面缺口解决后才可认定准备就绪 |

## 验收证据

在允许后续运行时，至少查看以下证据；不要求把这些业务指标变成核心 Run 成功判定：

1. 同一 Run 中四人各自的输入确实有各自计划、角色信息和已知地址；不会只看见名字。
2. 每步最多一个有效世界动作，MOVE 的实际终点及路径正确；到达后才进行相应活动。
3. 上课、用餐、自习、休息为 ACT；真实等待有原因和期限；没有大量格式失败后的兜底 WAIT。
4. 项目交流使用附近真实参与者，同一话题复用 conversation_id；未见到人就不编造对方回答。
5. 一个设施查询产生只投给请求者的下一轮观察；观察不直接改状态；有状态变化时能找到提交者和 before/after。
6. 记忆能检索到刚写入的内容；推测不当事实；长期目标未实现时给出证据，不编造总结。
7. 相同事实用于回放和恢复；暂停续跑不重复已提交动作。长时间睡眠的质量告警能区分正常活动与无进展。
8. 最后一步后的完成、固化或报告状态有解释；图中人物位置与其语义地点一致。

完整原意版本的放行前提是阻塞清单被真正关闭。仅保存文件、通过 schema 或看到模型回复，均不能证明这些行为已经实现。

实测补充：Chat三次合成工具调用与一次隔离真实MCP链路通过；Embedding两条文本成功返回1024维向量。当前记忆MCP实际是file_lexical词项检索，不能把独立Embedding成功等同向量记忆召回已接通。见《接口与本地验证记录.md》。
