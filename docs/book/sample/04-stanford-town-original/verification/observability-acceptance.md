# 运行可观测性优化与现有 Run 连续性验收

## 授权与操作边界

用户要求实现当前步执行进度、完整 SKILL 调用树，以及模型返回、接口执行、世界提交三个独立状态；测试后重启系统并通过界面验收。同时明确要求当前 25 人仿真继续执行、保留全部运行数据。

本次只允许重启 Web。主 Agent 不暂停、取消、重跑或重启当前仿真 worker，不修改当前实验、模型参数或历史证据。当前 worker 已加载的 Runtime 不会热更新；现有 Run 通过新的只读投影展示已有证据，新增轻量执行事件仅在以后启动的 worker 中生效。

用户后续明确“现在不用考虑已经 run 的实验，优先考虑需求完成”。因此不等待该 Run 完成 Step 才交付；完整的新执行事件由临时环境回归验证，已有运行页用于实际界面验收。既有数据仍不修改。

## 验收判据

- 当前 Run、Attempt、worker PID 与创建时间在 Web 重启前后不变，模型记录继续推进。
- 页面分别显示已提交步数、本步观察/处理进度、当前人物、SKILL/接口以及实际等待时间；已观察人物数不冒充已完成人物数。
- 调用树保留每次独立调用、父子关系和返回；同名 SKILL 的多次调用不合并，缺少关联证据时明确提示。
- 模型成功仅表示返回；接口成功需要实际工具返回或执行事件；世界提交需要匹配已提交 StepResult。失败、取消、回滚和未知分别保留。
- 当前 Run 缺少的历史证据不补造；新执行事件通过临时测试验证，不声称当前 worker 已加载新埋点。
- 运行页刷新、筛选、树展开及 Run/Attempt 切换保持状态隔离；只读检查既有已提交事实用于核对提交标签。
