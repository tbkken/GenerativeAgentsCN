# 25 人物资源及实验位置的界面导入

本说明只描述资料准备和系统已有界面入口。导入结果、资源 ID 与实验状态由主 Agent 在浏览器验收后另行记录。脚本不连接数据库、HTTP 或 Runtime，不修改实验目录。

1. 在公共资源中心导入 `stanford-town-original-agents-config.zip`，选中全部 25 个 Agent 并确认。该包是 `ga-package` v2 `config`，携带 50 张原样 PNG；普通可编辑人物使用中文显示名和英文稳定键。
2. 通过界面建立包含这 25 人的人群，并在实验创建中选择该人群。地图应为本案例原样经典地图，空间根名为 `the Ville`。
3. 在实验草稿的 Agent 页点击“导入”，上传 `experiment-placement-merge.json`。核对预览为 25 人，冲突策略保持 **“更新同名 Agent，保留未提供字段”**，然后确认导入。实际匹配依据是 `agent_key`。本文件只有 `agent_key`、`coord`、`spatial`；**不可选完整替换**，否则会删除未提供的人物字段和图片引用。
4. 保存完成后重新打开人物，核对坐标、完整初始地址、已知空间和头像／行走图，再执行实验预检。所有原始 25 人在自己的床上；应保留四层地址。

人物公共资源不携带坐标或空间。位置合并文件把原坐标、经典常用地址／已知空间与明确的 `initial_location` 一起写入实验装配。离线校验已确认 25 个人物位置在本案例地图上均不碰撞，地址一致，所有已知空间通过 Protocol 校验。现有前端的合并逻辑会保留未提供的 `scratch`、`currently`、头像、行走图和感知配置；还需由浏览器复查实际保存结果。

空间树选择器会重新选取该地址内靠近中心的可走格。它不会保留任意已有坐标。25 人中有 5 人的原坐标与该中心候选不同，导入后核对即可，避免再次确认空间树而改写原坐标：

| 人物 | 原坐标 | 空间树自动候选 |
| --- | --- | --- |
| 约翰 | [91, 74] | [90, 74] |
| 汤姆 | [73, 74] | [72, 74] |
| 詹妮弗 | [37, 65] | [36, 65] |
| 拉吉夫 | [26, 18] | [25, 18] |
| 卡洛斯 | [94, 18] | [93, 18] |

完整比较见 `spawn-picker-comparison.json`。这是对当前已支持入口的操作说明，不代表做过浏览器验收，也不需要改动系统。

参数映射：原项目的方框视野、半径 8、注意力带宽 8 原值保留；原图每帧 32×32、四行三列，映射为当前协议 `sprite_layout: 4x3`。不填写移动速度、显示缩放或旧引擎专属排程／反思参数，未填写项沿用当前产品合同，不能声称等同原版速度和完整执行算法。
