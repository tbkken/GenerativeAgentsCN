# 案例 1：醒来后的晨间工作启动

这是一个用于独立复现的 32 步晨间案例。陈明远从卧室睡醒开始，起身穿衣并整理床铺，去书房查看昨天的资料、整理资料并写下当天优先级；随后带着明确的工作安排去厨房准备和烹调早餐，转到餐区吃饭并收拾餐桌，最后回到书房打开资料开始第一项工作。32 步是实验的观察窗口，不是 Brain 的业务排程；Brain 按观察结果和自己的累计进度便签选择单一动作。案例讲解四层空间、感知、导航、最小私人进度便签、`MOVE`、`ACT`、`SET_OBJECT_STATE`、虚拟时间和 StepResult。一次完整 32 步行为与最终质量报告已验证，结果集中记录在 [最终验证记录](settings/verification-record.md)。

视觉方面，当前地图采用 32×24、32px 的逻辑网格，World 绑定 `map/assets/home-background.png` 住宅底图，工作书桌绑定整理前/`tidy` 两态。已确认完整背景、人物图、3 格显示、桌面状态切换和用餐后回书房工作的生活闭环；最后三步持续研究，未重新起床。跨 Attempt 汇总修复后，UI 与新导出一致保留 5 项质量记录：1 项首次空记忆、4 次本轮修正后的能力拒绝。最终模型调用为 108 次逻辑/108 次物理、0 次物理重试；页面总耗时 37 分 52 秒含约 4 分钟暂停修复等待。

浏览器导出的普通结果 ZIP 与独立质量报告已原样保存在 [导出归档](verification/exports/README.md)，SHA256 核对一致。ZIP 用于审计及查看嵌入素材，不是正式 `.gaexp` / `.garun`，也不是一键恢复包。顶部状态来源、历史导出标注与 Action 摘要时区三项问题已在后续 [P01–P03 回归](verification/p01-p03-regression.md) 中修复并验证，原 32 步事实与历史日志保留。估时偏低、日志级别、SOP 途经点等 P04–P09 仍待决定；出版近景图片和正式包协议复现尚需专项验收。历史人物比例、导航与进度问题见 [验证说明](verification/README.md)。未使用的 `map/assets/Room_Builder_32x32.png` 和 `verification/legacy-assets/map/` 素材只供历史问题溯源，不参与当前地图运行。

## 约 20 个生活活动（教学参照）

醒来并起身、穿衣、整理床铺、查看昨天笔记、区分已完成与待跟进资料、归类整理、将书桌状态设为 `tidy`、写下优先事项、选好今日材料、取出食材、清洗准备、烹煮早餐、检查火候、装盘、摆好早餐、用餐喝水、收拢餐具、打开研究资料、回看优先事项、开始第一项研究工作。卧室、书房、厨房、餐区之间的移动另用真实 `MOVE` 完成。

这些活动是观察窗口内的自然节奏，不是 Brain 中写死的排程，也不是 Runtime 的业务成功条件。移动可能因为路径或移动预算跨越多个 Step；动作失败时应按工具结果重新观察。
