# 案例 1 验证

本页记录当前验证口径；`preconditions.json` 是旧版检查文件，其中仍有三 MCP、禁止记忆和旧运行窗口等过期内容，不得用作当前验收或直接导入资产。学员按 `../settings/browser-authoring-checklist.md` 和 `../map/README.md` 的中文浏览器清单操作。

验证重点不是模型是否逐字复现约 20 个生活活动，也不是是否用完 32 个观察 Step，而是：路径是否可达、动作是否符合当前位置、每个 Agent 每 Step 是否最多一次 `world-act`，以及 StepResult 是否同时保存 Event(SPO) 和非空 `structured_payload`。业务上的“早餐吃完”和“开始工作”应作为事实或可选评估指标读取，不作为 Runtime 硬性完成判定。

当前地图使用一张完整住宅背景和工作书桌两态切片。背景显示、11 个空间节点、编辑器桌面两态切换及四段可达路线已通过浏览器检查；此外已完成一次 32 步真实晨间行为验证。地图检查与运行行为分别留有证据。

## 历史 Run 的正确诊断

Run `3ad4ff95-bccc-4dc9-b99d-c6e7a99807c6` 使用 3 格人物显示大小，已安全暂停在 26/32 步。运行状态是 PAUSED，案例行为验收未通过；角色曾重复穿衣、重启晨间活动并停留在卧室。

质量面板出现 6 项 `MCP_TOOL_ERROR`：Step 6 的 ACT 携带 `[11,5]`；Step 12/26 的 MOVE 将 `[12,6]` 与家中通道地址搭配；Step 18/20 将 `[12,6]` 与书房地址搭配；Step 21 将 `[11,6]` 与床边地址搭配。后五项包含目标坐标与地址不一致。Step 6 的真实当前坐标已经是 `[11,5]`，不能再误写为出生点 `[9,5]`，也不能据此断言它未先 MOVE。

后续诊断把问题分成四项：

- `world-perceive.events` 在坐标提交与地址更新之间产生了混合观察，出现旧地址跟随新坐标的现象。工程师已修复并完成新增与既有合计 51 项检查；重启后当前 Run 的 Step 4–6 已在浏览器核对从床旁到通道、书房的真实坐标与活动，不再出现旧床边事件跟随新坐标。当前 Run 的完整晨间动线也已验证。
- 工作书桌 Game Object 的范围全部被家具碰撞覆盖，以该对象的完整地址为导航目标不可达；应查询并前往桌旁可走站位 `[23,7]`。
- `world-navigate` 的 `next_coord` 只表示路径第一格。应查询最终可走 `target_coord`，MOVE 时仍提交同一个最终 `target_coord`，省略 `target_address`，让内核按移动预算推进并规范化地址。当前配置为 3 分钟×4 格/分钟，即最多 12 格/步，不是一格/步。
- 缺少持久的跨步生活进度，或只依赖被移动覆盖的活动文本，会导致角色重新起床、穿衣。修订 Brain 使用自己的“晨间进度便签”保存累计确认事项，并在下一轮核对待确认动作。
