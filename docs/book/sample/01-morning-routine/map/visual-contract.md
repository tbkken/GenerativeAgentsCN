# 案例 1 视觉契约：在家开启一天的工作

这份契约约束卧室、书房、厨房、餐区、通道与角色的同屏效果。地图有完整四层地址、模型能提交动作，并不等于画面可用；出版验收还必须看到实际回放中的角色、家具和移动路径。

## 统一尺度

- 全场景采用同一套俯视、轻度侧面可见的像素表现；地板、墙面、家具与角色使用同一相机方向。避免把写实房间图与低分辨率像素角色拼接。
- 一个逻辑 Tile 对应 32×32 源像素。本案例当前地图为 32×24 Tile；World 使用 4:3 的住宅底图源图 `assets/home-background.png`（1448×1086），浏览器负责将其完整显示到地图画布。必须检查缩放和裁切，不能只凭源图比例判定通过。
- 角色图集约定为 3 列×4 行、每帧 32×32；帧宽高和行列顺序必须与浏览器导入时的 `4x3` 布局一致。头像和行走图已上传并复制进当前实验；3 格显示设置与完整跨房间动线已确认，各处近景的比例细节、脚底锚点、遮挡和放大清晰度仍待出版专项验收。
- 素材的可见边界与占地格数分别记录。透明留白不代表物体变大；不得用“源图分辨率高”代替实际同屏尺寸检查，也不得把一张完整房间图声明成 1×1 家具切片后再任意放大。
- 渲染缩放保持整数像素边界，像素素材使用最近邻采样；如果应用当前渲染器不支持，必须在验收结果中记录实际显示情况，不能只凭素材文件判定通过。

## 角色、家具与通行空间

角色源纹理每帧为 32×32 像素，回放显示大小在本地图中设为 3 格；不能把源纹理的一格大小当成实际显示尺寸。定位点在脚底，显示缩放与碰撞判定分别检查。背景布局为卧室左上、书房右上、厨房左下、餐区右下和中间纵向通道；当前已通过浏览器确认的节点、阻挡与站位集中在 [地图配置步骤](README.md)，下表仅列同屏检查重点：

| 元素 | 当前浏览器配置中的范围 | 必须检查的同屏关系 |
| --- | --- | --- |
| 单人床 | 阻挡 `x=4..7,y=2..7`；床边站位 `[9,5]` | 角色脚底位于床边可走格，不进入床体阻挡 |
| 书桌 | 语义与阻挡 `x=24..29,y=5..7`；桌旁站位 `[23,7]` | 角色站位在桌外，整理前后材料可辨识 |
| 厨房操作台 | 厨房台阻挡 `x=1..11,y=12..14`；操作站位 `[10,15]` | 取物、备餐站位在台前可走格 |
| 早餐桌 | 餐桌椅阻挡 `x=23..27,y=14..18`；用餐站位 `[22,17]` | 吃饭站位与桌椅阻挡分离 |
| 房门与主要通道 | 通道语义 `x=13..18,y=1..21`；两侧墙在 `y=6..7` 和 `y=16..17` 留门洞 | 连续通行，核对放大人物的脚底、遮挡与转弯表现 |

这些范围是本案例的作者配置，不是 Runtime 中新增的家具或活动类型字典；阻挡范围也不等于素材可见像素的完整边界。

## 语义、图层与碰撞

1. 按 World → Sector → Arena → Game Object 绘制；World 底图必须处于最底层。
2. 卧室、书房、厨房、餐区的语义范围包含各自可站立和操作的区域。Game Object 的语义范围可以包含桌前或床边空地，碰撞只覆盖实际不可通过的实体。
3. Agent 的初始坐标、每个目标站位和门口都要落在可走 Tile 上，并与该 Tile 的完整四层地址一致。
4. 图像锚点、Tile 坐标和碰撞边界需要同时校准。调整素材大小后，要重新检查人物脚底、家具底边和通行空间，不能只改图片宽高。
5. 本案例的整理资料、煮早餐、吃饭等 `ACT` 产生语义事实，不自动移动物品或切换家具图片。没有合法对象状态事实时，回放不得从动作文本推断桌面变整齐、食物出现或餐具消失。

## 视觉交付条件

素材、地图定义与运行记录需要共同满足以下检查，才能将 `verification/visual-qa.md` 改为通过：

- 进度便签版 Run 已确认完整住宅、人物图、3 格显示设置及卧室→书房→厨房→餐区→书房的生活动线；第 9 步的 `SET_OBJECT_STATE` payload 与桌面从散纸切到整齐本册的画面已核对，返程桌面仍为 `tidy`。32 步行为已完成，质量报告和导出状态见 `../settings/verification-record.md`；出版图片仍需补齐各处近景、缩放值与遮挡检查。
- 检查初始床边站位、书桌前站位、厨房台前站位和早餐桌旁站位；四处的人物相对大小一致。
- 回放至少一次卧室→书房→厨房→餐区→书房的实际移动，门口和转弯没有穿墙或明显重叠。
- 检查默认缩放与放大显示，文字、角色轮廓和家具边缘可辨识；保存画布尺寸与缩放值，使书稿截图可复现。
- 素材文件路径均为本案例本地路径，实验包带有自己的物理副本，不从其他案例目录或公共作者资源运行期读取。

本案例的 World 底图使用 `assets/home-background.png`。`desk-scattered-source.png` 与 `desk-tidy-source.png` 已在浏览器中从同一矩形 `x=34,y=7,w=8,h=4` 建立切片；工作书桌 Game Object 为 `x=24,y=5,w=6,h=3`，默认整理前，顶层 `state=tidy` 已在编辑器中目视切换并恢复为整理前；运行第 9 步也已确认合法状态事实驱动相同切换。旧的 `Room_Builder_32x32.png` 仅供问题溯源，不参与当前底图显示。
