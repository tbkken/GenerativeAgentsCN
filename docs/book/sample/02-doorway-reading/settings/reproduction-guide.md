# 案例 2：学员浏览器复现指南

本指南串起已实际完成的正常流程配置，不要求阅读历史候选。目标是让林晨在门廊整理书包，观察目的地，分多轮穿门走到阅读桌旁，再取书、浏览、阅读和摘记。参考 Run 已完成 8/8 步；边界对照和整套案例结论另见 [验收资料](../verification/README.md)，不把参考 Run 的文字、耗时或随机 ID 当作每次复现必须相同的输出。

## 2. 创建完整背景地图

在地图中心创建“林晨的门廊与阅读室”，使用 **24×16 逻辑网格、32px tile**。上传本例完整背景，以素材源网格 **48×32** 创建全图切片“门廊与阅读室完整背景”，绑定 World，覆盖整个 24×16 地图并保存。

48×32 是源素材切片网格，24×16 才是仿真逻辑网格。原图完整缩放为 768×512 逻辑像素，每一逻辑格对应原图 64×64 像素；不要把背景拆成大量家具图片。

按 [节点原文](../map/semantic-nodes.md) 粘贴语义，按下表建立父子层级。坐标以 x、y、宽、高填写。

| 层级与名称 | 父节点 | x | y | 宽 | 高 |
| --- | --- | --- | --- | --- | --- |
| World：林晨的门廊与阅读室 | 无 | 0 | 0 | 24 | 16 |
| Sector：馆内阅读空间 | World | 1 | 1 | 22 | 14 |
| Arena：门廊 | 馆内阅读空间 | 1 | 1 | 10 | 14 |
| Arena：阅读角 | 馆内阅读空间 | 11 | 1 | 12 | 14 |
| Game Object：置物边柜 | 门廊 | 3 | 2 | 3 | 3 |
| Game Object：阅读桌 | 阅读角 | 16 | 5 | 6 | 4 |

只有 World 绑定图片，其余节点无额外素材；本例不绑定 Game Object 被动 Skill，也不设置对象状态换图。

## 3. 保存碰撞并检查通路

在地图编辑器依照 [当前碰撞表](../map/spatial-collision-candidates.md) 绘制并保存碰撞。重点核对中墙 x9–10 的 y0–7、y9–15 阻挡，**仅 y8 两格留作门洞**。阅读桌 GO 范围为 x16–21/y5–8，但实体桌椅只阻挡 x17–21/y5–8，保留 x16 桌旁可走列；不要把整个对象都涂成碰撞。

运行地图校验，再用两点路径检查 **(7,7) → (16,7)**。参考页面返回终点可走、路线可达 **11 格**，经过唯一 y8 门洞。检查背景、门洞、语义与碰撞是否对应；静态路径通过后还要在正式 Run 中核对真实 MOVE。

正式 Brain 导航使用对象地址，系统可能选中对象内其他可走终点。参考 Run 实际选择 (16,8)，路线 10 格；这与静态查询终点不同，不是路径长度矛盾。不要为了凑 11 格把 `next_coord` 当成最终目标。

## 4. 创建独立林晨与单人人群

保存显示 **2.5 格**、`vision_radius=10`、`attention_bandwidth=6`。新建单人人群“案例2：林晨穿过门口去阅读”，只加入本次创建的林晨。公共 Agent 不保存地图出生点，出生点在实验导入后配置。

## 8. 预检、执行与核对真实事实

保存后运行预检。参考实验为 **0 阻断、0 警告、0 自动检查、1 通过**，随后确认正式执行 8 步，实验封存并创建新 Run。记录自己这次的 Experiment、Run、Attempt ID，不复用参考身份。

在运行与回放中核对以下顺序，按事实判断，不要求模型逐字重演描述：

1. 林晨在 (7,7)/门廊整理书包。首次空记忆检索可以产生 `EMPTY_MEMORY_RETRIEVAL`，随后应写入便签，并在后续检索读回。
2. 感知实际返回阅读桌的稳定 key 和完整四层地址；角色初始知识没有提前预置该对象。查询路线不能被记为已经到达。
3. MOVE 真正穿过 x9–10/y8 门洞，逐轮消耗不超过 4 格。参考 Run 三次消费 **4+4+2**，落点依次 (10,8)、(14,8)、(16,8)。进入阅读角 Arena 后若仍未到桌旁，应继续 MOVE。
4. 到达阅读桌有效站位后，才依次提交取书、浏览章节、阅读一小节与摘记 ACT。核对事件、非空 payload、坐标与语义地址；活动文字不能代替真实移动，也不能编造没有材料支持的书页内容。
5. 检查背景、人物大小、脚底、门洞和桌旁位置。本例没有独立坐姿/阅读动画，普通 ACT 使用现有角色姿态和活动文字。
