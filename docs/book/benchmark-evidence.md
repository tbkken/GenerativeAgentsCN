# 第一章研究底稿：大模型能力与评价证据

本文件服务于第一章的概念解释、指标教学和数据卡写作，**不是当前模型的完整排行榜，也不是本书重新运行评测所得的实验报告**。
资料核验日期为 **2026-09-25**；模型行日期、论文日期、网页读取日期分别记录，不把其中一个替代另一个。
来源以基准维护方、作者仓库和原论文为主。网页搜索工具本次连接失败，以下内容通过直接 HTTPS 获取正文核验；未执行模型评测。
本轮没有保存完整网页归档、运行轨迹或数据集快照，因此这些链接支持资料追溯，尚不构成可离线复算的出版证据包。

## 1. 先说清楚测什么，再展示分数

每项能力按“读者任务 → 测试样本 → 评分指标 → 为什么合理 → 局限 → 带条件的数据”介绍。
能力是希望了解的属性，基准是抽样形成的任务集合，指标是把任务结果转换成数值的规则；三者不能混为一谈。
例如，“能修改程序”是能力，“修复一组真实仓库问题”是任务集合，“通过规定测试的问题比例”是指标。
同一个指标名称不保证同一口径：测试集、模型快照、提示、工具、预算、评分规则改变后，分数可能不再可比。
学术答题、真实任务、可靠性和效率应分别讲解。一个综合名次不能代替读者对具体用途的判断。
本章可借鉴 [HELM 原论文](https://arxiv.org/abs/2211.09110) 的多指标思路，同时讨论准确性、校准、稳健性与效率等维度。

## 2. 能力、指标与适用边界

| 能力 | 典型任务与候选指标 | 为什么这样测 | 不能据此推断 |
| --- | --- | --- | --- |
| 语言、知识与指令遵循 | MMLU-Pro 准确率；IFEval 约束通过率；开放写作量表与盲评 | 分别检验知识应用、遵守明确要求、开放表达质量 | 选择题高分不能证明写作好；格式符合不代表内容正确 |
| 数学与科学推理 | 固定题集正确率；GPQA 的明确分集；单次与多次尝试分开 | 可验证的最终答案便于检验复杂约束下的解题结果 | 解题不等于开展科研；输出很长不证明推理正确 |
| 代码与软件工程 | 程序测试通过率；SWE-bench 问题解决率 | 执行测试验证修改是否实现目标 | 通过有限测试不保证无缺陷；框架贡献不能都算给模型 |
| 工具与 Agent | 工具/参数正确率；最终任务成功率；重复成功率 | 从接口使用到目标状态逐层验证 | 成功调用接口不等于完成任务；一次成功不保证稳定成功 |
| 长上下文与检索 | LongBench v2 准确率；检索 Recall@k；证据支持率 | 分别检验找到资料、理解资料、据资料回答 | 上下文容量不等于有效理解；找回一句话不等于跨文档推理 |
| 多模态 | MMMU-Pro 准确率；语音 WER/CER；视频任务正确率；生成盲评 | 图像、语音、视频和生成任务需要各自的观察方式 | 识图结果不能代表语音或图像生成水平 |
| 可信性与稳健性 | 无依据陈述率、校准误差、扰动前后表现、拒答分类 | 同时检验对错、自知程度和条件改变后的可靠性 | 拒绝越多未必越安全；自信措辞不等于概率校准 |
| 效率与可用性 | 端到端延迟、P50/P95、吞吐、每次成功任务成本 | 对应用户的等待时间、服务容量和实际支出 | 只比较 token/s 或单次价格不能判断任务整体性价比 |

### 2.1 语言、知识与指令遵循

[MMLU-Pro](https://github.com/TIGER-AI-Lab/MMLU-Pro) 覆盖约 1.2 万道题、14 个领域，增加推理题并将候选答案扩展到最多 10 个。
有明确答案便于重复评分；候选增多可以降低随机猜中的机会，但必须查看每题实际选项数，不能把所有题的随机基线一律写成 10%。
[IFEval](https://arxiv.org/abs/2311.07911) 使用能够验证的指令要求。讲解时区分“满足某一条要求”和“同时满足一道题的全部要求”。
摘要、改写和创作再用明确量表评价忠实性、完整性、表达与受众适配；不能只凭参考文本重合率判断事实正确。
中文写作、中文专业知识和本土表达需补独立样本；英文考试成绩不能自动迁移成中文能力结论。

### 2.2 数学与科学推理

[GPQA](https://arxiv.org/html/2311.12022v1) 由领域专家设计问题，覆盖生物、物理和化学；它同时涉及知识储备与知识运用，并非纯粹逻辑测试。
应先给一个自编的简短题目，说明如何核对最终答案，再讲准确率；不要把受版权保护的整套基准题直接搬进教材。
Main、Diamond、Extended 是不同题集；数学考试的不同年份也可能难度不同，图表必须保留分集和年份。
讨论多次采样时同时报告次数、总预算和答案选择方法，不把可反复尝试的成绩当作一次作答能力。
专业测试中的人类成绩也受样本筛选、可用工具、答题时间与学科背景影响，不能直接概括“超过所有专家”。

### 2.3 代码与软件工程

[SWE-bench Verified](https://www.swebench.com/verified.html) 是经人工核验的 500 个仓库问题，核验涉及问题描述、测试和可解性。
测试执行提供比“代码看起来正确”更直接的证据，但测试遗漏的行为、可维护性和安全属性仍需另行评价。
完整系统榜单衡量模型与代理框架的组合；相同模型换工具、上下文处理、重试策略后，结果可能不同。
官方 Bash Only 设置通过统一 mini-SWE-agent 帮助比较模型，但仍须记录具体框架版本与模型推理设置。
官方说明 1.x 与 2.x 不一定可比：2.x 使用工具调用执行动作；1.x 解析输出字符串，温度设置规则也不同。

### 2.4 工具与 Agent

“工具名和参数合法”“接口执行成功”“最终目标完成”是三个不同层次，分别记录才能定位失败。
[τ-bench 原论文](https://arxiv.org/abs/2406.12045) 比较对话结束后的环境状态与目标状态，并以重复成功的指标讨论可靠性。
这适合解释：代理说“已改签”不能证明改签成功，必须核对系统中实际状态以及该任务要求遵循的规则。
[现行官方仓库](https://github.com/sierra-research/tau2-bench) 已发展为 τ³-bench；旧 τ-bench 仓库明确提示任务已过时。
2026 年 7 月 v1.0.1 修正影响 banking_knowledge 领域的评分；引用成绩必须固定版本、领域、任务分集、用户模拟器和试验预算。

### 2.5 长上下文与检索

[LongBench v2](https://longbench2.github.io/) 包含单文档、多文档、长示例学习、长对话历史、代码仓库和结构化数据等六类任务。
它有 503 道选择题，文本约 8 千至 200 万词；这里的单位是词，不能直接改写成相同数量的 token。
“能输入多少”与“输入后答得怎样”分开写；简单检索、综合推理、冲突证据处理也分别评价。
检索 Recall@k 只评价所需证据是否出现在前 k 个结果中，回答仍可能误解或曲解证据。
该榜单不同长度分组的任务分布不同，因此某个长文本分组分数更高不能证明文本越长模型越擅长。

### 2.6 多模态

[MMMU-Pro 原论文](https://arxiv.org/abs/2409.02813) 过滤仅凭文字即可作答的问题，增加候选答案，并提供题目置于图像内的设置。
这样可以减少“声称测视觉，实际上只利用文字线索”的情况；图像分辨率、裁切和 OCR 处理仍需记录。
语音转录可讲词错误率 WER、字错误率 CER；口音、噪声、断句和中文分词约定影响结果。
视频任务需记录抽帧和时长，图像/音频生成需评价指令符合度、内容质量与人工偏好，不能套用同一张准确率表。
本轮未核验足以代表当前图像、语音、视频和生成能力的成套成绩，正式正文中应明确待补。

### 2.7 可信性、稳健性与效率

事实核验先定义最小陈述单位和证据标准；无依据陈述与已证实错误分开，不能把“查不到”一律标成错误。
校准讨论概率判断与实际正确频率是否接近；从模型口头自信程度、token 概率推断答案正确概率，需要额外验证。
拒答分成合理拒答、错误拒答以及应该拒答却回答；只给一个拒答比例不能说明整体质量。
扰动测试应保持任务含义，观察改写、顺序、噪声是否造成不必要的性能下降。
效率测量固定输入规模、输出长度、并发、缓存和质量要求；工具等待、失败调用和重试都进入任务总成本。

## 3. 给初学者的指标计算例子

以下数字均为**教学假设**，不是任何模型的实测结果。

### 3.1 正确率与分母

`正确率 = 正确任务数 / 评价任务总数`。100 道题答对 80 道就是 80%。
如果另外 10 道题因超时没有结果，必须说明它们算失败、单列还是按预先规则排除；不能事后悄悄改分母。
同样是 80%，题目数量、任务难度和抽样范围不同，证据力度也不同。

### 3.2 pass@k 与 pass^k

`pass@k` 问“同一道任务给 k 次机会，至少一次成功吗”；它衡量多次尝试中找到成功答案的能力。
`pass^k` 问“同一道任务重复 k 次，是否每次都成功”；它关注重复执行的可靠性，τ 系列用此思路评价代理。
为直观看区别，假设某一任务每次成功概率都是 p，且各次独立：`pass@k = 1 - (1 - p)^k`，`pass^k = p^k`。
当 p = 0.8、k = 2，至少一次成功的概率是 96%，两次都成功的概率是 64%；它们不是相互矛盾的成绩。
这两个公式只用于上述独立同分布假设。真实任务难度不一、重试会改提示、运行会共享状态时，不能把总体平均正确率直接代入。
真实评测须按其规定的逐任务多次试验和统计估计方式计算，还要说明是否有人或程序负责识别并选择成功答案。
不能把 `pass@10` 与另一模型的 `pass@1` 并列后直接宣称前者更强；机会和成本都已改变。

### 3.3 证据、概率与成本

`Recall@k = 前 k 个检索结果中找到的相关证据数 / 全部应找证据数`；所需两条证据只找到一条，召回率为 50%。
这不评价回答是否引用正确；还需检查每条可核验陈述有没有得到对应证据支持。
二元结果的 Brier 示例为 `(预测概率 - 实际结果)^2`，实际正确记 1、错误记 0，多次预测取平均，数值越小越好。
预测 90% 会正确且确实正确，单项得分为 0.01；若实际错误则为 0.81，说明过度自信的错误会受到更大惩罚。
`每次成功任务成本 = 全部任务尝试总成本 / 成功任务数`；花费 10 元处理 10 项任务、成功 8 项，就是 1.25 元/成功任务。
延迟 P50 是中位数，P95 是 95% 的观测不超过的值；后者帮助读者看到较慢任务的等待体验。

这些例子用于解释评测和展示有日期的能力切片。它们没有覆盖所有能力，不组成“截至核验日的完整发展水平”。

- 数据条件：Verified 500 个问题，mini-SWE-agent 2.0.0，`reasoning_effort = high`，标签为 `System: Attempts - 1`。
- 日期：榜单该行 `date = 2026-02-17`；资料读取日期为 2026-09-25，不能把读取日期写成运行日期。
- 身份：行标识为 `20260217_mini-v2.0.0_claude-4-5-opus-high`，模型标签为 `claude-4-5-opus`。
- 来源类别：基准维护方官方榜单；非厂商宣传稿，但本书没有独立复测，该行的独立复核状态未核验。
- 已知设置边界：2.x 的官方说明为不设置温度参数，不应把它误写成 temperature = 0。

## 5. 从研究底稿到正式正文还需补什么

本轮核验的主要来源为 HELM、MMLU-Pro、IFEval 作者资料、GPQA、SWE-bench、τ 系列、LongBench v2 和 MMMU-Pro。
大纲中的 BFCL、GAIA、WebArena、RULER、DocVQA、ChartQA 等为扩展候选，本轮未逐项核验其现行版本、评价口径或近期成绩；定稿前另行核查，不据名称补写实时分数。

| 能力或证据 | 本轮状态 | 正文写作前的补充要求 |
| --- | --- | --- |
| 中文语言、知识、指令遵循 | 已说明评价思路，未提供当前可比成绩 | 确定中文任务集、模型快照、提示与人工评分协议 |
