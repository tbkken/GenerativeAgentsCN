## 第一章　认识大模型，读懂能力与评价

### 1.1 从一个回答出发：什么是大模型

以“为开放日写一份活动安排”为开场，展示流畅但可能有错的回答，引出生成能力与事实正确性的区别。

- 人工智能、机器学习、深度学习、基础模型、大语言模型和多模态模型的关系；参数规模只是“大”的一个维度。
- Token、分词、嵌入、上下文窗口、注意力与 Transformer 的直观解释。用中文短句说明 Token 不等于字数，窗口容量不等于有效记忆。
- 预训练学习语言和知识模式；后训练改善指令遵循、偏好与推理表现；推理时根据输入生成输出。解释训练与使用的成本、数据流和产物。
- 模型参数知识、当前上下文、外部资料和持久记忆分别保存什么；为什么“昨天聊过”未必代表今天能访问。
- 概率生成、采样、推理预算与不确定性；连贯解释不一定真实反映内部计算。

1.1已按八图重排：错误方案、术语关系、Token与窗口、逐步生成、关联与顺序、训练与推理、四种知识来源、输出变化与正确性。长篇叙述压缩为图旁短解释、对照表与要点，不要求初学者先推导网络数学。

### 1.2 从模型到应用：能力来自哪些层

区分基础模型、推理配置、系统提示、检索、工具、Agent 执行器和产品界面。一个带搜索与代码执行的应用答对问题，不能全部归因于模型的闭卷知识。

讲清闭源服务与开放权重、本地部署与云 API、模型与产品、模型名称与固定快照的区别。选型同时考虑质量、输入形式、工具兼容性、上下文、延迟、费用和数据边界。

### 1.3 怎样把“聪明”变成可测量的问题

先讲评价链：**使用目标 → 任务样本 → 可观察输出 → 判分规则 → 汇总指标 → 适用范围**，再介绍基准名称。

- 准确率：正确样本数 / 有效样本数。讲随机猜测基线、题目难度和样本构成。
- Precision、Recall、F1：用报名信息抽取说明误报和漏报；解释宏平均与微平均。
- pass@1、pass@k：一次成功与多次候选至少成功一次衡量不同使用条件；τ 系列的 pass^k 则衡量重复均成功，不可混用。
- 任务成功率：按预先定义的最终状态与约束判断，工具参数格式正确只是中间条件。
- 人类偏好、成对胜率和排名：适合开放生成体验，但受裁判、长度、风格和参评群体影响。
- 检索 Recall@k、排序指标、引用支持率与回答正确率：分别判断“找没找到”和“有没有用对”。
- 效率：首 Token 延迟、端到端 P50/P95、吞吐、Token 用量、单次成功任务成本；失败与重试也计入成本。

用十道小题手工算分；再展示同一准确率在不同样本量下的不确定性。解释置信区间、重复试验、测试集泄漏、污染、基准饱和及分布变化。

### 1.4 当前大模型有哪些能力：逐项读懂指标

正文每行都采用“真实需求 → 基准题型 → 指标 → 合理性 → 局限 → 本书应用”的格式，不能只列缩写。

| 能力 | 可采用的业界评价 | 为什么能够衡量该能力 | 不能据此推出什么 |
| --- | --- | --- | --- |
| 语言知识与理解 | MMLU / MMLU-Pro 多领域选择题准确率 | 固定题目和答案便于比较，多领域采样增加覆盖面 | 不证明实时知识、中文场景全面适用或绝无幻觉 |
| 指令遵循 | IFEval 可程序检验约束通过率 | 字数、格式等约束可重复检查，减少主观判分 | 满足形式不代表事实正确，也不能覆盖所有语义要求 |
| 数学、科学与复杂推理 | 固定年份 AIME、GPQA Diamond；高难推理可补充 FrontierMath | 精确答案或专家审核的难题检验问题求解 | 竞赛题表现不能换算成科研能力；有工具和无工具分开 |
| 代码生成与工程修改 | HumanEval / MBPP 测试通过率；SWE-bench Verified 问题解决率 | 执行测试接近功能正确，仓库任务包含定位和修改 | 测试不完备，代理框架、工具与预算会改变成绩 |
| 工具使用与长任务 | BFCL 调用正确性；τ 系列、GAIA、WebArena 任务成功率 | 检查工具选择、参数、交互和最终状态，接近工作链 | 单工具成功不代表长链可靠；环境和用户模拟器影响结果 |
| 长上下文与检索 | LongBench / RULER；按长度分组的检索与多跳任务 | 控制长度、信息位置和干扰，测能否取用信息 | 大窗口不代表所有位置同样可靠；单条“大海捞针”不够 |
| 图像、文档与图表理解 | MMMU / MMMU-Pro、DocVQA、ChartQA | 跨学科图像、文档问答和图表读数检验不同视觉任务 | 看懂图不等于空间仿真正确；OCR、分辨率和裁剪影响结果 |
| 语音、视频与生成 | ASR 的 WER / CER、视频问答、语音和图像生成的任务量表与盲评 | 分别测转录、时序理解、听感和生成质量 | 单个分数不能概括噪声、方言、打断和多模态全部能力 |
| 事实性与可信性 | 事实问答、引用支持、校准、错误拒答与扰动测试 | 分开答对、答错、不作答及条件变化后的可靠性 | 一个分数不能证明所有领域可靠；自信语气不是校准 |
| 开放生成与使用体验 | 人类成对比较、明确维度量表；自动裁判需校准 | 开放写作没有唯一答案，多维评分更接近使用目标 | 偏好胜率不能替代事实、执行正确性或独立安全检查 |

已核验基准的固定版本、原始出处及数值见[资料与证据规范](references-and-evidence.md)。表中的其他扩展基准是正文选题候选，定稿前还需逐项核验。语音、图像生成等用于解释模型生态，不意味着本仿真系统已有这些入口。

### 1.5 怎样说明“当前发展到什么水平”

正文保留带日期的能力快照，至少记录：模型完整标识、日期、基准版本与子集、分数及单位、工具、推理/采样预算、代理框架、来源和查阅日期。

同协议数据用于说明进步；不同条件的数据分组说明，不画成同一条进步曲线。优先使用独立、可复现评测，厂商自报明确标注；未知字段写“未披露”。本次已核验的 SWE-bench 和 LongBench v2 数值可用于讲解评价口径，详见资料表；它们只是部分能力的有日期实例，不能代替全领域的当前排名。

至少展示一个高分仍会失败的样本和一个工具改善结果的任务。章末按能力总结：哪些条件下已经有用，什么仍不稳定，为什么需要工具与应用层校验。定稿时更新快照。

### 1.6 为后续实践选择模型

读者用自己的 20–30 个入门任务建立小评测集，覆盖中文理解、结构化输出、工具参数、跨轮一致性与成本。此规模用于学习和初筛，不足以宣称统计上优于另一模型。

作业：为“活动筹备助手”和“仿真角色”分别写一页选型说明，说明能力需求、实测条件、预算和待检查问题，两者不必使用同一模型。

## 第二章　从对话到智能体：技术、OpenAI API 与 WorkBuddy

### 本章组织方式

贯穿任务是“准备社区学习中心开放日”：阅读规则与场地资料、抽取约束、查询可用空间、形成有依据的方案、检查冲突并生成交付文件。使用教学虚构数据。

每项技术提供概念、最小示例、API 实现、WorkBuddy 操作、结果核验和失败练习。两条路线并行，不假设产品界面暴露 API 全部参数。这里的 WorkBuddy 指腾讯 WorkBuddy，具体入口与版本见[资料与证据规范](references-and-evidence.md)。

### 2.1 环境与第一次调用

解释 HTTP、JSON、SDK、API Key、环境变量、模型标识、请求与响应。提供 Python 环境准备、安装依赖、读取 OPENAI_API_KEY、发送 client.responses.create(...)、提取文本与用量的完整示例；显式记录 SDK 版本与可用模型，密钥不入源码。

WorkBuddy：安装登录、选择工作目录、新建任务、选择模型并提出同一个问题；展示输入材料与结果文件。区分产品账号、模型提供商和 API 计费。

验收是能解释输入、输出、实际费用来源与连接失败原因。错误练习包括凭据缺失、模型不可用、限流和网络失败。

### 2.2 Prompt：把愿望写成可执行任务

讲目标、背景、输入、约束、输出、示例和验收；区分指令与待处理资料。用三版活动方案提示做同题对照：模糊要求、补足约束、增加少量示例，使用统一评分表。

API 解释 instructions 与输入消息的职责，保存提示与测试集；WorkBuddy 演示任务描述、材料和多轮纠正。提示优劣由结果判断，不靠修饰语，也不要求读取模型隐藏思维链。

### 2.3 上下文工程与跨轮状态

区分对话历史、文件上下文、工作区规则、工具结果、摘要和持久记忆。讲预算、截断、压缩损失、信息过期、来源和冲突。

API 采用明确的多轮状态管理方式，说明每轮实际送入什么；WorkBuddy 通过 @ 引用资料、附加文件和规则练习。不能凭模型说“记得”判断材料已读取。

### 2.4 结构化输出与校验

把通知抽取为主题、地点、时间、人数和缺失项。讲 JSON Schema、必填字段、枚举、空值、拒答与截断，区分可解析、符合 Schema 和事实正确。

API 使用 Structured Outputs；WorkBuddy 输出结构化文件并调用独立校验工具。这种提示约束不自动等于 API 的严格 Schema 模式。用时间冲突和错误人数说明还需业务校验。

### 2.5 Function Calling：请求工具执行

用只读 get_room_availability 展示完整循环：定义工具 → 发给模型 → 读取 function_call → 应用校验与执行 → 按 call_id 返回 function_call_output → 整理答案。

讲清模型提出调用、应用负责执行；处理未知工具、错误参数、多次调用、异常、停止条件和循环预算。保留继续调用所需的响应项，不只拼接可见文字。[OpenAI Function calling](https://developers.openai.com/api/docs/guides/function-calling)

WorkBuddy 观察实际工具执行与返回；未有任意 Python 函数注册界面时，通过 MCP 或受控命令承载，不虚构“Function Call 开关”。

### 2.6 MCP：按协议连接外部能力

讲 Host、Client、Server，tools、resources、prompts 的用途及宿主支持差异。Function Calling 是模型请求工具的接口机制，MCP 是宿主连接外部能力的协议。

把上一节工具包装为教学服务，讲发现、参数、调用、错误、认证、工具范围与授权。本地 stdio 和远程 HTTP 分开，本机地址不能直接视为云 API 可访问服务。

API 讲 Responses 的 mcp 工具、server_url、工具过滤与批准请求；本地连接采用官方支持方式并列环境前提。WorkBuddy 走“插件 → MCP 服务器 → 配置 MCP”，核对连接、工具列表与实际结果。[OpenAI MCP 指南](https://developers.openai.com/api/docs/guides/tools-remote-mcp)

### 2.7 CLI 与 Shell：把可重复操作变成工具

CLI 是程序的命令行接口，Shell 负责解析和调度命令。讲参数、工作目录、标准输入/输出、退出码、超时和路径。用 validate_schedule 检查方案冲突。

先手工运行，再通过工具执行。API 可用受控函数包装命令，或用官方 Shell 工具的本地/托管模式，说明文件可见性与执行责任。[OpenAI Shell 指南](https://developers.openai.com/api/docs/guides/tools-shell)

WorkBuddy 检查实际终端调用与退出码；它能执行本地命令不代表存在已核验的独立 WorkBuddy CLI。参数校验、目录限制与日志由执行层负责。

### 2.8 Skill：组织可复用的做事方法

讲适用条件、输入、步骤、停止、验收、引用资料、脚本和模板；以“检查并整理开放日方案”编写完整 SKILL.md。说明逐步加载资料、自然语言 SOP、脚本和工具权限的边界。

API 按当前官方支持说明上传与使用：托管 Shell 可挂载已上传 Skill，本地 Shell 使用本地文件，附件形式不同。手动加载 SOP 的简例明确标为应用层实现。[OpenAI Skills 指南](https://developers.openai.com/api/docs/guides/tools-skills)

WorkBuddy 展示查找、安装或上传、自建、启用、触发与验收。解释通用 Agent Skills、WorkBuddy Skill 和本系统 atomic/pack/brain、skill_key 的差异，不承诺直接互导。

### 2.9 Embedding、检索与 RAG

从资料太多出发，解释切分、向量、相似度、关键词检索、召回、重排、引用和基于资料回答。RAG 不会更新模型权重。

API 比较小型自建检索链与可用托管检索方式；保存命中文段再评价回答。WorkBuddy 用可读取资料与实际检索能力完成任务，未知底层实现不写成向量库。分别测 Recall@k、引用支持和最终回答。

### 2.10 Agent 循环、规划与记忆

从简单工具循环扩展为读取约束、决定下一步、执行、核对、继续或停止。ReAct、计划、反思是可选策略；讲循环上限、无进展检测、预算、恢复和接管。

任务状态、持久记忆和外部事实分别保存，确认真实结果后才标记完成。对比直接求解与按需调用检查 Skill，测收益和额外成本。

WorkBuddy 对比 Ask、Plan、Agent：从输入框“+ → 模式”切换，展示咨询、计划审阅与执行。产品模式不等于内部推理过程。

### 2.11 多模态与计算机交互

分别演示读场地图、读表格截图、听口述要求和保存文件。区分 OCR、图片理解、图像生成、语音识别/生成及其评价。

API 按选定模型和接口处理；WorkBuddy 仅写当前版本、模型和插件实际支持的能力。网页预览与 Agent 操作网页分别讲；使用浏览器 Skill 时记录来源与前提。素材生成不能代替第三章地图语义、碰撞和 UI 上传绑定。

### 2.12 多 Agent 协作与工作流

把活动筹备拆为资料整理、冲突检查和报告编写，主任务整合；讲分工、交接合同、重复工作、上下文隔离和预算。

对比单 Agent 和多 Agent。WorkBuddy 可用专家/专家团展示组织方式；区分固定程序流程、按需委派与仿真独立角色，不把多个工具称为多个自主角色，也不把本系统 Brain 固定成流程图。

### 2.13 可观测性、评估、可靠性与成本

用 Schema、确定性断言、工具最终状态、人工量表和经校准的模型裁判评价；包含缺资料、拒绝、过期信息和提示注入样本。

分别记录逻辑任务、模型逻辑调用、物理重试、工具调用、Token、端到端时间和费用。缓存、压缩、并行、模型分工都做质量—成本对照；按错误类型有界重试，可取消，不无限增加修复上下文。

以Langfuse演示Trace、Observation、Session和Score：用OpenAI SDK包装器记录模型调用，手动记录本地阶段，把业务校验与本次产物关联。默认离线fixture，真实请求与遥测导出显式开启；记录实际SDK版本与接收项目。

讲API日志、调用链、聚合指标和评价各能证明什么；用三幅Mermaid与静态参考说明层级、导出路径及WorkBuddy范围。WorkBuddy仅运行已埋点脚本时，不声称看到了宿主内部全部请求或积分。到第三章仍以Run文件和StepResult作为仿真事实来源。

### 2.14 技术选择与完整交付

总结选择原则：提示说明任务；结构化输出规定数据接口；Function Calling/CLI/MCP 接入执行；Skill 组织方法；RAG 提供知识；Agent 推进动态过程。微调、蒸馏和部署优化作延伸，讲适用条件，不作为入门前置。

交付 API 版可运行项目，以及 WorkBuddy 的任务说明、配置与执行记录。均含资料、完整提示/Skill、前提、版本、输出、评分和失败说明。未实测入口明确标注。

## 第三章　从零搭建一次社区学习中心开放日

### 3.1 贯穿案例与边界

组织者准备活动，两名来访者带不同需求抵达，志愿者协助交流；智能公告栏接收并发布场地信息，服务台处理咨询。安排发生一次有依据的调整，角色通过感知与沟通修正认识。

初步规模为 4 名 Agent、一个学习中心、若干相邻 Arena、2 个绑定根 Skill 的对象和普通物品。观察窗口由路径、调用链和模型吞吐校准，不写死某一步必须发生什么。

这是待制作的新教学设计，不替换既有晨间/阅读地图。先验画面空间，再组织行为。可分阶段建立独立实验，最终形成完整案例；SEALED 后调整须复制成新独立实验，不建立版本继承链。

### 3.2 认识界面与作者资源

按任务认识资源中心、实验中心和运行结果页；准备 Map、Spatial Asset、Agent、Crowd、模型预设、Brain、Skill 和 Evaluator。讲稳定 ID、直接编辑、归档/恢复与删除，不引入业务 Revision 或默认地图/Agent。

实验中心讲每页 5 条、负责人/标签、分页与归档恢复；不增加已明确移除的搜索组合筛选、比较或批量管理。Crowd 是作者侧选择集，进入实验后展开为独立 Agent，并验证重复成员去重与冲突诊断。

从目标推导场地、角色、对象与公开/私有信息。模型讲聊天、Embedding、参数与环境变量；配置存在和 Runtime 实际消费分别验证。

### 3.3 从图像到四层空间

上传完整背景，定义 World → Sector → Arena → Game Object，叠加语义、渲染、碰撞；解释 Tile 的职责。对象默认状态、状态图、尺寸、切片边界一致。

联合检查网格、尺度、人物脚底、遮挡、门洞、站位和路线。头像与行走图通过 UI 上传；出生位置属于实验装配，空地用三层地址，对象内保留四层地址。

晨间案例用于空间与连续生活练习，穿门阅读用于门洞与移动预算练习；不把历史 Run 拼成新案例证据。

### 3.4 Brain、子 Skill 与对象 Skill

给出完整 Brain SOP：读取上下文，感知、查询记忆，必要时导航/调用子 Skill，选择一个动作，保存待确认进度，下一轮以事实确认。

讲 atomic/pack/brain 是固有类型，对象根/子 Skill 是使用角色。子 Skill 为“比较可行方案”“整理已确认事项”，按需调用，不强制每轮反思。

对象根 Skill 为公告和咨询；对象有独立身份与私有记忆，每 Step 在 Agent 动作后自主执行。可感知、行动、响应真实请求，无需主动/被动开关。绑定对象仅修改自身状态，Agent 用 INTERACT 请求，不能直接改内部状态。

依赖按包内 skill_key 解析，同 key 同内容合并、异内容阻断，缺失与非法环在封存前发现。可选作者试运行没有仿真世界，需仿真 MCP 的 Skill 必须进入实验。

核对 Brain 的循环安全上限和无进展诊断；子 Skill 输出可以成为后续输入，但中间文本不直接驱动画面。成功提交动作后结束本轮，必要进度便签在动作前保存，下一轮再确认。

### 3.5 感知、导航、动作与时间

用真实调用解释只读 world-perceive、world-navigate 与唯一动作入口 world-act。核对 vision_radius 硬上限、attention_bandwidth、CURRENT 层级锚点、附近人物/事件/对象和已知空间。

完整讲六类动作：MOVE、ACT、WAIT、SPEAK、INTERACT、SET_OBJECT_STATE。普通活动不造编码字典，WAIT 有真实原因与边界，职业文字不授予权限。

检查目标、可走终点、已走和剩余路径；next_coord 不是整次目标；实际抵达后才 ACT。每个参与者每 Step 至多成功提交一次动作。

讲 IterationContext 的 Run、Attempt、Agent、Step、总步数、时区、虚拟时间、步长、位置、四层语义和公共变量。Scheduler 推进时间；虚拟时间、模型耗时、含暂停的墙钟时间分别阅读。

### 3.6 跨轮记忆与进度

演示 append、search、supersede、invalidate，核对记忆 ID、访问历史、有效态和来源；旧记录保留但默认不当有效事实。

存储检索成立与行为依赖记忆分别验证。按当前实现说明检索，不因提供 Embedding 预设就称为向量检索。已探索空间归参与者记忆，不每轮向全体发送全图。

### 3.7 多人交流与对象反馈

角色在可感知范围内发现对方，双方真实 SPEAK 复用 conversation_id。私人信息不从他人记忆检索泄漏。

讲完整链：参与者请求 → 公告栏按 SOP 与状态处理 → 对象 world-act 提交状态/回复 → StepResult → 下一轮仅目标 Agent 收到一次反馈 → 更新记忆与计划。

对象只感知范围内已执行运动事实；公开外观 state 与私有字段分开。核对 request_id、待处理请求、失败计数、恢复后重复响应。不给最后一步安排必须下一轮消费的首次请求作为唯一验收点。

### 3.8 草稿、副本、预检与封存

演示选入资源即复制完整闭包，草稿编辑包内内容，公共资源修改不自动同步；重新导入显式操作，替换地图重确认坐标与位置。

预检层级、地址、附件、对象交互、出生点和依赖，统计与明细一致。实验只有 DRAFT → SEALED；封存后调整创建新独立副本。

在练习副本演示归档、恢复、删除和独立性；操作反馈与所选实验/Run 状态分别阅读。

### 3.9 启动、观察与估算

启动时完整嵌入实验。认识 CREATED/QUEUED/RUNNING/FINALIZING/PAUSED/CANCELLED/COMPLETED/FAILED；最后一步之后还要完成报告和固化。

看执行中的模型调用、Trace、资源槽位与质量。按 Agent/对象数量、调用链、上下文和重试估算；暂停与调试时间另列。有原因和截止的等待不自动判卡死。

### 3.10 暂停、取消、续跑与重跑

分别操作并核对身份：新跑新 run_id；续跑同 run_id、新 attempt_id、从完整检查点的下一步继续；重跑用 Run 内嵌实验创建新 run_id。

检查动作、记忆、会话、对象状态与回复无重复。区分控制请求、模型等待中断与一致提交边界，不笼统写“取消只能等整步结束”。

### 3.11 回放事实与失败诊断

沿 MOVE 和对象更新追踪 MCP → World Commit → StepResult → Event(SPO)/structured_payload → 回放。移动活动文字与实际位移分别检查；Replay 只读已提交事实，不再调用模型。

独立对照讲门洞阻挡、残缺地址、超范围感知、第二次动作和空记忆。区分预期拒绝、行为质量、执行故障与页面问题；实际 bug 按仓库规则停验收、留证据、等针对该问题的授权。

### 3.12 业务指标、质量与 Evaluator

预先定义到达率、信息更新延迟、交流闭环、过时信息行动、回复遗漏/重复、每个成功结果的成本。分母、单位、窗口及未完成样本处理明确。

确定性诊断、Brain 合规与业务 Evaluator 分开。资源入包不代表执行链消费；NOT_EVALUATED/SKIPPED 如实解释，人工/外部评分不能冒充内置结果。

### 3.13 导出、迁移与离线回放

讲 ga-package v2：基础资源 config/.zip、实验 exp/.gaexp、运行 run/.garun；resources/index.json 统一内容，runtime/assembly.json 保存装配。清单 UUID 才是身份。

UI 导出基础资源、实验与 Run，分别验证普通结果 ZIP、正式包和独立环境复现。记录状态、提交边界、时间、大小和 SHA256，密钥仅在目标环境注入。

演示地图、Agent、Crowd、Skill、Brain 和模型的独立交换，以及从 config、exp、run 中选择所需基础资源。资源自身附件完整；config 可保留显式未绑定依赖，进入实验前必须绑定；同 key 异内容阻断整次导入。

CLI 延伸讲校验、新跑、暂停/续跑、重跑、封存与 Replay。系统 UI 验收仍走浏览器，不能用 CLI 替代缺失页面。无 Studio 验证数据库独立性，核对帧连续性和完整性；事实回放确定性不保证重新推理相同。

### 3.14 理解架构与整理交付

完成操作后再解释 Protocol、Studio、Runtime、Replay 与适配层，沿文件交换链回看职责。Brain 决定意图、顺序、条件与停止，内核负责身份、校验、提交、恢复和监督。

交付素材、完整 Skill、参数理由、实验/Run 包、截图、关键事实、质量报告、对照与复现说明。“已验收”必须定位版本、Experiment、Run、Attempt、Step 和原始证据。
