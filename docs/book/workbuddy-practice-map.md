# 第二章 WorkBuddy 实操对照：社区学习中心开放日筹备

> 本文是待实测的教学操作方案。官方资料核查日期：2026-09-25；产品文档基线参考 [WorkBuddy 5.6.2 更新日志（2026-09-21）](https://www.workbuddy.cn/docs/workbuddy/Changelog-5.6.2)。已读取官方文档，尚未确认读者客户端版本、账号权限和全部界面入口，未进行 UI 配置或验收。

与[全书大纲](book-capabilities-and-case-roadmap.md)第二章配套。这里的 WorkBuddy 指腾讯 WorkBuddy；它是承载模型、工具和任务的产品，不是 OpenAI API 的另一种界面。部分开发配置兼容 CodeBuddy，不表示二者所有功能相同。

## 一、统一练习材料与验收对象

使用虚构的“青禾社区学习中心开放日”，日期为 `2026-10-17`，时区为 `Asia/Shanghai`。材料、教学工具与正文现已整理到[第二章](<chapter 02/README.md>)及其[示例目录](<chapter 02/examples/README.md>)；以下保留操作设计与验收要求。它们不是已导入的系统资源，WorkBuddy 客户端操作仍待实测。

| 配套材料 | 内容与教学作用 |
| --- | --- |
| `brief.md` | 活动目标、受众、交付要求；所有人员与数据均为教学虚构 |
| `rooms.csv` | 阅读室容量 30 人、手作室容量 12 人、交流室容量 20 人，使用稳定 `room_id` |
| `rules.md` | 开放时间 09:00–12:00，人数不得超过容量，同一房间活动不得重叠 |
| `availability.json` | 已有预约：手作室 10:00–10:30 不可用；查询工具以此为事实依据 |
| `requests.csv` | 阅读分享 24 人、手作体验 10 人、交流活动 16 人；明确各自时长和可用时间段 |
| `reference-layout.png` | 示意图用于视觉理解练习；不作为房间容量、预约状态或可达性的唯一依据 |
| `expected-checks.md` | 人数、开放时间、预约冲突、缺失字段、引用支持等人工可核验规则 |

教学工作目录可命名为 `open-day`，只放本次材料副本。计划产物为 `constraints.json`、`schedule.json`、`validation-report.json` 和 `plan.md`。路径是教材拟定命名，不是 WorkBuddy 内置文件协议。

所有时间保存日期和时区偏移，例如 `2026-10-17T10:00:00+08:00`；冲突检查约定区间为 `[开始, 结束)`，首尾相接不算重叠。材料缺失时应返回待确认项，不能自行补出预约事实。

第二章的结果是活动筹备文件。第三章仍须按本系统 UI 完成资源上传、绑定、实验预检、封存和运行；本章结果不能充当 Run、StepResult 或 Replay 证据。

## 二、Prompt：写清任务与验收

- **目的：**比较模糊要求与明确任务合同对结果的影响。
- **操作路径：**新建任务 → 选择工作空间 → 输入目标、输入材料、输出格式和约束；操作入口见[创建任务](https://www.workbuddy.cn/docs/workbuddy/Create-Task)。
- **练习：**先用“帮我安排开放日”，再在独立对照任务中使用下方完整提示。两轮使用相同模型、材料和评分表。
- **观察：**产物是否包含全部活动、人数是否有来源、缺资料是否明示、是否满足规则；保留失败结果。
- **API 对照：**程序组织指令与输入材料，并保存每次提示和返回结果；不要用语气强弱代替质量测量。
- **边界：**提示词是行为要求，不替代权限控制和确定性校验；不要求公开隐藏推理链。

```text
请为青禾社区学习中心的开放日整理筹备方案。
依据工作空间中的 brief.md、rooms.csv、rules.md、requests.csv；预约情况须通过查询工具核对。
先列出已知约束和缺失资料，再生成 schedule.json 与 plan.md，说明每项安排的依据。
活动不得超过房间容量或开放时间，不得与已有预约或本方案其他活动冲突。
不得编造房间、预约或参与者资料。只生成本地文件；最终附独立校验结果和未解决事项。
```

## 三、上下文：文件、图片与规则分别提供什么

- **目的：**让读者看到模型使用的资料范围，以及资料缺失如何影响答案。
- **操作路径：**输入框 `@` 引用文件、文档或规则；也可上传、拖拽文件，或粘贴截图。见[创建任务](https://www.workbuddy.cn/docs/workbuddy/Create-Task)与[任务对话](https://www.workbuddy.cn/docs/workbuddy/Conversation)。
- **练习：**第一次只给需求，第二次加入房间表和规则，第三次加入示意图；要求标出每条约束的文件来源。
- **观察：**核对实际引用内容与输出；区分从图片观察到的布局、从表格读取的容量和工具返回的预约状态。
- **API 对照：**记录实际发送的文本、图片与历史消息；大材料需要切分、检索或压缩，而不是无限追加。
- **边界：**附件存在不证明内容已正确使用；`@` 不等于永久记忆；未核实底层检索实现时，不把文件读取写成向量检索。

## 四、Ask、Plan 与 Agent：咨询、审阅与执行

- **目的：**根据任务阶段选择交互方式，理解规划与执行的区别。
- **操作路径：**输入框 `+ → 模式` 开启“仅问答 Ask”或“计划 Plan”；关闭后回到默认 Agent。见[新建任务栏](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Task-Bar)。
- **练习：**Ask 讨论需要哪些资料；Plan 生成筹备步骤和交付清单；审阅后选择开始执行，生成产物。
- **观察：**确认 Plan 阶段实际展示的方案、确认执行的交互，以及执行后新增的文件；修改一次计划再执行。
- **API 对照：**应用自行管理“提出计划、等待用户、执行工具”的状态与入口；一个提示中的“先计划”不自动创建批准机制。
- **边界：**模式不是模型内部推理过程；官方地址 `/docs/workbuddy/Plan` 实为套餐管理，不能作为 Plan 模式教程来源。

## 五、模型与配置：选择能力，记录条件

- **目的：**理解产品账号、模型服务、推理配置和计费来源。
- **操作路径：**对话模型选择器选择可用模型；头像 → 设置 → 模型管理自定义模型。见[模型配置](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Model)。
- **练习：**记录客户端显示的模型标识、模式、思考强度和上下文配置；用同一组任务比较两种可用配置，计入失败及重试。
- **观察：**文本、图片和工具调用分别是否受支持；记录端到端耗时和实际可见用量，无法获得的数据写“未提供”。
- **API 对照：**程序选择模型并管理参数、请求记录和用量；自定义服务通常由读者向对应服务商付费。
- **边界：**官方文档的标准自定义路径为 `/chat/completions`；自定义 URL 不能证明兼容 Responses API 的全部对象、托管工具或实时接口。模型列表和上下文上限应随截图标日期，不写成永久常量。

## 六、结构化输出：可解析之后还要检查事实

- **目的：**分开 JSON 语法、Schema 合规、业务正确与来源可靠四层检查。
- **操作路径：**让 Agent 生成 `schedule.json`，在右侧工作空间文件中查看；让受控校验程序读取文件并写报告。见[结果查看](https://www.workbuddy.cn/docs/workbuddy/Results)。
- **练习：**定义活动 ID、房间 ID、开始/结束时间、人数、来源和待确认项；加入“手作室 10:00 开始”及“手作室 13 人”两个故意失败的输入。
- **观察：**报告分别指出预约冲突和容量超限；修正后重新校验，保留前后两次报告，不能仅凭 Agent 自述“已检查”。
- **API 对照：**API 路线使用支持的严格结构化输出方式，再运行同一套业务校验；模型拒答或输出截断也要处理。
- **边界：**WorkBuddy 中要求输出 JSON，不等于已开启 API 的严格 Schema 模式；校验脚本尚待编写和单独测试。

## 七、Function Calling 与 MCP：查询真实可用空间

- **目的：**把“模型提出工具请求”和“执行器执行工具”分开，并展示标准化接入。
- **操作路径：**先准备只读 `get_room_availability` 教学服务；WorkBuddy 中进入插件 → MCP 服务器 → 配置 MCP。用户级配置位于 `~/.workbuddy/mcp.json`，项目级位于 `<项目>/.workbuddy/mcp.json`。见[MCP 文档](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/MCP-Guide)。
- **练习：**接入后确认连接状态和实际可用工具；查询手作室，再据返回值调整安排；故意查询不存在的房间并观察错误。
- **观察：**核对请求中的房间与日期、服务返回的预约、方案的变化。客户端未展示的原始字段由教学服务日志取证，并标明来源。
- **API 对照：**Function Calling 由程序校验参数、执行查询并回传结果；MCP 则连接服务、发现工具并按宿主支持方式调用。
- **边界：**绿色连接状态不证明业务正确；本地 stdio 依赖本地可用运行环境，云 API 不能自动访问读者的 localhost。未证实存在任意函数注册界面时，不虚构“Function Call 开关”。

## 八、CLI 与 Shell：调用确定性的检查程序

- **目的：**说明 CLI 是程序接口，Shell 是解释和启动命令的执行环境。
- **操作路径：**在教学工作空间准备校验脚本；先由读者手工执行，再要求 Agent 调用同一程序。终端操作受权限模式约束，见[默认权限与安全沙箱](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Permission-Modes)。
- **练习：**后续为教材实现 `validate_schedule.py`，接收方案、规则和预约文件路径，输出报告与明确退出码；脚本当前尚未交付，不把示例名写成已安装命令。
- **观察：**核对工作目录、参数、标准输出、标准错误、退出码和报告文件；分别演示输入不存在与业务不通过。
- **API 对照：**用受控工具包装命令执行，设置参数校验、工作目录、超时和输出限制。
- **边界：**WorkBuddy 能运行本地命令，不证明存在独立 `workbuddy` CLI；斜杠命令也不等于 Shell 命令。未显示的退出码应从执行包装器报告取得。

## 九、Skill：把成熟方法组织成可复用流程

- **目的：**将约束抽取、预约查询、冲突检查和结果整理组织成可复用的方法。
- **操作路径：**技能 → 添加技能 → 上传技能、查找技能或创建技能；已安装列表控制启用状态。见[技能文档](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Skills-Market)。
- **练习：**创建“开放日筹备检查”Skill，明确输入、适用条件、步骤、失败处理、停止条件和交付物，引用校验脚本及模板；换一组人数和预约再执行。
- **观察：**检查实际生成的 `SKILL.md`、附件和调用行为；关闭 Skill 后做一次对照，区分流程复用与记住上一轮答案。
- **API 对照：**由应用或接口支持的运行环境加载 Skill 内容并提供工具；仅把一段 SOP 放进提示的简例，应标为应用层实现。
- **边界：**Skill 不自行授予工具权限；跨产品的目录、依赖和调用约定须分别验证，不能承诺直接导入本系统成为 atomic/pack/brain 或自动获得 `skill_key`。

## 十、记忆：保留偏好，不替代活动事实

- **目的：**区分当前上下文、个人偏好、活动状态与外部事实。
- **操作路径：**头像 → 设置中的记忆入口查看、编辑、删除或关闭记忆；当前文档也以“记忆与进化”指代入口，录制时按客户端核对。见[记忆](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Memory)与[系统设置](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Setting)。
- **练习：**只保存“报告偏好简短中文并附来源”等无敏感信息的偏好；把本次活动日期、预约与校验结果保存在任务文件中。
- **观察：**新任务是否能参考偏好，删除后是否停止使用；记录实际提取时间，不能预设立即自动记住。
- **API 对照：**程序选择持久化内容、更新时间、检索与注入范围；保存历史消息不自动构成可靠记忆系统。
- **边界：**WorkBuddy 的个人记忆不是本系统参与者隔离记忆；旧预约和过期信息须重新核实，不能因记忆存在就视为当前事实。

## 十一、浏览器与多模态：预览和操作分别验收

- **目的：**让读者区分图片理解、网页预览、网页信息读取与浏览器操作。
- **操作路径：**右侧边栏浏览器用于打开预览与多标签查看；需要点击、滚动或截图时，可采用官方介绍的 `agent-browser` Skill。见[右侧边栏](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Right-Sidebar)和[Agent Browser](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/WorkBuddy-Zero-Cost-Skill-Top-10/Agent-Browser)。
- **练习：**为虚构活动生成本地介绍页，预览桌面与手机视口；再按明确目标打开折叠规则、读取其内容并截图。
- **观察：**检查实际页面、点击前后状态与截图；把读取到的规则与原始材料核对。
- **API 对照：**图片输入、浏览器工具、截图和执行回路各有接口与环境前提，不能视为单个模型名称保证的完整能力。
- **边界：**能预览网页不证明 Agent 能操作网页；是否预装 Skill、运行依赖、登录态和授权均待实测。本练习不触发真实报名、发布或发送。

## 十二、专家团：比较分工收益与协作成本

- **目的：**区分角色提示、多任务并行、多代理协作和仿真参与者。
- **操作路径：**侧边栏专家 → 专家中心 → 选择专家或专家团并召唤；文档说明专家团由团长分工并汇总。见[专家](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Expert-Center)。
- **练习：**按客户端实际支持的配置，尝试资料整理、冲突核对、报告编写三类分工；不预设任意自建专家团入口已存在。
- **观察：**与单 Agent 使用同一输入、工具和评分表，比较错误、重复工作、上下文遗漏、耗时及可见成本，检查最终结论有无遗漏反对证据。
- **API 对照：**应用明确任务交接数据、可用工具、上下文隔离、停止条件与汇总规则；并行本身不保证更好。
- **边界：**产品专家不是具有法定资质的人；多个对话窗口不自动形成协作；本系统角色由自己的状态、感知、记忆和提交合同定义。

## 十三、权限、调试与交付：以可检查结果收尾

- **目的：**理解提示要求与执行权限的不同职责，形成可复核的失败与交付记录。
- **操作路径：**输入框底部查看默认权限；安全中心检查文件、命令、网络策略及审计；右侧查看产物和变更。见[权限模式](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Permission-Modes)、[结果查看](https://www.workbuddy.cn/docs/workbuddy/Results)和[帮助与反馈](https://www.workbuddy.cn/docs/workbuddy/From-Beginner-to-Expert-Guide/Function-Description/Feedback)。
- **练习：**保持默认权限，在副本目录执行；复现缺资料、不可用工具、格式错误和预约冲突，分别判断是输入、配置、模型选择还是执行问题。
- **观察：**记录实际批准动作、文件差异、工具结果、校验报告和耗时；停止任务后检查已写入文件，再决定继续或重试。
- **API 对照：**应用管理认证、权限、重试、取消、预算与日志；错误类型不同，处理方式不同，不能无限重跑直到成功。
- **边界：**完全访问影响当前客户端全部已有与新建任务，不是只影响当前练习；审计日志、过程说明与原始模型请求不同，未暴露的 Token、参数或调用次数不猜测。

交付包应包括输入材料、实际提示、Skill 与脚本、模型和客户端版本、操作记录、输出文件、校验规则、成功及失败报告。截图说明取材时间和任务；只记录观察到的事实，不把“文档支持”写成“本机已经通过”。
