## 二、页面骨架

### 2.1 叙事主线

一句话主线：**材料被下载，不等于有人能接手；把"谁要做什么、拿到哪份文件、验到哪一层"逐条写清，交付才算成立。**

四段递进：

1. **先说清接收者要完成什么**（5.7.1）——"请帮我看看"不是交付目标，五类检查回答五个不同问题，不能相互替代
2. **一张清单与四类文件**（5.7.2 + 5.7.3）——用清单把需求、证据与文件对上；普通结果 ZIP 与 config／exp／run 是不同合同
3. **接收方先做只读核验**（5.7.4）——字节与来源、协议与事实、交付结论三层，不需要模型凭据，失败要分类记录
4. **正式复现是一项单独工作**（5.7.5 + 5.7.6）——新跑／续跑／重跑／复算身份不同；一份允许写"尚未验证"的可执行交付记录

### 2.3 Hero 定位

Hero 页 7 张（24 页的 29%，落在 20–30% 区间）：

- **01 封面**——"下载"与"接手"之间的落差
- **04 五类接收检查**——全篇第一个主轴，五个问题并列且不可替代
- **10 四类文件**——普通结果 ZIP 与三种正式包的分岔
- **14 三层只读核验**——字节 → 协议 → 结论的阶梯
- **18 四种工作的输入与身份**——新跑／续跑／重跑／复算的逐行对照
- **21 一份可执行的交付记录**——等宽色块登记样式，全篇唯一的"真实形态"物证
- **24 结束页**——三句话收束
