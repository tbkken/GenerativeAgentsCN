## 二、页面骨架

### 2.1 叙事主线

一句话主线：**委托要的不是一段演示，而是一份别人能检查、能使用、能维护的成果。**

贯穿全篇的一条链：愿望 → 可回答的问题 → 项目约定 → 需求与证据 → 职责与阶段产物 → 相称的完成条件。

### 2.2 目录 ↔ 扉页契约

本节地图页列出 4 个知识块；扉页共 4 张，编号 ①–④ 与地图**一一对应且顺序一致**：

| 编号 | 对应小节 | 扉页 | 覆盖页 |
| :--- | :--- | :--- | :--- |
| ① | 5.1.1 将一句愿望改写成可回答的问题 | 03 | 04–06 |
| ② | 5.1.2 建立一页足够具体的项目约定 | 07 | 08–10 |
| ③ | 5.1.3 把需求连到证据，而不只连到文件名 | 11 | 12–14 |
| ④ | 5.1.4–5.1.6 三类职责、阶段产物与完成条件 | 15 | 16–23 |

### 2.3 Hero 定位

Hero 页 7 张（24 页的 29%，落在 20–30% 区间）：

- **01 封面**——委托人原话 → 研究问题 → 两种交付范围，一条纵向链
- **04 三个未确定**——上大图 + 下方结论条，本节唯一的「一个愿望拆三问」
- **08 设计交付 / 运行交付**——左右双列四行逐行对齐，全篇结构主轴
- **12 R3 追溯链**——四节点横向链，从得分回到事实
- **18 六环节交接**——六节点 + 对齐的六项产物
- **21 完成不等于都肯定**——两种交付范围 + 名称与证据相称
- **24 结束页**——一句可验收的改写 + 落款
