# 第四章场景案例设计

> 编写日期：2026-09-25。本文是[全书大纲](book-capabilities-and-case-roadmap.md)第四章的设计底稿，已据此完成[第四章正文](<chapter 04/README.md>)。下列八个案例均未完成系统资源制作、浏览器搭建或运行验收，规模与观察窗口是待校准的教学建议，不是系统默认参数，也不是已获得的实验结论。正文给出更具体的材料、条件和判分；两者都不冒充运行证据。

第三章通过“社区学习中心开放日”教会读者使用系统；第四章研究不同应用问题。每案选择一个主要干预因素，以真实世界事实和明确的判分规则解释结果，不再重复一次全功能入门。

## 共用的实验设计

### 先确定问题、单位和可观察结果

每案先写一页实验计划：研究问题、参与者、输入事实、干预因素、基线、对照、主要指标、观察窗口、终止条件及不能推出的结论。区分三个层次：系统是否按合同执行、角色行为是否符合本案目标、结果能否解释现实问题。没有现实数据校准与外部验证时，结论仅适用于这些角色、模型和条件下的仿真探索。

观察单位可以是人、请求、任务、消息或已提交行动，不能在计算时临时更换。例如“咨询成功率”的分母是预先登记的咨询任务数，不能改成已经得到回复的任务数。每案建议只选一个主要指标，其余用于解释原因和成本。

下文的观察窗口记为 `W`，从 Run 的第一轮虚拟时间开始，到计划最后一轮的已提交边界结束。步数由虚拟时长与步长换算，先依据地图路线和真实模型吞吐校准，再固定两组参数。窗口结束不强制角色宣布业务成功，也不要求某个业务事件恰好在第几 Step 发生。

### 一次只改变一个因素

基线与对照分别封存为独立实验，保留完整包内资源。除明确列出的干预外，保持地图、角色、初始位置与知识、对象事实、模型及采样参数、视野、注意力、步长、总步数、Skill 依赖和结果留存设置一致。改变地图布局的案例则列出唯一移动的语义对象及其前后坐标，其他可走区域和碰撞保持一致。

自然语言干预应保存精确差异。例如“使用交接清单”只能修改交接 Skill 的相关段落，不能同时让对照组得到更多初始事实或更大视野。对象自主行为、角色自由回复可能导致实际进程不同，这些差异是待观察的结果；没有按设想发生的 Run 也保留。

每组先做少量独立新 Run 检查可执行性，再按预算增加重复次数。建议以每组 3–5 次作为教学探索起点，不能据此宣布统计显著或普遍优越。记录全部 Run，报告单次结果、组内分布和失败数；有足够样本再报告适当的不确定性区间。相同随机种子不保证模型生成相同。

### 用事实链和判分表连接指标

世界变化以已提交 StepResult、Event 与 `structured_payload` 为准；位置使用实际坐标与地址，交互使用真实请求 ID，对话使用会话 ID，记忆使用实际记录 ID 和有效态。Trace 用于解释调用过程，中间文字不能证明抵达、回复送达、设备修复或状态换图。

业务判断需要语义阅读时，在运行前制作简短判分表，给出成立、部分成立、不成立和无法判断的例子。人工评分保留所依据的 Agent、Step、Event、会话或记忆记录；关键样本可由两名评阅者独立判分并解释分歧。不要要求 Skill 为教材另造一套回放 JSON。人工或外部评分不冒充系统内置 Evaluator 的执行结果。

比率统一报告“分子 / 分母”和百分比；分母为零时标为“不适用”，不能写 0% 或 100%。时延以虚拟分钟或 Step 为单位，说明起止事件；到窗口结束仍未完成的样本标为未完成，单列数量，不从时延统计中悄悄删除，也不擅自把窗口长度当成真实完成时长。暂停、调试和模型耗时不计入虚拟业务时延。

模型逻辑调用与物理尝试分别记录。涉及“每个成功结果的成本”时，分子包括为所有样本发生的调用，分母仅为按预先规则成立的结果数，并同时报告成功率；没有成功结果时成本标为不可计算。Token、费用或原始 Payload 未留存时写“未记录”，不按想象补齐。

### 所有案例共同的系统验收

主 Agent 按浏览器完成素材上传、资源绑定、包内编辑、预检、封存、运行和回放；资料生成与离线读导出不能代替页面操作。每案独立保存 `map/`、`agents/`、`skill/`、`settings/`，另设 `verification/` 保存证据，不能依赖上一案例的公共资源副作用。

系统验收检查四层空间、真实出生地址、依赖闭包、身份注入、每个参与者每 Step 至多一次成功动作、对象回复只向目标次轮投递一次、已提交事实与回放一致。新跑、续跑和重跑的身份分别核对。业务没有达标不自动等于系统缺陷；预期权限或不可达拒绝先按合同解释。发现当前案例的新 bug 或体验问题时，按仓库约定停止构建/运行验收、留证据，等待针对该问题的明确决定。

对象绑定根 Skill 后按 SOP 自主执行，拥有独立私有状态和记忆。人物通过 `INTERACT` 请求，不能直接修改绑定对象内部状态。对象用 `SET_OBJECT_STATE` 修改自身，用同次 `world-act.responses` 回复真实请求；公开 `state` 外观标签不意味着其他内部字段自动公开。以下场景都不假定内核自带业务队列、库存锁、审批权限、动态碰撞或物理设备机理。

## 4.1 社区服务大厅：减少问错窗口与重复咨询

**业务问题。** 当来访者只知道自己的需求、不了解服务分工时，入口咨询方式能否减少走错窗口和重复说明？重点是服务分流与等待体验，不模拟真实行政审批。

**规模建议。** 4 名来访者、1 名引导员；入口、等候区和两个服务区共 4 个 Arena；咨询台及两个窗口为绑定根 Skill 的对象。每个来访者有一项虚构、难度相近的咨询任务，两类需求各 2 人。建议先考察 60–90 个虚拟分钟，路径与回复周期校准后确定步数。

**SOP 与事实链。** 来访者描述需求，必要时补充缺失材料信息；咨询台按服务范围解释可去的窗口。人物根据真实感知或交互反馈获得地址，导航并实际抵达后咨询目标窗口。窗口可按 SOP 记住本人的待处理请求、给出咨询意见，并在需要等待时说明条件；这属于对象行为策略，不是内核提供的排队服务。记录“提出需求→咨询回复→实际移动→正确窗口回应→人物确认下一步”的事实链，确认不等于真实业务办理成功。

**单变量对照。** 基线咨询台一次给出建议；对照咨询台在需求缺少一个预先规定的关键字段时先澄清，再建议窗口。只改变咨询台的澄清策略，服务范围、来访者信息、窗口位置和工作人员保持一致。不预设澄清必然节省时间，它可能减少走错却增加前置交互。

| 指标 | 分母、单位与窗口 |
| --- | --- |
| 正确咨询闭环率（主要） | `W` 内取得适配自身需求的目标窗口回复，并实际确认下一步的任务数 / 全部 4 项初始咨询任务；单位 %。用预设服务范围判定适配。 |
| 无效窗口访问率 | `W` 内向不处理该需求的窗口提交的真实交互请求数 / 全部窗口交互请求数；单位 %。入口澄清请求不进入该分母。 |
| 重复说明负担 | `W` 内针对同一任务、向已接收过同一核心需求的服务对象重复提交且未补充新信息的次数 / 全部初始咨询任务数；单位 次/任务，依据请求原文和判分表。 |
| 首次有效回应时延 | 从首次提交咨询请求，到得到第一条可执行且与该需求适配的回复的虚拟分钟；按两类需求分别报告中位数、范围和未回应人数。不得用仅已完成组的平均数宣称公平。 |

**验收边界。** 行为验收关注建议是否正确、人物是否真实到达、等待是否有依据。系统验收关注请求/回复身份、次轮投递和路径事实。窗口之间的“先来先服务”若要研究，必须明确写成对象 SOP 并观察执行，不能称为已存在的内核队列。组间需求差异只能讨论本次设定中的体验差别，不能推出真实人群的公平结论。

## 4.2 组织任务交接：设备维护班组的信息交接

**业务问题。** 设备检查从上一班交给下一班时，怎样减少证据遗漏、无依据的“已经修好”和重复检查？本案把组织协作放进工业班组背景，研究交接信息，不模拟真实维修和设备物理故障。

**规模建议。** 交班员、接班员、复核员共 3 名 Agent；值班室、设备间、资料区共 3 个 Arena；一台绑定根 Skill 的教学设备和一个交接记录设施。所有人物从 Run 开始即存在，接班前可按明确条件等待，不假定系统动态创建班次或人员。建议窗口为 90–120 个虚拟分钟。

**SOP 与事实链。** 设备在包内保存虚构且明确的异常信息，并通过交互回答可公开的观察结果。交班员获取现状，记录已观察事实、未确认推断和待办；接班员接收交接后复述重点、核对设备，再选择普通检查活动。复核员只根据真实消息和对象回复提出核查建议。链条是“设备回复→交班记录→交接发言→接班检索/复述→再次核对→确认或保留待办”。`ACT` 写“检查”只能证明角色执行了该活动，不能证明物理设备恢复正常。

**单变量对照。** 基线允许自由叙述交接；对照调用包含“现象、证据来源、已做、待做、不能确认”五项的交接整理子 Skill。两组由设备提供完全相同的信息，角色最初知道的内容一致；仅改变交接组织方法，其他 Brain 决策和复核条件保持一致。

| 指标 | 分母、单位与窗口 |
| --- | --- |
| 关键交接信息到达率（主要） | 首次交接开始后至 `W` 结束，接班员实际收到且正确复述或使用的关键事实条数 / 预先列出的应交接关键事实总数；单位 %。来源未知的重复说法不算正确到达。 |
| 无依据完成声明率 | `W` 内宣称某项检查或问题已完成、但缺少本案规定证据的声明数 / 全部完成声明数；单位 %，明确“观察到状态恢复”与“猜测恢复”的判据。 |
| 不必要重复检查率 | `W` 内在没有新证据、状态变化或复核要求时重做的检查任务实例数 / 全部已提交检查任务实例数；单位 %。正常复核不算重复劳动。 |
| 每项有效交接的调用成本 | `W` 内全部模型逻辑调用数 / 满足预定信息到达条件的交接任务数；单位 调用/任务，另列物理尝试数及失败任务数。 |

**验收边界。** 行为验收看信息是否保留不确定性、接班是否使用真实证据。系统验收看记忆隔离、会话关联、子调用 Trace 和对象状态权限。若设计状态变化，由设备根 Skill 在自身 SOP 和真实请求下提交，不能让人物职业名称授予修改设备权限。设备维修质量、故障概率、零件库存和真实工业安全均不在本案结论内。

## 4.3 图书馆／展馆运营：让访客找到适合的区域

**业务问题。** 在没有完整场馆认知的情况下，导览信息放在哪里更容易被发现，是否帮助不同兴趣的访客选择合适区域？重点是空间布局和信息可见性，而非服务窗口分流。

**规模建议。** 4 名访客、1 名讲解员；入口、两处主题区和休息区共 4 个 Arena；一个绑定根 Skill 的导览牌、两件提供主题介绍的对象。访客有不同但明确的兴趣与一个相同的步行预算约束。建议窗口为 45–75 个虚拟分钟。

**SOP 与事实链。** 访客从当前可见内容出发了解区域，必要时咨询导览牌或讲解员；选择匹配兴趣的区域，真实抵达后进行阅读或观看活动，再记录体验。导览牌只能依据包内内容说明区域，不编造服务。链条是“发现标识→获得主题/地址→选择→实际路径→目标区域 ACT→体验记录”。评价匹配依据预先登记的兴趣和主题事实，不根据角色最后一句满意宣言判定。

**单变量对照。** 基线导览牌位于入口侧面，对照移动到入口主要可见路径旁；只改导览牌的语义位置及其一致的图片位置，内容、主题区、碰撞、人物起点、视野和注意力不变。导览牌不得成为新增路障。讲解员的帮助策略在两组保持相同。

| 指标 | 分母、单位与窗口 |
| --- | --- |
| 合适区域使用率（主要） | `W` 内在满足自身兴趣条件的区域真实抵达并完成至少一次对应活动的访客数 / 全部 4 名访客；单位 %，每人最多计一次。 |
| 导览发现率 | 在进入第一个主题区前，真实感知结果中出现导览牌或向其提交交互的访客数 / 全部访客数；单位 %。模型口头说“看见标识”不替代感知证据。 |
| 每次成功访问的实际路程 | `W` 内全体访客已执行 MOVE 路径的格数总和 / 成功的合适区域访问数；单位 格/次，同时报告没有成功访问的人数。导航计划路径不计。 |
| 首次匹配时延 | 从 Run 开始至每名访客首次在合适区域提交对应活动的虚拟分钟；报告分布及窗口内未匹配人数，并按兴趣组列出原始结果。 |

**验收边界。** 行为验收区分“知道区域”“到达区域”和“开始对应活动”。系统验收关注标识移动后的语义/图片一致、可见范围与实际路径。该实验可以比较作者定义布局中的可发现性，不能直接证明真实建筑导视效果；人物视角、脚底锚点和模型注意力也不是人的视觉测量。

## 4.4 通知纠错与信息传播：让过期消息退出当前认识

**业务问题。** 一条原本有效、后来被明确更正的活动地点消息，如何在小群体中传播和退出旧计划？重点是信息来源、记忆有效态与纠错链，区别于单纯“大家有没有到场”。

**规模建议。** 通知协调员与 3 名参与者，共 4 名 Agent；旧地点、新地点和连接区域共 3–4 个 Arena；一个保存当前通知的公告对象。各组使用同一条旧通知、同一条有依据的更正请求和同样的初始知情分布。建议窗口为 60–90 个虚拟分钟，并给首次更正后的接收与行动留出若干轮。

**SOP 与事实链。** 先让参与者通过真实公告回复或发言获得旧地点；协调员在确认已有旧通知接收证据后向公告对象提出更正。公告对象核对自身内容并提交新状态与回复。参与者只在实际收到更正后更新认识，按相同规则告知已交流过的同伴。链条为“旧通知事实→旧记忆→对象更正提交→定向反馈/发言→新记忆→后续行动”。若某 Run 未触发更正，记为未形成纠错观察条件，不编造更正时点。

**单变量对照。** 基线收到更正后仅追加新记忆；对照对已确认过期的旧通知调用 `supersede`。两组的更正内容、证据说明、通知同伴规则、检索问题和行动目标保持相同。观察是否替代记忆有效减少旧内容干扰，而非预设追加策略一定失败。没有替代内容的作废信息另设 `invalidate` 小练习，不混入本次主比较。

| 指标 | 分母、单位与窗口 |
| --- | --- |
| 更正后的过期行动率（主要） | 从每名参与者实际接收更正起至 `W` 结束，仍按已作废地点提交的相关导航后移动、到场活动或传播声明数 / 同一窗口内其全部相关行动和传播声明数；单位 %，逐项保留判分事实。 |
| 更正覆盖率 | 公告更正提交后至 `W` 结束，实际收到正确更正的目标参与者数 / 预定应通知参与者总数；单位 %。知道世界已改不等于每个人已收到。 |
| 有效记忆纠正率 | `W` 结束时，已接收更正且默认检索不再返回旧有效通知的参与者数 / 已接收更正且曾存储旧通知的参与者数；单位 %，以真实 search 和记忆有效态为证。 |
| 更正传播时延 | 从公告更正的提交 Step 到各目标参与者首次实际接收更正的 Step 差；单位 Step，报告分布、未接收人数与未触发更正的 Run 数。 |

**验收边界。** 行为验收不把先前合理使用旧消息算成错误，也不把只见过新消息的人当作已完成记忆纠正。系统验收核对对象自己改状态、回复身份、消息与会话链、旧记忆保留历史且有效态正确。来源追踪使用导出事实与人工关联，不宣称系统已经提供通用社会传播因果分析器。

## 4.5 小组协作学习：共享分散信息并形成有依据的结论

**业务问题。** 当解题所需事实分散在不同成员手中，讨论组织方法是否改善信息汇总和结论质量？这是知识整合任务，不将模型扮演的学生表现等同于真实教学效果。

**规模建议。** 3 名学习者、1 名主持人；讨论区和资料区共 2 个 Arena；一处提供共同题面的资料对象。选择可人工核验的教学虚构题，例如在若干场地约束下选出可行活动方案；每名学习者掌握不同的必要条件，完整条件集、正确答案与评分表留在教师资料中，不送入所有角色上下文。建议窗口为 45–60 个虚拟分钟。

**SOP 与事实链。** 成员先理解自己掌握的条件，听取他人陈述，遇到矛盾再请求澄清；主持人整理已共享证据并提出候选结论，成员以实际发言支持或反驳。最终结论必须有可定位的公开发言及依据，私人想法不算小组已共享。链条为“私人条件→SPEAK→他人收到→记忆/核对→候选方案→有证据的共同结论”。

**单变量对照。** 基线主持人自由组织讨论；对照主持人在信息出现冲突或准备总结时调用“逐项核对约束”子 Skill。成员知识、题目、回答策略和讨论时间相同，只改变主持人的核对方法。子 Skill 不接触教师答案，也不保证每轮都调用。

| 指标 | 分母、单位与窗口 |
| --- | --- |
| 结论约束满足率（主要） | `W` 内最后一份明确公开的最终方案满足的可判定条件数 / 题目全部必需条件数；单位 %。没有最终方案单列，不能用最好的一次候选代替。 |
| 必要信息共享率 | `W` 内至少被持有者或实际获知者正确公开表达一次的必要条件数 / 全部预设必要条件数；单位 %，重复表达不重复计数。 |
| 发言有效贡献率 | `W` 内提供新必要事实、纠正错误或完成有效推导的成员发言数 / 全部与任务有关的成员发言数；单位 %，按预设量表判分并保留分歧。 |
| 每项正确结论的调用成本 | `W` 内全组模型逻辑调用数 / 满足所有必需条件的最终方案数；单位 调用/方案；同步报告未形成或不正确方案的 Run 数。 |

**验收边界。** 行为验收看最终结论和证据，不要求语言完全相同，也不把长篇发言等同于贡献。系统验收核对私人知识没有从跨身份记忆泄漏、会话参与者正确、子 Skill 的输入输出可定位。人工评分是本案评价，当前业务 Evaluator 是否由 Runtime 消费须按实现状态另报。

## 4.6 社区公共议题协商：保留分歧的有依据决定

**业务问题。** 对共享空间使用规则存在不同偏好时，协商方法能否让理由被听见，并形成清楚记录的决定或未解决分歧？本案不同于有标准答案的协作解题，也不把一致发言率当作唯一成功指标。

**规模建议。** 3 名具有不同偏好的居民代表、1 名主持人；一处会议 Arena 和一处资料区；一个保存既有场地事实的说明对象。题目可为晚间活动时段安排，输入包括可使用时间、安静需求及活动需求；人物偏好是教学设定，不代表真实人口群体。建议窗口为 60–90 个虚拟分钟。

**SOP 与事实链。** 代表说明偏好和理由，区分不可妥协条件与可调整要求；主持人核对事实，归纳选项，再请各方明确同意、保留或反对。依据实际发言记录决定与分歧。链条为“理由提出→事实核对→选项比较→各方明确回应→决定及未解决事项”。不能从沉默推定同意，也不能让角色读取其他人的私有偏好来编造代表意见。

**单变量对照。** 基线主持人按开放讨论整理方案；对照在形成最终方案前增加一次“逐人确认理由是否被准确表达”的复述环节。两组初始偏好、共同事实、选项范围和总窗口相同，只改变这个确认环节。对照耗时增加或最终仍无共识都属于可报告结果。

| 指标 | 分母、单位与窗口 |
| --- | --- |
| 重要理由准确纳入率（主要） | `W` 内最终公开记录中被准确表达的已公开重要理由数 / 全部已公开且经预设规则判定为重要的理由数；单位 %，不把记录不赞同等同于忽略。 |
| 明确回应覆盖率 | `W` 内对最终候选方案明确表达同意、保留或反对的代表数 / 全部 3 名代表；单位 %。无最终候选方案时标为未进入该阶段。 |
| 事实性错误比例 | `W` 内协商发言中与共同材料矛盾或无材料支持却当作事实的可核验声明数 / 全部可核验事实声明数；单位 %；价值偏好不按真伪评分。 |
| 保留意见记录率 | `W` 内在最终公开记录中保留原意的反对/保留事项数 / 最终确认环节明确提出的反对/保留事项总数；单位 %，没有此类事项时不适用。 |

**验收边界。** 行为验收允许形成“尚无一致意见”，但须清楚说明分歧；不以强行改写人物偏好制造成功。系统验收关注真实发言、会话关联和私有记忆边界。本案只能研究所设角色的协商过程，不推断现实居民支持率、政治倾向或政策效果。

## 4.7 选修：场地临时关闭演练

**业务问题。** 某条原本常用的通路在本次活动中关闭时，参与者能否依据真实可达性改道并在窗口内集合？主要研究路线适应；通知速度是可另行设计的研究问题，不能同时作为本轮干预。

**规模建议。** 3 名参与者、1 名引导员；入口、两条路线及集合区共 4–5 个 Arena；一个给出当前路线说明的公告对象。选择存在可走替代路线的小地图，先在 UI 校验两种布局。建议窗口为 30–60 个虚拟分钟，根据最长替代路径校准。

**SOP 与事实链。** 参与者确认集合目标，依据已知地址查询路线；常用通路关闭但另有可走路径时，导航应返回通往同一集合目标的绕行路径，参与者根据实际结果提交 MOVE。只有真实没有可达路径时，才记录不可达原因并查询其他有证据的目标或咨询引导员，不猜门洞、不穿墙。公告对象按本实验事实答复。主要链条为“真实路线查询→取得实际可达路径→提交并执行移动→集合区到达”；不可达另按真实发生情况记录。等待只用于真实条件和明确边界，不用 WAIT 假装已经完成集合。

**单变量对照。** 基线地图开放常用通路；对照在封存前关闭该通路的固定碰撞位置，两组其他区域、角色、起点、目标与一般引导策略一致。公告在两组均要求参与者以实际导航为准，避免同时改变信息质量。所谓“临时关闭”是本次实验开始时已存在的场景条件，不在 Run 中动态改碰撞。如果另研究提前通知，应单独建立“同一关闭地图、只有通知策略不同”的一对实验。

| 指标 | 分母、单位与窗口 |
| --- | --- |
| 集合到达率（主要） | `W` 内实际坐标进入集合区的参与者数 / 全部 3 名参与者；单位 %，引导员不在分母内。 |
| 路线执行启动时延 | 两组分别记录，从每人首次获得通往集合目标的可达路径，到首次提交沿该路径的 MOVE 的虚拟分钟；报告分布及取得路径但未开始执行的人数。同 Step 完成查询和动作可为 0；没有取得可达路径的人另列。 |
| 实际移动负担 | `W` 内所有参与者的已执行路径格数 / 初始参与者数；单位 格/人，同时列到达率，避免将没有移动误判为效率高。 |
| 无效导航／移动请求率 | `W` 内因目标证据不足、地址不合法或权限不符而被拒绝的导航/移动请求数 / 全部导航与移动请求数；单位 %，按实际拒绝原因分类。合法目标真实不可达不混入该分子，正常返回绕行路径也不算拒绝。 |

**验收边界。** 行为验收允许未集合和不同路线选择，但必须解释实际证据。系统验收检查碰撞与已执行路径、拒绝是否符合合同、旧计划是否被错误当作实际位移。静态地图存在替代路径时，直接返回可达绕行路线属于正常行为，不能因没有先拒绝而判为缺陷；如需测试真正不可达，应另做目标确实无路径的独立对照。本案不模拟烟气、踩踏、容量约束、人员伤亡或真实应急安全，不把集合比例作为现实疏散合规结论。

## 4.8 选修：长时程校园生活中的计划与记忆演变

**业务问题。** 当观察跨越昼夜和多个活动周期时，角色是否保持身份与计划连续性，怎样处理已完成、未完成和改变的事项，额外整理记忆是否值得成本？本案放在短案例后，重点是长期一致性与运行资源。

**规模建议。** 先用 3–4 名 Agent、4–6 个相邻 Arena 和 1–2 个必要对象；观察 24–48 个虚拟小时。Step1 对应起点，若步长为 10 分钟，精确覆盖24/48小时并含终点需145/289步；实际覆盖为 `(最后提交Step−1)×步长`。必须先核对路径、活动粒度及模型成本后决定。每晚和跨日等待有明确虚拟时间边界；不能靠超大地图和全天活动清单制造难度。

**SOP 与事实链。** 角色根据虚拟时间、真实位置、已有承诺和有效记忆选择活动；行动前记“待确认”，次轮核实后才标记完成。适当时整理已确认经历和剩余事项，不能把总结产生的新说法当作历史事实。链条为“承诺/目标→跨步进度→实际活动→完成证据→记忆整理→下一周期选择”。日常生活内容保持简洁，不要求每个时点执行固定活动。

**单变量对照。** 基线仅维护累计进度便签；对照在跨日或累积足够新经历时，按同一明确条件调用一次“整理已确认事项”子 Skill。只有整理策略改变，角色任务、记忆访问权限、场景、模型和窗口不变。不预设整理一定改善行为，注意摘要遗漏和额外调用。

| 指标 | 分母、单位与窗口 |
| --- | --- |
| 已确认事项反复执行率（主要） | `W` 内已有完成事实、没有新需求却再次执行的预登记一次性任务实例数 / 全部已提交的一次性任务执行实例数；单位 %。日常周期性活动不算重复错误。 |
| 承诺兑现率 | 截止时间落在 `W` 内且被角色明确接受的承诺中，按截止时间及事实标准完成的条数 / 全部此类承诺数；单位 %。无明确截止的愿望另列。 |
| 记忆整理事实保真率 | 对照组在 `W` 内整理内容中，能被此前已提交事实或有效来源记录支持的可核验声明数 / 全部可核验整理声明数；单位 %，区分引用他人说法与本人观察。 |
| 每人每虚拟小时调用量 | `W` 内全体角色及对象的模型逻辑调用数 /（初始 Agent 数 × 实际覆盖的虚拟小时）；单位 调用/(人·虚拟小时)，另列对象调用数、物理尝试和暂停墙钟。 |

**验收边界。** 行为验收检查跨日日期、计划与事实、重复活动和总结偏差，不要求所有人一直忙碌。系统验收另做一次明确的暂停/续跑检查，核对同 Run、新 Attempt、下一提交 Step 和无重复副作用；两组若进行恢复比较，应采用同一规则，不能只中断一组后把差异归因于记忆策略。历史校园长 Run 不替代本案新设计的验收，长时程模型表现也不能直接推论真实人的生活规律。

## 制作与验证优先顺序

| 阶段 | 案例 | 进入条件与本阶段产物 |
| --- | --- | --- |
| 前置 | 第三章贯穿案例 | 先完成短流程、对象自主执行、记忆、会话、运行控制及导出的当前版本验收；既有历史 Run 仅作参考。 |
| 第一批 | 4.1 服务大厅、4.3 图书馆／展馆 | 地图较小、目标事实明确，先建立比率、时延、路径和未完成样本的教学模板。两案分别研究交互策略与空间布局。 |
| 第二批 | 4.2 班组交接、4.4 通知纠错 | 在请求/回复、记忆替代和会话证据可靠后制作；补齐信息到达、事实保真和无依据声明的评分表。 |
| 第三批 | 4.5 协作学习、4.6 公共议题协商 | 先准备可核验题目与开放协商两种不同量表，再运行；避免用同一个“任务成功率”掩盖知识正确性与意见表达的区别。 |
| 选修扩展 | 4.7 临时关闭 | 先验收独立地图的通路与碰撞；本轮只研究静态关闭条件，不扩展动态设施或物理灾害。 |
| 最后 | 4.8 长时程校园 | 短案例的恢复、质量汇总和成本记录通过后再增加窗口；先明确预算和观察价值，再扩大人数或地图。 |

每案完成后交付基线与对照的独立实验清单、精确 Skill 差异、预定指标表、全部 Run 结果索引、关键事实、评分记录、质量与成本，以及正常、失败、未完成样本。正式 `.gaexp/.garun`、普通结果 ZIP、独立环境复现分别标记状态；未完成的导出和复现不写成“一键可用”。

正文已补充具体角色、任务事实、空间设计、SOP 差异和人工判分示例。后续仍须将教案制作成每案独立的完整资源与 Skill，经浏览器搭建并取得真实证据；调整条件时保留原计划和记录。本文给出的策略与指标不能提前写成效果结论。
