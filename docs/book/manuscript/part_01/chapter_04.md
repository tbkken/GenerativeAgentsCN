# 第 4 章 论文架构一：人物定义 Persona

Smallville 不是空城，它之所以能呈现可信社会行为，前提是小镇里的每个居民都被定义成一个具体的人。这里的“人”不是指真实意识，也不是指复杂心理模型，而是指一个能持续行动的角色锚点：

- 他是谁
- 他住在哪里
- 他平时怎么生活
- 他和谁有关系
- 他最近在关心什么
- 他已经知道哪些事情

这些信息共同构成人物定义 Persona。没有人物定义 Persona，后面的记忆流 Memory Stream、检索 Retrieval、反思 Reflection、日程 Planning 和对话 Dialogue 都没有稳定对象。记忆不知道属于谁，计划不知道服务谁，对话也不知道应该延续什么关系。

> 人物定义 Persona 是生成式智能体的身份底座。它让同一个大语言模型 LLM 在不同角色身上表现出不同生活轨迹，而不是每一轮都重新生成一个陌生人。

![图 4-1：人物定义 Persona：从角色档案到小镇行动](../../assets/chapter_04/ch04_persona_identity_workbench.png)

*图 4-1：人物定义 Persona 的系统入口。角色不是一句角色卡，而是从角色配置 `agent.json` 进入提示词组装器 Scratch、空间记忆 Spatial、关联记忆 Associate 和日程 Schedule，再影响记忆流 Memory Stream、日程 Planning、对话 Dialogue、反应 Reacting 和最终行动 Action。*

## 4.1 人物定义 Persona 的位置

生成式智能体 Generative Agents 的架构经常被概括为记忆流 Memory Stream、检索 Retrieval、反思 Reflection、日程 Planning 和对话 Dialogue。这个概括没有错，但如果直接从记忆流 Memory Stream 开始，读者容易漏掉一个更基础的问题：

经验流属于谁？同样一件事，进入不同角色的人生里，意义并不一样。

 - 伊莎贝拉 Isabella Rodriguez 听到“情人节派对”，会想到咖啡馆、顾客、布置和邀请。
 - 山姆 Sam Moore 听到“地方选举”，会想到竞选、邻居、公共事务和说服。
 - 克劳斯 Klaus Mueller 听到“社会议题”，会联想到研究论文、低收入社区、社会正义和学术讨论。
 - 玛丽亚 Maria Lopez 听到“霍布斯咖啡馆”，可能会想到学习、吃饭、直播之余的社交机会。

这些差异不是记忆流 Memory Stream 自动产生的。它们来自角色一开始就拥有的身份、习惯、关系和目标。

```mermaid
flowchart TD
    Persona["人物定义 Persona<br/>身份/性格/习惯/关系/目标"] --> Memory["记忆流 Memory Stream<br/>这个人经历过什么"]
    Persona --> Planning["日程 Planning<br/>这个人今天要做什么"]
    Persona --> Dialogue["对话 Dialogue<br/>这个人会如何说话"]
    Persona --> Reaction["反应 Reacting<br/>这个人如何解释现场事件"]

    Memory --> Retrieval["检索 Retrieval<br/>想起哪些经历"]
    Retrieval --> Planning
    Retrieval --> Dialogue
    Planning --> Action["可信行为"]
    Dialogue --> Memory
    Reaction --> Action
```

*图 4-2：人物定义 Persona 在生成式智能体 Generative Agents 架构中的位置。人物定义 Persona 不是装饰性人设，而是记忆流 Memory Stream、日程 Planning、对话 Dialogue 和反应 Reacting 共同依赖的身份底座。*

## 4.2 人物定义不是一句角色卡

很多大语言模型 LLM 角色应用会把人物定义 Persona 简化成一句角色卡：

```text
你是伊莎贝拉，34 岁，友好、外向，是霍布斯咖啡馆老板。
```

这能让模型说话时带一点角色味道，但还不够支撑小镇生活。小镇居民不是只在被用户提问时出现。他们会起床、工作、吃饭、移动、等待、聊天、错过事件、记住邀请、调整计划。要支撑这些行为，人物定义至少要覆盖六个层面。

| 定义层 | 中文意思 | 对可信行为的影响 |
| --- | --- | --- |
| 身份 | 角色是谁，年龄、职业、家庭或社会位置是什么。 | 决定角色能自然做什么，不能突然变成另一个人。 |
| 性格 | 角色稳定的反应倾向和说话气质。 | 影响对话风格、是否主动社交、如何回应冲突。 |
| 背景知识 | 角色已经知道的事实、经历、专业和个人历史。 | 让回答和行动有来历，不像空白模型临场编造。 |
| 生活习惯 | 作息、常去地点、日常活动节奏。 | 生成日程时提供生活骨架，让角色不是随机游走。 |
| 社会关系 | 角色和其他居民的亲疏、合作、冲突或共同经历。 | 决定对话是否自然，信息传播是否有路径。 |
| 当前目标 | 角色最近正在关心或推进的事情。 | 让今天的行为有方向，例如筹备派对、竞选市长、写论文。 |

*表 4-1：人物定义的六个层面。人物定义 Persona 的作用不是写一段漂亮介绍，而是给后续行为生成提供稳定约束。*

这张表也解释了为什么“可信行为”不能只靠提示词 prompt 语气。一个角色说话像咖啡馆老板，只是表层可信；他每天会去咖啡馆、会关心顾客、会把派对消息告诉合适的人，才是系统层面的可信。

## 4.3 系统中如何定义一个角色

在项目里，定义一个角色不是只写一句提示词 prompt。一个可运行智能体由多类配置和运行模块共同装配出来。读者在这个阶段不需要逐行读源码，但必须先知道完整角色定义会流向哪里。

角色配置先进入运行链路，再被拆给不同模块使用。

```mermaid
flowchart TD
    JSON["agent.json<br/>人物定义入口"] --> Game["Game.__init__()<br/>合并公共配置与角色配置"]
    Config["data/config.json<br/>公共运行参数"] --> Game
    Game --> Agent["Agent.__init__()<br/>装配运行对象"]

    Agent --> Scratch["提示词组装器 Scratch<br/>生成基础人物描述"]
    Agent --> Spatial["Spatial<br/>角色知道的地点和对象"]
    Agent --> Schedule["Schedule<br/>日程系统"]
    Agent --> Associate["Associate<br/>长期记忆库"]
    Agent --> Action["Action<br/>当前行动"]
    Agent --> Maze["Maze / Tile<br/>当前位置与地图事件"]

    Scratch --> Prompts["各类提示词 prompt<br/>日程/对话/反思/评分"]
    Spatial --> Prompts
    Schedule --> Prompts
    Associate --> Prompts
```

*图 4-3：项目中角色定义进入系统的路径。角色配置 `agent.json` 只是入口，真正运行时还要被拆入提示词组装器 Scratch、空间记忆 Spatial、日程 Schedule、关联记忆 Associate、行动 Action 和世界地图 Maze。*

## 4.4 base_desc.txt：基础人物描述模板

项目里最核心的人物描述模板是 `generative_agents/data/prompts/base_desc.txt`。这是很多后续提示词 prompt 的共同底座。读这段模板前，先把变量含义看清楚。

| 模板字段 | 主要来源 | 中文意思 | 对行为的影响 |
| --- | --- | --- | --- |
| `${name}` | `name` | 角色姓名。 | 让模型知道当前要扮演的是哪个居民。 |
| `${age}` | `scratch.age` | 角色年龄。 | 影响说话方式、生活阶段、社会角色和日程合理性。 |
| `${innate}` | `scratch.innate` | 先天或稳定性格，例如友好、好奇、热情。 | 影响角色遇事时的反应倾向和对话气质。 |
| `${learned}` | `scratch.learned` | 后天经历、职业身份、专业背景和重要关系。 | 决定角色为什么会关心某些事情，也决定他能自然谈论什么。 |
| `${lifestyle}` | `scratch.lifestyle` | 长期生活习惯，例如几点睡、几点起、平时如何生活。 | 给日程生成提供作息边界，避免角色每天随机生活。 |
| `${daily_plan}` | `scratch.daily_plan` | 角色典型一天会做什么。 | 让系统生成一天安排时有稳定骨架。 |
| `${date}` | 仿真时钟 | 当前日期。 | 让计划、回忆和事件时间对齐。 |
| `${currently}` | `currently` | 角色最近正在关心、准备或推进的事情。 | 直接影响今天最可能出现的行动和对话主题。 |

*表 4-3：基础人物描述提示词 prompt 的字段含义。定义角色时，最重要的不是写得漂亮，而是让每个字段都能影响后续行为。*

完整的中文模板如下：

```text
姓名: ${name}
年龄：${age}
先天特质：${innate}
后天特质：${learned}
生活习惯：${lifestyle}
日常计划：${daily_plan}

今天是 ${date}，${currently}
```

英文对照模板可以这样理解：

```text
Name: ${name}
Age: ${age}
Innate traits: ${innate}
Learned traits: ${learned}
Lifestyle: ${lifestyle}
Daily plan: ${daily_plan}

Today is ${date}. ${currently}
```

以伊莎贝拉 Isabella Rodriguez 为例，按项目字段填充后，基础人物定义提示词 prompt 是：

```text
姓名: 伊莎贝拉
年龄：34
先天特质：友好、外向、好客
后天特质：伊莎贝拉是霍布斯咖啡馆的老板，她总是想办法让咖啡馆成为人们放松和享受的地方。
生活习惯：伊莎贝拉晚上11点左右上床睡觉，早上6点左右醒来。
日常计划：伊莎贝拉每天早上8点开放霍布斯咖啡馆，站在柜台前直到晚上8点，然后关闭咖啡馆。

今天是 2024年02月13日（星期二）。伊莎贝拉计划于2月14日下午5点在霍布斯咖啡馆与她的顾客举行情人节派对。她正在收集聚会材料，并告诉大家在2月14日下午5点至7点在霍布斯咖啡馆参加聚会。
```

对应的英文写法可以这样写：

```text
Name: Isabella
Age: 34
Innate traits: friendly, outgoing, hospitable
Learned traits: Isabella is the owner of Hobbs Cafe. She is always looking for ways to make the cafe a place where people can relax and enjoy themselves.
Lifestyle: Isabella goes to bed around 11 PM and wakes up around 6 AM.
Daily plan: Isabella opens Hobbs Cafe at 8 AM every day, stands behind the counter until 8 PM, and then closes the cafe.

Today is Tuesday, February 13, 2024. Isabella plans to hold a Valentine's Day party with her customers at Hobbs Cafe at 5 PM on February 14. She is gathering party materials and telling everyone to attend the party at Hobbs Cafe from 5 PM to 7 PM on February 14.
```

这段提示词 prompt 的价值不在于文采，而在于它把角色定义压成模型每次都能读懂的基础上下文。后面生成起床时间、一天日程、对话、反思焦点、事件重要性评分时，都会反复用到这类基础描述。到第 15 章，这些字段会进入智能体 Agent 初始化链路，继续连接提示词组装器 Scratch、空间记忆 Spatial、日程 Schedule 和关联记忆 Associate。

## 4.5 agent.json：角色配置的真实格式

基础人物描述提示词 prompt 不是手写出来的孤立文本，它来自每个角色目录下的 `agent.json`。以伊莎贝拉 Isabella Rodriguez 为例，真实配置文件位于：

```text
generative_agents/frontend/static/assets/village/agents/伊莎贝拉/agent.json
```

下面保留完整顶层字段，并只截取空间树 spatial.tree 里最能说明问题的两个分支：霍布斯咖啡馆和伊莎贝拉的公寓。完整文件还包含玫瑰酒吧、哈维奥克供应店、柳树市场和药店、奥克山学院宿舍、约翰逊公园等已知地点。

```json
{
  "name": "伊莎贝拉",
  "portrait": "assets/village/agents/伊莎贝拉/portrait.png",
  "coord": [72, 14],
  "currently": "伊莎贝拉计划于2月14日下午5点在霍布斯咖啡馆与她的顾客举行情人节派对。她正在收集聚会材料，并告诉大家在2月14日下午5点至7点在霍布斯咖啡馆参加聚会。她也邀请本地记者林晓在社区公告板旁收集居民留言，希望林晓能帮忙把派对和社区活动告诉更多居民。",
  "scratch": {
    "age": 34,
    "innate": "友好、外向、好客",
    "learned": "伊莎贝拉是霍布斯咖啡馆的老板，她总是想办法让咖啡馆成为人们放松和享受的地方。她和本地记者林晓关系友好，经常请林晓记录咖啡馆里的社区活动。",
    "lifestyle": "伊莎贝拉晚上11点左右上床睡觉，早上6点左右醒来。",
    "daily_plan": "伊莎贝拉每天早上8点开放霍布斯咖啡馆，站在柜台前直到晚上8点，然后关闭咖啡馆。"
  },
  "spatial": {
    "address": {
      "living_area": ["the Ville", "伊莎贝拉的公寓", "主人房"]
    },
    "tree": {
      "the Ville": {
        "霍布斯咖啡馆": {
          "咖啡馆": [
            "冰箱",
            "咖啡馆顾客座位",
            "烹饪区",
            "厨房水槽",
            "咖啡馆柜台后面",
            "钢琴",
            "社区公告板"
          ]
        },
        "伊莎贝拉的公寓": {
          "主人房": [
            "床",
            "书桌",
            "冰箱",
            "壁橱",
            "架子"
          ]
        }
      }
    }
  }

```

这份配置可以按三层读：身份字段定义“她是谁”，空间字段定义“她知道哪些地方”，当前目标 currently 定义“她最近正在推进什么”。

| 字段 | 中文含义 | 进入模块 | 对行为的影响 |
| --- | --- | --- | --- |
| `name` | 角色姓名 name。 | `Agent.name`、提示词 prompt。 | 后续记忆、日程、对话和日志都用它标识这个角色。 |
| `portrait` | 头像资源 portrait。 | 前端资源路径。 | 让回放和界面能显示角色头像，不直接影响推理。 |
| `coord` | 初始坐标 coord。 | `Agent.__init__()`、世界地图 Maze。 | 决定角色进入小镇时站在哪个地图格子 tile 上。 |
| `currently` | 当前目标 currently。 | `Scratch.currently`、基础人物描述提示词 `base_desc.txt`。 | 直接影响当天日程、对话主题和可能传播的信息。 |
| `scratch` | 草稿状态 Scratch 的基础人物字段。 | 提示词组装器 Scratch。 | 提供年龄、性格、经历、生活习惯和典型日计划。 |
| `spatial.address` | 常用语义地址 semantic address。 | 空间记忆 Spatial。 | `living_area` 会被补成“睡觉”地址，用于睡眠和居住地点定位。 |
| `spatial.tree` | 空间树 spatial tree。 | 空间记忆 Spatial、行动地点选择。 | 决定角色知道哪些大区域 sector、场所 arena 和设施 object。 |

运行时，`agent.json` 不会直接变成完整智能体。项目先把 `data/config.json` 里的公共 agent 配置与角色自己的 `agent.json` 合并，再进入 `Game.__init__()` 创建角色配置，最后由 `Agent.__init__()` 拆给提示词组装器 Scratch、空间记忆 Spatial、日程 Schedule、关联记忆 Associate 和当前行动 Action。也就是说，`agent.json` 是角色定义入口，不是全部运行状态。

## 4.7 好的人物定义要能产生行为

人物定义不是越长越好。对生成式智能体来说，好的人物定义要能被后续系统使用。一个弱定义是：

```text
李明是一个善良的人。
```

这句话太空。它能影响语气，却很难影响日程、地点、关系和事件传播。一个更有用的定义是：

```text
李明是社区诊所医生，平时上午在诊所接待居民，下午会去公园散步。他关心老年人的健康问题，最近正在组织一次免费体检活动。
```

后者包含职业、地点、作息、关注议题和当前目标。系统可以据此生成行动：上午去诊所，下午去公园，遇到老人时谈体检活动，把活动信息传播给其他居民。可以用这张表判断人物定义是否可用：

| 检查项 | 好定义 | 弱定义 |
| --- | --- | --- |
| 能生成日程 | 有作息、职业、常去地点。 | 只有抽象性格。 |
| 能触发对话 | 有当前目标、社会关系、共同话题。 | 只有“友好”“开朗”这类形容词。 |
| 能影响记忆重要性 | 某些事件对角色身份有特殊意义。 | 所有事件看起来都差不多。 |
| 能支持社会传播 | 角色有理由告诉别人某件事。 | 角色没有明确动机。 |
| 能被实验验证 | 行为能在回放和日志中观察。 | 只停留在模型语气上。 |

## 4.8 本章小结

人物定义 Persona 是生成式智能体 Generative Agents 的第一层架构。它不负责保存后续经历，也不负责生成全部行为，但它给每个智能体提供了身份底座。没有这层底座，小镇里就只有一组共享大语言模型 LLM 能力的文本接口，而不是一群能持续生活的居民。

在项目里，人物定义 Persona 不是一句角色卡，而是从 `agent.json`、公共配置、提示词组装器 Scratch、空间记忆 Spatial、日程 Schedule、关联记忆 Associate 和地图状态一起进入运行系统。`base_desc.txt` 把姓名、年龄、性格、背景、生活习惯、日常计划和当前目标压成基础上下文，后续日程、对话、反思和重要性评分都会复用这层身份信息。

好的人物定义必须能产生行为。伊莎贝拉 Isabella Rodriguez 的派对、山姆 Sam Moore 的竞选、克劳斯 Klaus Mueller 和玛丽亚 Maria Lopez 的关系形成、约翰 John Lin 的日常连续性，都不是靠漂亮形容词成立，而是靠身份、习惯、空间、关系和当前目标共同约束出来。角色配置提供起点，运行过程中的记忆流 Memory Stream 则继续保存新经历。

下一章进入记忆流 Memory Stream。角色是谁已经清楚，接下来要看“这个角色经历过什么”，以及这些经历如何被保存为未来行为的材料。
