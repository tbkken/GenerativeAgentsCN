# 参数与输入边界

以下是准备在 UI 中输入的**教学候选配置**，不是已经创建的实验，也不是模型性能建议。实际保存值、模型连接和资源身份要填入验收记录。

## 时间与观察窗口

| 项目 | 设计值 | 原因与边界 |
| --- | --- | --- |
| 时区 | `Asia/Shanghai` | 与第二章预约资料一致 |
| 开始时间 | `2026-10-17T09:50:00+08:00` | 留出咨询与移动机会；不是保证按时完成的脚本 |
| 单步时间跨度 | 1 分钟 | 当前 `ga-cn-v1` 每分钟 4 格，便于观察多轮 MOVE |
| 请求步数 | 48 | Step1 为 09:50，Step48 为 10:37，观察更正后的到达与启动 |
| 随机种子 | 42（若界面使用该值则记录） | 不保证远端模型重跑逐字一致 |
| 检查点频率与保留 | 先保留界面支持值并记录 | 不手工删检查点或改 Run 文件制造恢复结果 |

手作新时间为 10:30—11:30。48 步的窗口不能验证完整活动结束；如果研究问题改为完整结束，应调整观察窗口、重新估算预算并创建独立实验。按同一起点至少需要覆盖 Step101 的 11:30，且“时间到了”还不能代替完成活动的事实。

## 人物与对象

- 四个 Agent，两个绑定根 Skill 的对象；两对象同样可能每 Step 调用模型，不能只按四个人估算费用。
- 人物视野候选为 8 格、注意力带宽为 8；对象视野候选为 6 格、注意力带宽为 8。数值用于限制局部信息与上下文，须在 UI 中保存并查看真实感知输出。
- 人物显示高度候选 1.8 格，行走图为 `4x4`。这是视觉参数，不改变逻辑移动速度。
- 公告栏与服务台交互距离候选为 1 格。用对象真实地址查询可达邻格，不猜测人工选点一定会成为终点。
- 四个出生 Arena 与已知空间见[地图说明](../map/README.md)。记录实际坐标及保存后的层级地址。

若 8 格内看不到目标，先依据已经配置的已知空间移动或请求帮助。增大 `world-perceive` 的 `radius_tiles` 请求不能突破人物视野硬上限；返回的 `vision_radius_tiles` 表示该硬上限。注意力也不能被“请给全图”绕过。

## 模型设置

在模型页显式选择可用聊天服务与具体模型 ID，按当前网关支持的协议配置。第二章使用 Responses，不代表第三章网关会自动使用同样的原生工具接口。连接测试、参数保存与仿真中实际调用应分别核对。

本材料不填写虚构服务地址或共享密钥，不推荐尚未实测的吞吐值。记录实际 `provider`、`base_url`、`model`、`context_window`、`max_tokens`、温度、思考设置、超时与重试；配置项是否适用以所选协议与模型为准。当前模型页面未逐项暴露全部底层字段，可核对界面及导出中的非秘密配置，无法确认的值记未知，不为寻找字段绕过界面改包。模型密钥由本机凭据或声明的环境变量提供，导出包不能携带真实密钥。

当前创建向导显示聊天与 Embedding 两项选择，但 Runtime 的记忆检索实现是 `file_lexical`。选中 Embedding 资源不能作为“已使用向量检索”的证据。自定义 Evaluator 也要区分资源可入包与当前执行链是否消费。

## 教学信息隔离

1. 共同 Brain 只组织行为，不预先告诉四个人手作 10:30 才可开始。
2. 服务台对象的资料包含既有预约 10:00—10:30；其回复须来自真实咨询请求。
3. 公告栏初态为旧安排，收到林岚基于真实查询提出的更新后，才提交新的 `state` 与正文。
4. 周宁与访客通过感知外观、INTERACT 或实际对话获得消息，随后更新各自记忆。
5. 作者知道完整故事不等于每个角色知道。案例总览、评分答案和验收表不能整份塞入每个角色的上下文。
