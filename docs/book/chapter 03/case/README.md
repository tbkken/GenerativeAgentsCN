# 青禾开放日：第三章贯穿案例

这是一套供读者通过 Studio 逐项建立的新案例作者材料。**文件与素材已准备，尚未上传为公共资源、创建实验、封存或运行。** 本目录没有 `.gaexp`、`.garun`，也没有虚构的运行结果。

## 要观察的问题

手作活动原消息是 10:00—11:00，服务台掌握手作室 10:00—10:30 的已有预约。林岚应通过真实咨询发现冲突，比较可行安排后请求公告栏更新；其他角色通过实际渠道获知调整，再更正记忆和行动。

候选调整是 10:30—11:30，是否采取该安排以及消息怎样传播，需要由实际执行产生。案例不固定谁在第几步说什么，不用成功故事替代运行证据。

| 活动 | 旧计划 | 指定场所 | 计划人数 |
| --- | --- | --- | --- |
| 阅读分享 | 10:00—11:00 | 阅读室 | 24 |
| 手作体验 | 10:00—11:00，需核对冲突 | 手作室 | 10 |
| 交流活动 | 10:00—10:45 | 交流室 | 16 |

日期统一为 2026-10-17，时区为 Asia/Shanghai。三项活动的时长和房间信息承接第二章；本章为了研究信息更正，特意从一份待核验的旧安排开始。第二章已经通过校验的排期不能作为所有角色的初始知识直接复制进来。

实际模拟 **4 名 Agent + 2 个绑定 Skill 的对象**。计划人数是背景资料，不能当作本实验参与者数量。候选运行从 09:50 开始、每步 1 分钟、48 步，观察到 Step48 的 10:37；只评价调整后的信息、到达和启动，不声称观察了全部活动结束。

## 准备顺序与材料

| 顺序 | 材料 | 在系统中怎样使用 |
| --- | --- | --- |
| 1 | [地图与空间](map/README.md) | 上传背景、定义四层语义、碰撞、对象与状态图 |

| 3 | [五份 Skill](skill/README.md) | 创建子技能与对象根技能，再创建共用 Brain，核对依赖 |

地图和人物素材来自[原创矢量绘制脚本](render_assets.py)，同时保留 SVG 和 PNG。脚本只准备图片，不写入系统资源、实验或 Run。5 份 Skill 也需要通过界面创建、保存、绑定和选入实验，不能把文件存在当成配置完成。

## 信息应放在哪里

| 内容 | 所在位置 | 为什么 |
| --- | --- | --- |
| 场所名称、对象用途、公开外观 | 地图语义与 `state` | 支持局部感知与定位 |
| 角色职责、旧消息与个人目标 | 各人物资料 | 形成不同出发点 |
| 感知、查询、比较、便签、动作的组织方式 | 共同 Brain 与子 Skill | 复用方法，不提前给答案 |
| 10:00—10:30 已有预约 | 服务台 Skill 私有资料 | 通过真实咨询提供依据 |
| 已接受的新公告正文和来源 | 公告栏自己的状态与记忆 | 先提交，再通过查询传达 |
| 完整研究问题、正确答案和评分条件 | 作者说明与验收表 | 用于观察，不作为每人全知上下文 |

服务台与公告栏使用 Runtime 提供的真实请求身份；来访者不能直接修改绑定对象的内部状态。教学中按组织者身份执行的业务判断仍是 SOP，不应夸大为一套新的安全认证系统。

## 本轮实际完成的范围

已完成正文、原创素材、五份 Skill 及其纯文档解析，查阅了当前实现，并通过浏览器只读核对公共资源分组与新建向导。没有进入其他实验做运行诊断，也没有启动本案例模型调用。详细依据与尚待项目见[第三章核查记录](../verification.md)。

后续构建需要先完成画面与空间检查，再组织行为。若实际操作发现系统 bug，按仓库约定停止该案例构建/运行验收，记录入口、步骤、身份、影响与证据；修复需针对该问题另行授权，不能换一个成功 Run 跳过问题。
