# 业务评价口径与空白评分表

本表由人工或独立分析流程根据真实证据填写，不是已经执行的系统 Evaluator。四个角色和观察窗口先固定，之后再比较不同实验。

## 固定定义

- 目标访客为陈晨和许安，分母固定为2；他们分别要到达阅读桌、手作台的实际可走活动位置。
- 公告更正时刻取公告栏 `state` / 正文更新的已提交 Step，而不是林岚提出请求的时刻。
- 许安“获知”的主要口径取其实际接收到已确认的新安排后，形成有来源的有效记忆或明确回应。服务台建议“可以考虑10:30”属于候选，不能直接算正式公告已传达。仅看到公告栏 `revised` 外观不足以确认知道具体时间。
- 双向对话要求同一有效 `conversation_id` 下，提问者和回应者均有实际 SPEAK，回复与问题相关；模型在一句话中扮演两人不计。
- 过时信息行动只计明确可判定依据的相关动作；不知道依据的行动单列“无法判断”。“等待到10:30”若有当前来源，是合理等待。
- 对象回复以真实有效请求ID统计，区分待处理、已提交待投递、已投递；观察末尾刚发出的请求另列，不凭窗口截止判永久遗漏。
- 成本合计同一 Run 全部 Attempt 的物理尝试、失败与重试，并另列各 Attempt 明细，再除以同一 Run 的成功结果数；零成功时单位值不可计算。续跑不能漏算恢复前已经发生的成本。

## 空白结果表

| 指标 | 分子 / 分母或时间点 | 结果 | 证据 | 状态 |
| --- | --- | --- | --- | --- |
| 两位访客到达率 | 待填 / 2 | 未测 | 待填 | 未执行 |
| 许安信息更新延迟 | Step_v − Step_u；每步1分钟 | 未测 | 待填 | 未执行 |
| 目标会话闭环率 | 已闭环 / 已发起 | 未测 | 待填 | 未执行 |
| 过时信息行动率 | 有证据的过时行动 / 可判定相关机会 | 未测 | 待填 | 未执行 |
| 行动依据可判定覆盖率 | 可判定相关机会 / 全部相关机会 | 未测 | 待填 | 未执行 |
| 对象回复完整性 | 有效请求 / 已回复 / 待投递 / 重复 | 未测 | 待填 | 未执行 |
| 总成本与单位成功成本 | 实际用量或费用 / 成功结果数 | 未测 | 待填 | 未执行 |

如果公告始终没有更正，公告传播延迟没有合法起点；应记“更正未发生”，不能填0。如果许安通过另一真实渠道，在公告提交前就已获知并核实最终安排，单列“更正前获知”，不纳入以公告为起点的非负延迟统计，也不把负值截成0。如果更正已发生但许安到窗口结束仍没有获知，记“截至10:37未观察到”，保留被截断的观察，不把它当作有限延迟。

## 一项单变量对照建议

保留基线，再在新的独立实验中只改变周宁“看到公告调整后主动询问附近访客是否已知”的 SOP。固定地图、初始资料、模型、视野和观察窗口，记录多个 Run 的结果及费用。若其他条件也发生变化，在报告中明示，不能把全部变化归因于通知方式。
