## 二、页面骨架

### 2.1 叙事主线

一句话主线：**技术不是按顺序堆上去的，是按缺口补上去的。**

四个递进问题贯穿全篇：

1. **缺什么**——输入、事实、执行、方法、验证五类缺口（2.14.1）
2. **怎么跑通**——API 路线：本地检查 → 普通文本 → 受约束候选 → 工具闭环 → 独立校验（2.14.2）
3. **怎么交付**——WorkBuddy 路线：任务合同 → 工作空间核对 → 失败与依赖处理（2.14.3）
4. **到哪为止**——交付清单、完成边界、微调蒸馏部署的时机、章末练习（2.14.4—2.14.6）

### 2.3 Hero 定位

Hero 页 6 张（25 页的 24%，落在 20–30% 区间）：

- **01 封面**——缺口 → 技术 → 路线 → 交付四节点竖链
- **05 缺口 → 技术主轴**——左「先找缺口」大块 + 右侧五条技术分支
- **10 完整命令链**——本地检查 → 普通文本 → 受约束候选 → 工具闭环与校验
- **16 工作空间核对**——左「工作空间文件」+ 右「变更 / 产物」双面板
- **19 三组交付物**——需求与来源 / 排期与校验 / 说明与记录
- **25 章末收束**——第二章 2.1—2.14 技术地图
