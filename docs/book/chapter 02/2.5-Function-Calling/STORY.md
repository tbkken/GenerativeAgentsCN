## 二、页面骨架

### 2.1 叙事主线

一句话主线：**模型只提出调用，真正查到记录、真正决定能不能用，都在应用这一侧。**

四个递进问题贯穿全篇：

1. **工具长什么样**——先把查询能力做小做清楚（2.5.1）
2. **一轮调用留下什么**——name、arguments、call_id 四条证据（2.5.2）
3. **回路怎么接**——先保留完整输出，再回填结果，然后继续请求（2.5.3）
4. **什么时候必须停**——参数错误、工具失败、无进展与预算（2.5.4–2.5.6）

### 2.3 Hero 定位

Hero 页 7 张（26 页的 27%，落在 20–30% 区间）：

- **01 封面**——左侧主张 + 右侧「模型请求 / 应用检查 / 工具执行 / 结果回传」四段竖排
- **05 六步往返序列**——谁发给谁、每一步交回什么，全篇结构主轴
- **10 call_id 关联链**——请求 → 执行 → 回传 → 下一轮，含一条证据旁路
- **15 回路代码**——`responses.create` 到 `function_call_output` 的完整衔接
- **20 执行前校验与无进展阻断**——三条分支汇入同一处记录
- **23 只读查询与写操作分界**——三行对照矩阵
- **26 结束页**——三枚反问收束
