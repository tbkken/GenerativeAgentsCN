## 二、页面骨架

### 2.1 叙事主线

一句话主线：**先证明环境跑得通，再证明请求真的发出去了，最后证明读进来的材料是对的。**

贯穿全篇的四个递进问题：

1. **我在和谁说话**——API、HTTP·JSON、SDK 三个层次，以及一次请求经过谁（2.1.1）
2. **拿什么比**——同一组材料与同一个校验器，是后面所有对照的前提（2.1.2）
3. **怎么跑起来**——独立虚拟环境、人工参考答案、最小 API 调用（2.1.3／2.1.4）
4. **出错查哪层、产品路线怎么对**——故障归属与 WorkBuddy 的取证方式（2.1.5／2.1.6）

### 2.3 Hero 定位

Hero 页 6 张（24 页的 25%，落在 20–30% 区间）：

- **01 封面**——请求生命周期轮廓，四处节点一条线
- **05 一次请求经过的层**——全篇结构主轴，四节点 + 三处故障归属
- **09 时间区间 [开始, 结束)**——本节唯一一张按时刻核对的图，全页焦点
- **15 最小调用的四个要素**——代码与要素标注合成的主视觉
- **20 两条路线，共用材料，分别取证**——分叉与汇合的双路线结构
- **24 结束页**——三步链收束
