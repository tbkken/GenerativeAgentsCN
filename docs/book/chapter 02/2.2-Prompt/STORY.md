## 二、页面骨架

### 2.1 叙事主线

一句话主线：**把愿望写成可以检查的任务，是把「说不清」变成「对得上」的唯一办法。**

六个递进问题贯穿全篇：

1. **写什么**——六个问题构成一份任务说明（2.2.1）
2. **怎么改**——从模糊提示逐步改进（2.2.2）
3. **怎么划边界**——用示例澄清边界（2.2.3）
4. **放哪里**——把指令与材料分别发送（2.2.4）
5. **凭什么相信**——先检查读到了什么（2.2.5）
6. **错了怎么查**——失败诊断与练习（2.2.6）

### 2.3 Hero 定位

Hero 页 7 张（24 页的 29%，落在 20–30% 区间）：

- **01 封面**——从「一句愿望」到「六项可检查条件」的整幅对照
- **04 六问任务合同**——本节的方法主轴，2×3 六格全页焦点
- **08 三种写法**——只改一处的对照设计，A／B／C 三列
- **12 两个示例**——半开区间判断规则，左右双例
- **15 instructions 与 input**——指令与材料分离的唯一结构图
- **22 三段诊断顺序**——先查源头，再查是否进入请求，最后才归因模型
- **24 结束页**——三个反问收束
