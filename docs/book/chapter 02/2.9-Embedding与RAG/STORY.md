## 二、页面骨架

### 2.1 叙事主线

一句话主线：**先把能作依据的材料找出来，再让模型组织答案；找得到、引得住、判得对是三件事。**

逐层推进的问题：

1. **凭什么找到相近内容**——Embedding 把文本变成向量，方向相近就排前面（2.9.1）
2. **相似度说明了什么、又没说明什么**——余弦相似度只比较方向，不等于答案正确（2.9.1）
3. **切到多大才讲得清**——切片要保留能解释证据的最小上下文（2.9.2）
4. **每一步都看得见**——读取、切片、向量、排序、取前 k、交给模型（2.9.3）
5. **不自己实现行不行**——托管 File Search 是另一条路线（2.9.4）
6. **产品里怎么做同一件事**——WorkBuddy 用文件搜索完成取证任务（2.9.5）
7. **怎么证明它真的有用**——检索命中、引用支持、业务通过分别测量（2.9.6）

### 2.3 Hero 定位

Hero 页 7 张（25 页的 28%，落在 20–30% 区间）：

- **01 封面**——从问题到依据再落到答案的通路
- **04 语义相近**——本节唯一一张「字面不同、方向相近」的向量示意
- **08 RAG 通路**——全篇结构主轴，五节点链路 + 人工复核旁路
- **12 小型检索器的六步**——读取到回答的可见过程
- **16 托管路线的五步准备**——上传到关联的完整前置流程
- **23 三个环节各测各的**——三列指标并列，全篇唯一的度量图
- **25 结束页**——三个追问收束
