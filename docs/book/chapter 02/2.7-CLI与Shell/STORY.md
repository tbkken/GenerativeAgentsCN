## 二、页面骨架

### 2.1 叙事主线

一句话主线：**规则一旦写明确，就该交给程序逐条判定，而不是交给模型猜测。**

六个递进问题贯穿全篇：

1. **命令由什么组成**——参数、工作目录与环境、标准输出、标准错误、退出码（2.7.1）
2. **为什么时间适合定性判断**——半开区间与重叠条件（2.7.2）
3. **谁先跑**——先手工建立可信基线，再让模型调用（2.7.3）
4. **怎样只交出可控的一小步**——白名单 + `shell=False` 的受控函数（2.7.4）
5. **命令在哪里跑**——托管容器与本地 Shell 两种位置（2.7.5）
6. **怎样取证**——在教学工作区执行并保留失败报告（2.7.6 · 2.7.7）

### 2.3 Hero 定位

Hero 页 7 张（24 页的 29%，落在 20–30% 区间）：

- **01 封面**——命令行三行命令重绘 + 一枚橙色退出码标记
- **04 一条命令的六个部分**——进程合同全景图（三类输入 → 子进程 → 三路结果）
- **08 半开区间时间轴**——本节唯一一张「按分钟刻度核对」的图，全页焦点
- **12 两个具体错误**——左「重叠」／右「超容量」双列对照
- **15 受控包装器**——四步链路，说明模型不需要拼接任意命令的能力
- **19 托管与本地两种位置**——双列并列，强调两者不是前后阶段
- **24 结束页**——三句收束
