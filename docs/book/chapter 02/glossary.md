# 第二章术语速查

| 术语 | 在本章中的含义 | 容易混淆的边界 |
| --- | --- | --- |
| API | 应用之间约定的调用接口 | 有接口不代表当前账户有权限 |
| SDK | 帮助程序调用服务的库 | 仍会发生网络请求与错误 |
| Prompt | 提供给模型的任务描述、要求与示例 | 不能替代程序权限与业务校验 |
| 上下文工程 | 选择、组织并更新模型当次需要的信息 | 大上下文不等于关键事实一定被使用 |
| JSON Schema | 描述数据结构、字段及类型约束 | 符合结构不保证内容真实或方案可行 |
| Structured Outputs | 用受支持的 Schema 约束模型输出结构 | 仍要处理拒绝、中断与业务错误 |
| Function Calling | 模型提出函数名与参数，由应用执行并返回 | 提出请求不等于动作已经执行 |
| `call_id` | 将一个工具请求与相应结果关联的标识 | 不能自行造一个 ID 冒充对应结果 |
| MCP | 宿主与外部能力之间的连接协议 | 协议支持范围与宿主实际能力需要分别确认 |
| Host / Client / Server | 宿主应用、连接组件、能力提供者 | Server 可以是本地进程 |
| stdio | 通过标准输入和输出交换消息 | 协议 stdout 不能混入普通调试日志 |
| CLI | 通过命令、参数、输入输出与退出码使用程序 | CLI 不是一种模型，也不必包含 Shell |
| Shell | 解释和执行命令的运行环境 | 本地与托管执行的文件、权限不同 |
| Skill | 可复用的操作方法及相关资料、脚本 | 安装不代表一定触发，也不授予权限 |
| 渐进读取 | 先发现相关方法，再按需加载详细内容 | 不应一次把所有技能材料塞入上下文 |
| Embedding | 将文本等内容表示成可比较的数值向量 | 相似不等于正确、最新或获得授权 |
| RAG | 检索相关材料后辅助模型生成 | 不修改模型权重，引用仍需核对 |
| Agent | 能围绕目标组织观察、决策、工具执行与反馈的应用 | 自主选择下一步仍需执行和停止边界 |
| ReAct | 让推理与行动交替推进的一种组织方式 | 可见工具过程不等于完整内部思维链 |
| 记忆 | 保存并在后续任务取用的信息 | 当次任务事实、偏好与会话历史作用不同 |
| 工作流 | 预先组织步骤、依赖、分支与交接 | 依赖前一步结果的步骤不能任意并行 |
| 多 Agent | 多个有任务与上下文边界的角色协作 | 角色数量不等于准确率 |
| 幂等 | 重复请求不会产生重复的业务效果 | 需要执行服务支持，提示词无法单独实现 |
| 逻辑调用 / 物理尝试 | 应用的一次请求意图 / 实际网络尝试 | SDK 重试可能让两者数量不同 |
| 提示缓存 | 复用重复输入前缀的处理工作 | 不是长期记忆，不保证每次命中 |
| 微调 | 通过训练样本调整模型对任务的适应 | 不替代实时外部事实查询 |
| 可观测性 | 通过记录推断应用的执行过程与问题位置 | 依赖真实埋点和数据完整性，不是模型内部思维读取器 |
| Langfuse | 组织大模型应用调用链、用量和评价的工具 | 不替代本地业务校验或本系统的StepResult |
| Trace / Observation / Session | 一次调用链／其中一项操作／多次相关调用的分组 | 根子关系是观测结构；不会自动证明所有子进程都已被记录 |
| Generation | 面向模型调用的Observation类型 | 一条generation不必然等于一次底层HTTP尝试 |
| Score | 按明确规则给记录附加的判断值 | 正常结束、质量合格和最终业务完成是不同判断 |
| 埋点与上下文传播 | 记录操作并把它关联到正确的调用链 | 异步、线程和进程边界需要按实际SDK支持处理 |
