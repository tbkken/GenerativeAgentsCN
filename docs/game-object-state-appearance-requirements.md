# Game Object 状态外观：产品与实现需求

日期：2026-09-06  
状态：待实现需求，非功能已完成说明；交互已按用户确认简化为内联“增加状态”  
首个验收案例：`docs/images/desk-tidying-v1`，许知行整理书桌  
范围：管理台作者配置 → 实验封存 → Run → 状态事实 → 图片回放完整链路

## 1. 要解决的问题

用户已经可以为地图中的 Game Object 选择素材，也有通用对象状态修改动作。但角色把书桌状态改为“已整理”之后，地图图片不会自动变成整理后的样子。

本需求在现有“显示素材”下面增加“＋ 增加状态”。用户只填写一个自定义状态名并选择素材，不选择状态字段、不编写 JSON、不先打开配置弹窗。未添加状态时直接使用当前显示素材。运行和回放根据系统已提交的真实状态选择素材。

示例：

| 书桌状态字段 `state` 的值 | 显示素材 |
| --- | --- |
| `scattered` | 散放材料 |
| `stacked` | 码齐材料 |

用户不编写 JavaScript，不连接事件处理器，也不学习流程编排。Brain 通过通用 `world-act` 改变对象状态；系统不增加“整理书桌”业务代码。

## 2. 核心决定

1. 入口名称为“状态外观”，不是“响应事件”。事件记录变化，状态决定当前画面；刷新、回放跳转和恢复不依赖再次触发事件。
2. 第一版仅针对 L4 Game Object。World、Sector、Arena 的素材选择维持现有能力，不新增其动态状态机制。
3. 用户仅配置多条“状态名 → 素材”。内部统一读取对象的 `state` 字段，不向普通作者暴露字段选择。现有显示素材就是默认外观。
4. 第一版仅精确匹配顶层字符串字段。不支持表达式、嵌套路径、复合条件、正则、范围、优先级或脚本。
5. 只切换视觉，不修改对象身份、空间地址、坐标、边界、碰撞、路径、交互范围、可交互条件或 Skill 绑定。
6. 编辑器预览只是本地预览，不能写入 initial_state 或运行状态，不能产出世界事件。
7. 所有候选素材及其递归依赖必须随实验一次性导入，Run 再持有完整副本。未命中的状态素材也不能漏打包。
8. 不新增 Revision、发布、跟随最新、引用锁或跨资源运行时查询。既有可变公共作者资源原则不变。

## 4. 管理台交互

### 4.1 默认就是现有操作

选中 Game Object 后，在当前显示素材下面增加一个轻量入口：

```text
显示素材  [散放材料 ▾]
＋ 增加状态
```

用户不点击增加状态，就完全沿用现有素材选择、保存和显示方式。不要求创建“默认”状态、不要求填写初始状态、不显示缺失状态警告、不增加保存步骤。只选择一张显示素材即可完成配置。

### 4.2 有需要才增加状态

点击“＋ 增加状态”，直接在检查器内新增一行：

```text
显示素材  [散放材料 ▾]                    默认显示

状态名             显示素材                 操作
[已整理         ]  [码齐材料 ▾]             删除

＋ 增加状态
```

每行只包含两个输入：用户自定义的状态名和素材选择器。状态名允许中文，例如“已整理”“打开”“关闭”；它本身就是 Agent 使用的状态值，不自动转换成英文代码。状态字段固定为内部的 `state`，用户不必理解或选择这个字段。

复用现有合法静态素材选择能力，包括已支持的静态切片和静态画布组合；显示缩略图和素材名称，不新增上传库。动态精灵动画不属于第一版支持范围，应明确标记，不能静默取任意帧。

可提供非必需的“预览”操作用于观察效果；不以弹窗、预览、初始状态选择作为保存前置。预览不改变对象状态。

### 4.3 保存、删除与只读

- 状态行跟随现有地图保存机制持久化，不再增加“应用状态配置”的独立提交步骤。
- 尚未保存的变更使用地图现有未保存提示。保存失败保留输入；重新打开以服务端保存内容为准。
- 新增行、修改或删除行进入现有撤销/重做机制。删除所有状态行后恢复未配置时的界面。
- 删除状态行不删除素材、不修改当前运行、不强行修改对象 initial_state。若初始状态原来引用已删除名称，按默认素材显示。
- 快速切换对象时，输入、预览及异步加载不得串到另一对象。
- 只读实验/Run 可展开查看，不允许修改。
- 小屏及窄检查器保证字段和按钮可达。禁止系统级 alert/confirm/prompt。

### 4.4 初始状态与校验

新建配置从“显示素材”对应的默认外观开始；增加“已整理”这一行不会自动让书桌变成已整理。只读展示既有 initial_state 可放在高级信息中，不成为普通用户必填项。

内部 `state` 缺失或为空字符串时表示使用默认外观；运行需要恢复默认时，可通过合法 `state_patch: {"state": ""}` 进行。空字符串不允许作为用户新增的命名状态。其他非匹配值也按默认素材回退。用户不必为了回到初始状态再复制一张默认素材。

最少校验：状态名非空、唯一，素材已选择且有效。新增空行尚未完成时在该行提示；用户可以删除该行继续保存，不影响未使用本功能的对象。

示例提示：

- “状态名‘已整理’重复，请保留一条。”
- “请选择‘已整理’对应的素材。”
- “素材‘码齐材料’已不可用，请重新选择。”
- “两种素材宽高比不同，切换时内容大小可能变化。”

字段缺失、空值或没有匹配项是正常默认分支，不因为用户未配置状态而制造警告。只有用户主动查看高级状态信息时，可以解释当前回退原因。

## 5. 状态匹配合同

输入：当前 Game Object 状态、该对象状态外观配置、默认素材。输出：一个确定的有效素材描述及匹配状态，不能产生任何世界修改。

逻辑：

1. 未配置状态外观，使用现有默认外观。
2. 获取对象顶层 `state` 字段的原始值。
3. 仅当值为字符串，且与某一配置值完全相等时，使用对应素材。
4. 其他情况使用默认素材。

大小写敏感，不进行 trim、大小写转换、下划线/连字符替换、字符串包含匹配、数字布尔转字符串。作者输入状态名时可去掉首尾空白，但界面必须显示保存后的准确名称。运行状态不做隐式转换。

推荐长度上限：状态名 128 字符，映射 32 条。具体限制统一纳入 schema 和 UI。首版不接受空状态名、重复状态名或无素材映射。

状态映射不是允许状态枚举，也不是权限规则。未知值仍是可能合法的世界状态，只是视觉采用默认素材。不能以缺少图片为由拒绝合法状态提交。

缺少默认素材时：保留系统原有的无素材显示行为；用户启用状态外观则必须明确选择一个合法默认静态素材，确保回退可用。

## 6. 数据结构建议

下面是新增节点字段的语义示例，最终字段名称可调整，但不能丢失约束或形成多套相冲突的事实源。

```json
{
  "id": "desk-tidying-v1-desk",
  "kind": "GAME_OBJECT",
  "material_slice_id": "desk-default-slice",
  "initial_state": {},
  "state_appearance": {
    "cases": [
      {"value": "已整理", "material": {"kind": "RECIPE", "id": "materials-stacked-canvas"}}
    ]
  }
}
```

- 默认素材仍由现有字段负责，不在 state_appearance 中重复保存另一份默认值。
- 作者侧素材引用须是可校验的明确联合类型，禁止同时指定切片与画布，禁止仅凭素材名称寻找。
- 若复用/改造 SpatialAppearance.state_variants，必须收敛为一个权威合同。节点、素材默认值、运行投影不能各保留一套相互覆盖但优先级不明的映射。
- 首版状态外观规则归地图节点，不增加素材级映射与节点级覆盖的双重继承。
- 公共 Studio UUID 可以用于作者编辑引用；实验内必须转换为包内稳定 key 或物理资源路径，不能留下运行期回查 Studio 的条件。
- 对象 object_key 必须贯穿动作、状态事件、包内节点和回放显示实例。不得按显示名称合并不同书桌。
- 不把素材 URL、作者资源 ID 或纹理 key 写入 world-act 的 state_patch。对象状态仍只描述世界语义。

## 7. 素材显示规则

### 7.1 放置与图层

状态切换沿用对象既有的放置范围、原点、旋转、缩放和同层排序；各状态不提供单独的位移、碰撞或深度覆盖。切换后对象保持同一显示实例，或以等价方式替换其视觉子项，不应重复叠加旧图片。

遵守 L1 World → L2 Sector → L3 Arena → L4 Game Object。背景静态合成不能提前烘焙会变化的 L4 图片，否则换图后会留下旧物品。

同一对象的纹理切换采用统一确定的放置算法；与现有默认素材绘制保持一致。如果现有策略会拉伸到节点 bounds，则全部状态也使用该策略；不为其中某一状态偷偷自动裁透明边。不同图像大小不会影响对象世界坐标。

### 7.2 透明度和尺寸

- PNG alpha 必须保留，不能出现棋盘背景、黑底或旧图残影。
- 相同尺寸、锚点和物品像素尺度的状态图，切换时不应跳动或缩放。
- 图片宽高比不一致只作作者警告，不自动修改原图。
- 第一版不自动抠图、修正素材比例或推测物品轮廓，也不根据 alpha 改碰撞。

### 7.3 单对象替换边界

本功能替换的是该对象的整份所选视觉，不自动理解“桌子不变，只换纸张”。书桌案例可选：

1. 每种状态选一份完整桌面组合：空书桌＋对应材料，组合在现有静态画布中完成；
2. 空书桌与材料作为 Arena 下两个同级 Game Object，仅材料对象配置状态外观，先验证同级图层排序与交互站位。

不能把书本挂成 Game Object 的子 Game Object，增加第五层。若管理台已有画布组合不能完成上述第一种方式，应登记独立缺口，不默认为状态外观已同时实现可编辑多层图元系统。

## 8. Runtime 与事实边界

继续使用现有通用动作：

```json
{
  "action_type": "SET_OBJECT_STATE",
  "object_key": "运行上下文中实际返回的对象 key",
  "state_patch": {"state": "已整理"},
  "description": "将讲义和笔记本整理成一摞。"
}
```

这只是参数说明，不允许模型伪造对象身份或绕过附近对象检查。开发时核对实际公开 schema，不为示例随意新增参数。

动作经 World Commit 后才改变图片。模型生成说明、发起工具调用、工具参数预校验通过、被动 Skill 返回文字，均不能提前驱动回放。

每个 Agent 每步最多一个世界动作。ACT 整理和 SET_OBJECT_STATE 是不同动作；若案例需要两者，分步提交。也可将状态修改作为该步唯一动作并携带合理语义描述，不能为了视觉新增自动第二次提交。

GAME_OBJECT_STATE_CHANGED 继续携带完整 before/after、object_key、操作者等结构化事实及 SPO。字段无变化、或修改与外观无关的字段时，不触发不必要的纹理重载。动作是否形成 no-op 事实按既有世界合同处理，不由渲染器决定。

不得扩大现有权限、修改所有状态的合法性规则或把角色职业作为状态修改授权。当前状态修改校验是否充分属于独立审查事项，本需求不宣称已解决多人竞争与业务权限。

### 8.1 Agent 如何知道可以使用哪些状态名

作者在界面创建的状态名必须作为对象可用外观状态元数据随包保存，并在 Agent 合法感知该对象时，通过现有 `world-perceive` 对象描述紧凑返回，例如当前状态和 `available_visual_states: ["已整理"]`，并说明空字符串可恢复默认。名称必须原样传递，不要求作者再去 Skill 抄一遍。

只在该对象被合法感知的范围内提供，不把整张地图全部对象及状态名注入所有角色；仍遵循视野、带宽及稳定对象身份约束。模型不需要知道素材路径或纹理 URL。

Brain 决定是否改变状态，`world-act` 接收目标对象和准确状态值，系统校验并提交，回放负责选图。MCP 不从“我收拾好了”这类任意自然语言自动猜测状态名。可用外观状态不是业务权限白名单，本需求不把其他状态字段或未知值的合法性规则收窄。

验收补充：用户只在地图中增加“已整理”一行，不向 Brain 重复抄写状态枚举，Agent 在合法观察对象后能获得该名字并提交状态变化。没有配置状态外观的对象不产生额外状态配置要求。

## 9. 实验包与 Run 的自包含性

选入地图时，必须复制：

- 默认素材、所有状态素材；
- 每张切片的源图片、裁剪与帧信息；
- 画布/recipe 的全部递归引用素材及渲染参数；
- 状态外观规则、对象初始状态、空间节点与稳定身份。

包校验遍历所有分支，不能只收集 initial_state 当前命中的一项。缺少未命中素材也必须在封存前报出。缺失、非法路径、循环依赖或不支持的动态资源均应定位到对象、状态值和资源。

完整性清单与 Bundle Hash 覆盖映射、字段、值、素材内容和渲染参数。改状态映射会改变行为内容哈希。

Run 再复制完整实验。运行、恢复和回放只读取 Run 内嵌内容；公共素材之后改名、修改、归档或删除不影响已导入实验和 Run。不得因已有实验使用而禁止公共素材修改/删除。

Runtime 和 Replay 不引入数据库依赖；Web 只提供包内素材的可访问地址适配。素材 URL 不能被当成持久协议身份。

## 10. 回放、刷新与异步安全

- 初次打开：先从包内初始状态及目标 Step 的已提交事实还原状态，再绘制对应外观。不能默认所有对象先展示初始图再永远不更新。
- 正向播放：本步事实提交后，在本步显示最终对象状态。
- 倒退/任意跳转：从可靠边界重新归约到目标 Step；不能在当前累计对象上只追加新 patch。
- 同一步多个角色修改同一对象：按 StepResult 的权威提交顺序归约，最终画面与对象最终状态一致；前端不按请求返回先后决定胜负。
- 查看旧 Step 时后台 Run 继续推进：不得把最新对象状态覆盖当前回放步骤。
- 暂停恢复：保持对象 key、状态和配置，重建视觉后与恢复边界一致，不重放状态修改副作用。
- 切换 Run/实验/对象：清理或隔离上一作用域的显示实例、纹理引用和加载回调；延迟请求不得覆盖新选择。

纹理缓存建议使用 Run 包身份/内容哈希与包内资源 key，而非对象显示名称。相同纹理可复用；不每帧重新下载、不为每次状态变化永久保留一份副本。

## 11. 失败与诊断

区分以下两类情况：

1. 无匹配状态：按设计使用默认素材，是正常分支；不每步生成错误日志。
2. 已匹配但素材损坏或加载失败：显示默认素材并产生一次可定位的外观加载诊断；默认素材也失败则显示中性占位与说明，不静默空白。

错误诊断至少包含 Run、对象 key、目标 Step、状态字段和值、包内素材路径和错误原因，不记录密钥。相同问题去重，提供手动重试或页面重载后的重新加载机会。

纯显示错误不能改写 Run 已提交状态或将本来完成的仿真改为失败。缺失依赖导致实验包本身不完整时，依既有包校验合同阻止运行或打开，不能通过视觉回退掩盖完整性错误。

配置保存失败时保留用户输入，显示失败原因，不能提示已保存。删除状态行或移除映射不得删除相应素材文件。

- Agent：许知行，本案例独立创建。
- Map：知行自习室，本案例独立创建。
- Brain/Skill：desk-tidying-v1 专属配置，不引用其他实验大脑。
- 状态：默认 → 已整理；无需作者填写初始状态。
- 显示素材：散放外观；点击增加状态，填写“已整理”并选择码齐外观。
- 运行：短 Run，建议 4–6 步，不需要全天作息、移动、社交或反思。

自然语言 Brain 先观察并确认对象，再执行整理与合法状态提交，随后检查。不要按固定 Step 在前端切图，不需要新增被动 Skill 直接修改状态。

现有两张材料首版存在尺度差异；实施验收应使用同尺寸、同锚点、同物品尺度的可靠测试素材，避免把美术不一致误判为渲染跳动。最终书中素材再单独完成校准。
