## 2. 必须解决的阻塞

### B1：客观后果没有合法执行入口

现有 Scheduler 对每名 Agent 依次 think、commit，然后冻结 StepResult（`start.py:174—210`）。`modules/game.py:317` 有六类通用动作及其事实提交，没有路径后的交通规则裁决链。`ga_runtime/package.py:94` 读取 evaluation 主要用于 results 配置；文件中存在 evaluators 列表不证明任意评估器会在线执行。

离线统计可以从轨迹判断一次违规，但无法让未执行的处罚产生当次出行成本、再进入后续计划与记忆。因此只补一个结束后报告不足以满足原需求。

需要讨论“包内客观规则如何经内核验证产生同一步派生事实”的通用扩展边界：交通规则应属于实验，内核只负责输入、权限、确定性、提交及恢复。不能硬编码交通业务流水线；不能让 Brain 或被动 Skill 自行写 Run 文件冒充世界事实；不能让骑行者再提交第二次动作来给自己处罚。方案尚未实施，相关权限及提交边界需用户确认。

### B2：客观状态会泄漏成认知

`runtime/capabilities.py:499` 直接把 `object_state` 放进 game_objects，附近可交互对象还会再次复制其完整状态。若摄像头状态包含内部运行开关、抓拍列表或处罚队列，骑行者进入半径就可能读到全部字段。把“不要偷看”写进 Skill 无法修复这个边界。

`modules/maze.py:510` 的事件感知按附近 Tile 枚举，没有执法事实的 audience/知情过滤；现有指纹按 SPO、描述、地址去重，缺少完整独立事实身份。重复发生但文本相同的交通事件存在被合并风险，与仓库对 Event 完整身份的要求冲突。

需要内核观察投影明确区分可见外观、可见标志、内部设备状态、私有通知和研究者事实。已有 external_observations 仅证明请求者被动反馈链可用，不代表后台通知的延迟、收件人、去重和恢复全部完成。

### B3：运动与时间粒度不符合完整交通要求

`config/schema.py:102` 的 stride_minutes 为整数且最小 1；`runtime/iteration.py` 同样以分钟为步长。`start.py:240` 使用统一的每分钟移动格数，默认 4；`world-act` schema 没有速度、加速度、等待秒数、车道路径或逐段时间。

当前 MOVE 是按预算消费静态路径，不是电动自行车动力学；邻近 Agent 感知没有速度字段。同一步按 Agent 顺序执行，也不能直接宣称为所有车辆同时推进的交通模型。一分钟内高速接近、缺口交织与减速等现象可能被跳过。

完整要求需细化时间、对象运动、路径占用与冲突语义。若用户接受分钟级行为研究，可另立明确限制的版本；本稿没有自动选择这种缩减，更没有建议通过贴“骑行”标签把步行预算当成真实骑行速度。

### B4：合法路径、物理碰撞和动态通行不能混用

`ga_protocol/navigation.py:11` 是四邻域 BFS；Runtime 调用静态碰撞寻路，没有按骑行模式、法律许可、意图限定路线。去同一目标时，模型选择“合法绕行”可能仍被寻路带过缺口。

静态护栏可建真实碰撞、缺口可留空，但 `SET_OBJECT_STATE` 改一个 open 字段不会自动更新碰撞。移动中的其他 Agent 也没有在这条寻路链里形成时间占用约束。动态堵塞、缺口被占用、真实减速等待不能只靠语义描述保证。

需要路线选择忠实于 Agent 意图的通用能力，并分别处理硬物理约束与可以违反的规范。静态不同政策地图可以分别封存，运行中自动改变通路则需要另外的提交机制。

### B5：对象状态缺少研究设施保护

`runtime/capabilities.py:722` 的状态修改主要验证附近可用对象与非空 patch；`modules/game_object_interaction.py:201` 浅合并任意状态字段。人物职业或角色描述不会自动形成字段/迁移权限。

如果摄像头被配置为可交互对象，当前不能把“骑行者无权关闭摄像头或清空罚单”当成已由内核保证。需要通用权限与状态校验，实验内定义允许操作；不能把设备维护角色写死到内核。

### B6：研究记录尚未闭合

当前已有动作、感知调用、记忆检索及模型过程审计，但无自动将所有需求 context、机会事件段、实际路径、处罚通知和后续计划按稳定身份联结的成品输出。`runtime/brain.py:345` 的审计记录是调用与动作记录，不等于 12 节点完整研究表。

最小补齐应以已有 StepResult 与 Trace 的关联导出为基础；新增客观后果需先有真实事实。不要强迫每个 Skill 输出一套回放 JSON，也不要把重要研究证据只藏在会被截断的模型文本中。

## 4. 可直接复用的基础

自然语言 Brain 编排、精确 MCP 工具名、按需子 Skill；只读确定性计算脚本；基础四层语义与静态碰撞；Agent 私有 memory-stream-search/append/supersede/invalidate；单步一个 world-act；被动观察下一轮只投给请求者；Run 内嵌实验与文件化事实。

其中计划可以作为 Agent 私有有效记忆保存，并在更新时 supersede 旧计划。这符合记忆能力边界，但必须明确 UI 原 Schedule 不会因此自动同步，也不代表强类型计划存储 API 已存在。所有封存资源都使用包内副本，不建立来源升级或 Revision 关系。
