## 2. 完整实验放行需要的证据

| 验收点 | 必须可复核的结果 |
| --- | --- |
| 人物与任务输入 | 当前 Brain 看到本人预设、截止时间、有效计划；不会用旧计划覆盖新计划 |
| 物理路线与行为意图 | 合法绕行路径不误入机动车道；经缺口路线物理可执行；护栏不可穿越 |
| 交通运动 | 速度与时间单位明确；减速改变真实轨迹/耗时；邻车快速接近和占用有真实执行状态 |
| 可见性 | 视野外、遮挡后的摄像头不出现；设备可见不等于内部抓拍结果可见 |
| 客观违规 | 依据全段 executed_path 与规则；不是根据 action description 或模型自报 |
| 抓拍与处罚 | 设备覆盖和状态参与判定，抓拍与处罚分开，有可追踪规则与事实 |
| 知情隔离 | 后台已抓拍但未通知时，本人 context/memory 不含该结果；通知只投给正确收件人 |
| 反馈 | 已知结果影响下一轮 ETA、压力、计划或记忆；不是只在结束报告中统计 |
| 幂等与完整身份 | 同一违规段不重复开罚；重新进入形成新事件；同文同地不同时间不误合并 |
| 恢复 | 在抓拍、通知、处罚边界暂停续跑，与不中断运行具有一致事实，不重复抽签或投递 |
| 研究记录 | 每项条件、感知、选择、实际后果和记忆引用能回溯到同一 Run/Agent/Step/事件 |
| 独立包 | 移走 Studio 数据库与公共资源后，包仍能运行/恢复/回放，不读取来源资源 |

这些是待完成的验收要求，不是已跑通的测试清单。最后一步不应发起需要下一轮才有观察的新查询；正式 Run 需要留出反馈消费窗口，未收到的通知标明尚未送达。

## 3. 需要先确认的设计决策

建议保持原始研究目标，并先补齐通用能力，再制作正式素材和实验包。需要确认的首要事项是：**按完整交通闭环推进，还是明确接受分钟级的行为选择研究。** 后者会缩减快速接近、真实减速、遮挡等研究能力，不能沿用原需求名称却不披露减少的内容。

完整版本还需要具体定义：

1. 背景交通的运动精度，以及 PNG 中事故/冲突是否属于首期验收。
2. 客观规则输入、抓拍确定性/随机性、处罚与通知延迟、是否增加旅行时间。三份需求未给定这些数值。
3. 首期做单次缺口选择，还是同一 Run 内多次出行并观察记忆积累。若只做单次选择，无法充分验证长期学习。
4. 固定条件、人物、重复次数与模型预算。先做可审计的条件设计，再按实测吞吐确定规模。

其中第一项范围决定会影响地图尺度、时钟合同和素材制作，适合先讨论。其余数值可在方向确定后逐一固定，不需要现在将所有细节一次性决定。
