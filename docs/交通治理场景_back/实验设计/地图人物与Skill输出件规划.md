# 地图、人物与 Skill 输出件规划

参照 `docs/images/creek-university-v2` 的交付粒度组织，但本阶段只形成设计底稿。下列地图范围、人物和参数是建议，不是三份原始资料已经给定的数值，也不是已经通过导入的配置。

## 1. 地图设计

World：逸仙小镇交通治理试验街段。首期只画可形成选择与反馈的局部道路，不制作完整小镇。

| 层级 | 建议内容 | 作用 |
| --- | --- | --- |
| L1 World | 整体道路环境、坐标尺度、实验使用的基本语义 | 最底层渲染；不能放隐藏设备信息或人物秘密 |
| L2 Sector | 西侧接近区、缺口决策区、东侧离开区、合法绕行区 | 描述空间区域，不承担自动流程 |
| L3 Arena | 非机动车道段、机动车道段、合法绕行通道、安全等待区、起终点区 | 可重复命名但必须具有不同稳定 ID |
| L4 Game Object | 护栏段、缺口锚点、摄像头、提示牌、道路障碍物、目的地入口 | 只有这些节点可按需绑定被动 Skill |

初步可用 96×48 Tile、32px/Tile 作为画布规划，实际米/Tile 和模拟时钟必须在交通运动方案确定后校准。不能从像素大小自动推出真实车速。建议纵向分出机动车道、护栏带、非机动车道和绕行带；护栏中部为研究缺口，合法通路在远端明确连接。

这是一份布局意向，不是已可录入的坐标表。正式素材输出需做到：

1. 四层节点范围与图像、车道边界、起终点逐一对齐，所有可行路线连通。
2. 护栏为阻挡，缺口及真实路口可通行；法律禁止进入的车道不因违法属性自动变成墙。
3. 合法路线与经缺口路线都能执行，并有可测距离差；检测全路径是否意外抄近路。
4. 摄像头安装点、设备可见范围、遮挡、抓拍覆盖范围分开表示；不能用一个半径替代全部语义。
5. 为停止观察、等待、接近缺口安排真实可用位置，保证关注对象不会被其他大量装饰占满 attention_bandwidth。
6. 相同位置的反复违规使用不同事实身份；固定 node_id 与动态 event_id 分开。

建议地图输出：总体效果图、四层叠加核对图、原始分层素材、world/sector/arena/object 节点清单、静态碰撞与连通检查、各候选路线长度、设备观察/抓拍范围说明、人物出生点与已知地址。不要把一张漂亮底图当成可运行地图。

## 2. 人物与实验内配置

公共 Agent 只存可复用人物信息和资源；坐标、任务截止时间、已知路线、实验初始经验在本次实验内明确设置，物理导入后与公共人物断开。

建议人物底稿包含：

- 身份与日常出行方式：电动自行车骑行者，职业为人物条件之一。
- 自然语言性格：守法倾向、风险偏好、时间敏感程度，有权衡空间，不写必选答案。
- 本次任务：目的地、原定到达时间、迟到后果、是否允许修改目标。deadline 是外部约束时，不能通过随意延后 deadline 把迟到消掉。
- 已知信息：基本规则、本人熟悉的目的地与合法路线；摄像头实时状态、未来堵塞及后台处罚不在初始知识里。
- 初始经验：无特殊经历或明确的预置经验条件；经验真伪与主观推测清晰标注。
- 观察参数：vision_radius 和 attention_bandwidth，所有对照保持一致，除非专门研究感知差异。

人物交付按 `agents/人物名/` 分目录，包含可读人设、当前 Studio schema 的 definition、头像及骑行纹理。sprite 布局按当前支持的 4x3/4x4 选择并核对方向；本阶段没有生成图片，不用普通步行图暗示已经实现骑行动力学。

goals/tags 和专用数值字段的运行输入覆盖尚需确认。不要为绕过字段缺失把整个人物和实验秘密塞进 currently 或 World 语义。

## 3. Brain 与子 Skill 组合

建议一个根 Brain：`traffic-gap-rider-brain`。子 Skill 为按需能力，不把整个 17 节点图逐格转成固定调用链。

| 建议 Skill | 职责 | 边界 |
| --- | --- | --- |
| traffic-rule-context | 读取包内与当前情境有关的规则和合法替代方案 | 只给主体允许知道的规则；不返回隐藏设备状态 |
| travel-time-pressure | 用已知路线、时间和任务计算 ETA、slack、连续压力 | 可用只读确定性脚本，不推进时间、不声称全知 |
| travel-plan-adjustment | 对已获知的上轮实际结果维护/局部调整/重规划 | 更新个人有效计划记忆；不修改未授权外部截止时间 |
| travel-memory-reflection | 对重要或重复经历提炼有证据的认识 | 不将未知抓拍写入本人记忆，不必每步调用 |
| road-facility-observer | 解释请求者已经获准获得的设施观察 | 作为 Game Object 被动 atomic Skill；不抓拍、不处罚、不改世界 |

根 Brain 的自然语言 SOP 草案：

> 先查看本人的 IterationContext，辨认任务、当前地点、时间和已投递观察。检索有效出行计划及与当前情况有关的个人经验；上一轮有已获知的新结果时，修正个人计划，记录本人实际知道的内容。使用 world-perceive 观察附近道路及对象，需要路线估算时调用 world-navigate。结合包内适用规则、已知路线、当前时间压力和个人倾向，比较继续行驶、合法绕行、真实等待或经缺口进入机动车道等选择；不要预设压力或摄像头必然决定选择。必要时调用子 Skill 帮助计算、调整或反思。使用 memory-stream-append、memory-stream-supersede、memory-stream-invalidate 保存或修正个人认识，推測和客观证据分开。最后只调用一次 world-act 提交当前选择；提交后等待下一轮核对实际结果，不自报已经到达、已经被抓拍或已经免罚。

这是 SOP 设计草案，未保存为可导入 SKILL.md。`world-perceive`、`world-navigate`、`memory-stream-search` 和相应记忆写工具名必须在最终正文明确出现，当前工具暴露依赖这些名字。子 Skill 不可提交 world-act；根 Brain 的成功动作是本轮终点。

不新增交通活动枚举到系统；“保持车道”“违规进入”“绕行”属于本实验的选择分析标签。真正动作仍由通用 MOVE/WAIT 等表达，违规标签由客观规则核实。

## 4. 客观规则与记录输出

客观规则应是实验包内的确定性内容，至少明确定义：参与者类别、车道范围、违规触发和例外、抓拍覆盖与设备运行条件、是否随机抓拍、处罚触发、通知时机与收件人、是否影响行程。

如采用随机抓拍，必须保存可恢复的随机状态或按稳定事件身份导出随机结果，暂停续跑不能再次抽签。罚款数值或时间成本是研究者配置，不让 LLM 代为裁决。

建议事实最低内容：事件身份、关联动作、发生时间、涉事主体、规则 key、轨迹证据、设备 key、判定结果、处罚内容及知情状态。遵守 SPO + structured_payload，由合法提交链产出。研究记录中的 decision_reason、压力分值与记忆引用属于审计信息，不直接改变画面。

系统当前缺少该客观规则提交入口，不能把这些字段加入一个 Game Object 就宣称可用。完整实施需先确认能力方案。

## 5. 仿真参数与调用量

完整交通版本的 Step 时长目前待定，需要能表达接近缺口和减速事件的粒度。暂不输出虚假的秒级 simulation-settings.json；当前 schema 只接受分钟整数步长。

如果后续明确接受分钟级行为版本，可另评估 1 分钟一轮，禁止对快速接近、秒级抓拍及交通冲突作精确结论。长时记忆实验则需要足够行程长度与再次经过缺口的机会，不能用瞬移复位压缩为重复问答。

所有开始时间使用显式 `+08:00`；时间前进由 Scheduler 决定。每名 Agent 每步最多一个动作，交互反馈到下一步，因此一次 INTERACT 本身占用一个决策轮，观察设施能否直接感知应事先设计清楚，避免治理提示组平白多消耗一个时间步造成混淆。

调用量按 `Agent 数 × Step 数 × 每轮实际模型调用数 × Run 数` 估算，另计被动模型、记忆后继续决策、重试及固化。单轮先感知再决策通常需要至少两次模型往返，但这是估算而非固定架构。纯计算脚本不必占额外模型调用。不预先要求强制 1—3 步试跑；正式实验前的能力验收使用独立隔离测试即可。

## 6. 对应参考案例的最终输出件

| 参考案例输出类别 | 本实验最终应交付 | 当前状态 |
| --- | --- | --- |
| README、实验设计与落地 | 范围、研究问题、对照、管理台录入顺序、限制 | 本次已给设计与边界；正式录入顺序待能力确认 |
| map | 图像、四层节点、碰撞、路线、感知与抓拍范围、校准记录 | 本次给设计要求，未生成素材或地图配置 |
| agents | 人物设定、Studio definition、头像/骑行纹理、实验出生点 | 本次给字段与角色方案，未录入 |
| skill-definitions | 一个 Brain、按需子 Skill、只读脚本、依赖闭包 | 本次给职责和 SOP 草案，未制作正式包 |
| simulation-settings.json | 真实通过 schema 的时间/步数/模型等配置 | 等待时间精度与执行规模决定 |
| verification | 单元/集成/页面/模型/MCP/恢复及泄漏验证 | 本次有现有测试记录，未运行实验 |
| 源码核对与待解决项 | 当前能力矩阵与放行证据 | 本次已交付 |
| 实验特有补充 | 客观规则、条件矩阵、事件段定义、指标导出 | 本次定义研究口径，执行实现待确认 |

完成后，依次在 Studio 建公共资源、显式选择地图并完整导入实验、编辑实验内人物和任务、校验依赖及物理资源、封存独立 `.gaexp`、创建 Run。多个条件是独立自包含实验，不建立业务 Revision 或来源升级关系。
