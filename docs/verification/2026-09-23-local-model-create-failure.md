# 本地模型配置导致溪谷大学创建失败

## 证据与原因

用户确认问题发生在本地网页和本地模型，并要求按已配置参数处理，不设置替代默认值。本地 Web 访问日志存在连续三次 `POST /api/studio/experiments` 返回 422；此时未生成新 Run，尚未进入模型调用阶段。远程服务器没有对应的新 Run，本轮未修改远程服务或穿透配置。

通过本地网页按溪谷大学地图、人群、`context-driven-simulation-brain` 和现有模型配置重走创建最后一步，错误为：

```text
1 validation error for ModelsConfig
chat.vllm.secret_ref
Extra inputs are not permitted [type=extra_forbidden, input_value=None]
```

只读检查确认公共模型记录 `350d83b5-70c1-40d8-82de-8ae244f319b2` 的聊天配置实际含 `secret_ref: null`。该字段在当前 Protocol 中非法。原始访问日志仅有状态码，详细错误来自同路径浏览器复现，不声称访问日志包含完整错误体；本轮未确定该历史字段首次写入时间。

## 处理

通过模型中心打开已有配置“本机默认模型”，保持所有表单值及凭据不变，点击保存模型，由正常保存入口重建合法聊天配置。没有直接改数据库，没有新增兼容分支，没有放宽 Protocol，也没有修改产品源码。

保存前后逐项比对：唯一差异是删除 `chat.secret_ref`。聊天模型 `Qwen3.8-27B-UD-Q4_K_XL`、地址 `http://127.0.0.1:8888/v1`、90 秒超时、2048 最大输出、0.2 温度、凭据环境变量及其他参数全部一致；向量配置 `http://127.0.0.1:5002/v1` / `auto` 原样保留。“本机默认模型”是这条既有记录的名称，并非本次添加的默认回退。

## 验收与边界

- 模型中心按已保存聊天配置测试，页面显示“聊天模型调用成功”。
- 重启前检查未发现 Runtime worker 进程；目录中若干 9 月 7 日/14 日的残留 RUNNING/CREATED 记录未改写。通过既有 `restart-web.bat` 重启本地 Web，端口 8000 新监听 PID 66552，健康检查成功。
