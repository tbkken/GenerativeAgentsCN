# 地图 Skill 目录刷新修复记录

日期：2026-09-13。当前状态：**源码修复与工程回归通过，主 Agent 已通过公共地图的原浏览器路径验收：创建并保存新 Skill 后直接返回原地图，新项可选，未保存输入与当前选择保留。实验作用域与异步乱序仅有工程测试证据。**

## 已授权问题

地图“新港西路交通治理·核心街区”（`map_id: c333e061-c5df-4dc3-b9f9-3182671f550c`）已打开，随后用户在 Skill 工作区创建并保存 `traffic-camera-observe`，返回原地图后，东行道路摄像头对象的绑定下拉框仍只有旧目录的 3 项，找不到新 Skill。

原因是地图编辑器只在首次 `loadDocument()` 时读取 Skill 目录。公共地图工作区返回同一地图时复用编辑器，未重新读取目录；整个浏览器刷新后出现新项不能证明这个返回路径已修复。

工程子 Agent 只修复目录刷新机制，不修改上述地图、摄像头、Skill 或实验数据，不操作浏览器、不启停服务、不提交 Git。真实浏览器验收由主 Agent 执行，结果另记如下。

## 实现

- `generative_agents/web/static/map-editor-v2.js`：增加独立 `refreshSkillCatalog()`；首次加载地图以及工作区重新进入时均可调用。使用当前 `ResourceScope` 请求可绑定 Skill，不回查其他作用域。
- 刷新仅替换当前 Skill 下拉框的选项，保留下拉框本身、事件监听器、当前选择和焦点；不重绘检查器或整幅地图，不触碰其他未保存表单、节点选择和视图位置。当前已选但未出现在新目录的名称保留，避免静默清空待保存绑定。
- 刷新请求具有取消和递增代次校验；读取 JSON 后再次校验。过期请求、旧作用域响应不覆盖新目录；作用域变化时清除旧目录候选。请求失败有明确提示，返回地图页可以重试。
- `generative_agents/web/static/map-workspace.js`：每次进入地图工作区均触发目录刷新。公共工作区返回原地图继续复用编辑器。**实验工作区既有 `openMap` 重新加载语义保持不变**，不因同一 ID 跳过地图替换或包内内容刷新；本修改没有扩展其地图生命周期。
- 不新增跨资源全局事件；刷新与用户进入地图工作区的动作直接对应。

## 工程验证

新增测试文件：`tests/frontend/map-skill-catalog.test.cjs`。

新增 7 项行为测试覆盖：

1. 先打开公共地图，模拟另一个工作区保存新 Skill，再返回同一地图，新项可选；原地图文档、节点草稿、字段文字、焦点、选择和视图保持。
2. 目录刷新不清空当前未保存的 Skill 选择，即使新目录缺少该名称。
3. 新请求完成后，旧请求晚返回或晚解析 JSON 都不能覆盖目录。

5. 即使新作用域尚未开始刷新，旧作用域响应也不会被采纳。
6. 刷新失败可见、表单保留，再进入时可以重试。
7. 实验工作区继续执行原地图重新打开流程，目录请求仅访问该实验包。
