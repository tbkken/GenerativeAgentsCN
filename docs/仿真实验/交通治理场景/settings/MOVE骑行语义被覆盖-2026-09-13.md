## 影响与诊断边界

交通治理需要依据实际通行方式与路径判断骑行借道，而不是只知道发生了位移。当前正式事实的语义已经退化，这会影响当前状态展示与摄像头感知/判定所依赖的信息。尚未让人物进入摄像头监测区，**没有声称已复现摄像头漏拍或误拍**。

初次浏览器证据定位到“请求 → 已提交世界事实”之间存在语义改写。用户随后要求根因分析，主 Agent 只读检查源码，已确认覆盖发生在 `Game.commit_world_action`，并被 `StepResult._validate_world_fact_consistency` 的固定动词校验锁定。完整链路见下节。修复方案应保留可审计的真实移动方式，同时维持坐标、地址、路径与世界提交校验；不要求新增硬编码交通活动字典。

## 根因分析（2026-09-13，只读诊断）

### 已确认的处理链

1. **模型参数符合 MCP 暴露的字段。** `generative_agents/runtime/capabilities.py:132`–135 的 world-act schema 明确接受顶层 description、predicate、object、emoji。`_act` 在 651 行复制请求，MOVE 分支在 655–675 行校验路径并归一化目的地，没有在此处删除骑行语义。因此本问题不是模型写错了参数层级，也不是编辑器未保存 Skill。
2. **World Commit 无条件改写活动语义。** `generative_agents/modules/game.py:369`–375 先取得原始请求；496–516 行的 MOVE 分支随后强制设置 predicate="移动到"、object=实际落点地址，并重新生成 description。requested_* 仅用于审计。392 行还在没有显式 emoji 时固定使用步行图标。已经到达和只走完部分路径都会进入这个改写分支，无法仅靠更强的 Brain 措辞避免。
3. **相同值同时写入多个正式结果。** 同文件 518–543 行用改写后的值设置 agent.action、地图事件索引和 scratch.currently；557–580 行又用这些值生成结构化世界事实。下一轮 `generative_agents/runtime/brain.py:479`、483 直接读取 currently 和 current_action。因此不是 UI 独自换了显示文字。
4. **结果协议将固定文案当作合法性条件。** `generative_agents/runtime/results.py:255`–292 的 `_validate_world_fact_consistency` 既验证坐标、实际路径与地址，又在 286–289 行要求 AGENT_MOVED 的 predicate 必须等于“移动到”、object 必须等于实际地址。如果只取消 Commit 中的一行覆盖，仍会被这里拒绝。
5. **摄像头感知没有正式的移动方式字段。** `generative_agents/runtime/capabilities.py:508` 返回附近 Agent 的正式 current_action；`generative_agents/runtime/object_skills.py:103`–109 的 observed_actions 只投影 fact_id、event_type、agent_key、step_no、predicate、裁剪后的 visible_segments 等，将 MOVE 的 object 固定为“可见范围内的路径”。它不返回 requested_predicate/description。因此当前传感器观察链取得的正式动作缺少骑行方式；不能要求摄像头凭姓名、职业或模型猜测补全。仍未通过真实监测区运行复现漏拍/误拍。
6. **回放忠实展示了已被改写的事实。** `generative_agents/web/static/replay-player.js:396`–404 从 fact.action.description 与 emoji 绘制气泡，`console-api.js:2626` 用 action.description 展示检查器；这解释了实际界面的通用移动文字和步行图标。

根本设计问题：实现把“系统核验的空间位移事实”和“用户 Skill 定义的移动行为语义”放进同一组字段，并用固定文案代替后者。真实坐标/到达状态需要由内核保证，但这不需要清除骑行、步行、推行等自然语言活动信息。

### 为什么现有测试未暴露

- `tests/runtime/test_brain_capability_runtime.py:435` 的测试关注实际只走到过道时，不能把模型所说的“已经移动到洗漱区”当作落点；502 行直接断言 predicate="移动到"。它保护了真实落点，却没有同时覆盖合法移动方式的保留。测试名称与输入可确认这一关注点；没有据此推断历史修改者的主观意图。
- `tests/runtime/test_object_skill_runtime.py:187` 的摄像头测试在收到可见路径后由测试模型直接返回“抓拍”，断言的是范围裁剪、事实引用和记录成功，没有先判断可见活动是否确为电动自行车骑行。因此测试通过不能证明“骑行语义经真实 Commit 进入摄像头感知”已成立。

### 导航目标偏离的独立原因

实际请求链已经证明：导航目标 `[28,26]`，模型后来主动把 MOVE 目标改成 `[9,26]`。`capabilities.py:409` 返回的 next_coord 确实是 path[0]；工具描述在 95 行称它为“a next waypoint”，返回体没有明确重述目的地，也没有提示“MOVE 应继续使用原目标”。这是容易误用的接口表达。Brain 的明确说明没有被模型遵守，是直接行为原因；不能从一次调用推断模型内部思考或保证仅改措辞即可解决。

系统并未将该 20 格请求强行截成 1 格：`_act` 会对实际 MOVE 请求重新寻路；`game.py:366` 只在给定路径上按预算截取。默认算法 `generative_agents/config/algorithm.py:42` 为每分钟 4 格，`generative_agents/start.py:247`–258 按步长计算上限；目标只距 1 格时只存在 1 格路径。此处是源码默认能力说明，不把它冒充本 Run 已实测的最大移动速度。

### 诊断时的修复方向（历史记录）

统一调整 MCP 行为语义、World Commit、StepResult 校验及感知投影：保留由内核校验的实际坐标、路径与到达状态，同时将合法移动活动保存为正式、可感知的语义信息。避免直接信任“已经抵达”的自由文本，也不新增交通活动字典。补充骑行/步行/推行语义经过真实提交进入附近 Agent、摄像头和回放的完整链路检查。导航另需澄清原始目标、路径第一格和本步可移动边界的含义，不能由内核暗中替模型把相邻目标换成远端目标。

上述根因诊断阶段仅阅读源码和已有测试并更新诊断资料，未改系统代码、实验包、Skill 或 Run，未恢复仿真。

### 用户确认后的实施边界

上述根因分析之后，用户要求再次核对架构一致性，并明确授权工程子 Agent 修复。实施采用以下收紧后的方案：

- 保留 canonical MOVE 位移事件及真实坐标、路径、地址、抵达校验；不把取消固定动词校验作为必需修复。
- 复用 world-act 已有 predicate 表达自然语言移动活动，正式活动仅在 MOVE 通过校验且真实提交后保存；不给用户增加同义输入或交通活动字典。
- 移动活动与内核生成的空间事实分开保存，通过 Event、StepResult、感知和回放统一传递；不能读取 requested_* 给历史事实补写活动。
- 附近观察者仅获得可见活动和裁剪后的真实轨迹；不得因加入活动描述而泄漏未感知的目的地、未裁剪路径或范围外坐标。公开位移描述不展开计划目的地地址。
- 缺省活动不推断步行；工具说明澄清 next_coord 是路径第一格，实际 MOVE 目标仍由调用者明确指定。
- 原 Run 的前三帧与内嵌实验已只读计算 SHA256，保存在 `MOVE语义修复-验收基线.json`。修复后先核对原页面与历史保留，再通过 UI 恢复并验收新 Step；工程 Agent 不操作数据库、实验包、Run 或服务。

## 独立的模型行为观察（不是上述系统 bug 的根因）

Step 1 的 world-navigate 请求目标为 `[28,26]`，返回 reachable=true、distance_tiles=20、next_coord=`[9,26]`。Brain 正文明确说明 next_coord 只是路径第一格，并要求 MOVE 使用同一导航目标；模型随后在进度便签与实际 world-act 中选择了 `[9,26]`，真实只移动 1 格。这个目标选择偏离需要后续处理，但不能因此指责内核把 20 格移动预算截成 1 格——系统收到的目标本来就是相邻格。目前不把移动速度、是否按时到达或六组时间压力校准标成通过。

另有首个模型响应同时请求 world-perceive 和 memory-stream-search，未遵守每次一个工具的 SOP；这两项读取没有依赖猜测的导航目标。本次未把它混同为已发生的世界事实错误。
