## 预期与实际

预期：界面支持的对象感知参数能随 Skill 绑定保存，重新打开后仍存在。

发现时实际：服务端对地图编辑文档校验失败，拒绝以下字段：

```text
2 validation errors for MapEditorDocumentV2
hierarchy_nodes.10.skill_bindings.0.vision_radius
  Extra inputs are not permitted [type=extra_forbidden, input_value=24, input_type=int]
hierarchy_nodes.10.skill_bindings.0.attention_bandwidth
  Extra inputs are not permitted [type=extra_forbidden, input_value=8, input_type=int]
```

发现时页面顶部自动保存状态和操作失败提示均包含这两条诊断。节点局部“保存”提示不等于服务器持久化成功；当时绑定、监测状态与参数未得到保存确认，地图、背景和空间节点仍以先前成功保存的版本为准。

## 影响、证据与处理边界

- 影响：无法通过普通用户界面完成摄像头 Skill 绑定保存，阻断后续实验配置。
- 已确认的接口表现：前端可录入两个字段，而当前运行服务的 `MapEditorDocumentV2` 校验不接受它们。发现时尚不确定具体原因；后续经用户授权进行只读定位，已确认是运行服务未加载新版绑定模型，证据见下节。
- 证据：本会话浏览器 AX 返回完整错误、字段值和失败状态；随后截图显示地图顶部“自动保存失败”。截图时选中项为父级 Arena，故该截图不能代替此前 AX 中摄像头表单及字段错误的证据。未保存独立截图文件。
- 已停止：未移除字段绕过保存，未重复试存，未改源码、直接接口、数据库或实验目录，未启停服务，未交给工程子 Agent。
- 与此前已修复的目录刷新问题分别记录；新建 Skill 可选已经通过浏览器验收，不代表这次持久化路径也通过。

### 直接证据

1. 监听 `127.0.0.1:8000` 的进程为 PID `27496`，启动时间为 **2026-09-13T07:15:57+08:00**。命令使用 `C:\ProgramData\anaconda3\python.exe -m generative_agents.web.main`，目标工作数据路径位于本仓库。`var/logs/web.stderr.log` 同样记录 `Started server process [27496]`。
2. 只读请求 `http://127.0.0.1:8000/openapi.json`，当前在线 `GameObjectSkillBinding` 声明只有 `interaction_key`、`skill_name`、`description`、`interaction_radius_tiles`、`default_request` 五个属性，并且 `additionalProperties=false`。**缺少的正是浏览器保存报错的两个属性。**
3. 本仓库 `generative_agents/config/game_object_skills.py` 第 40–41 行已声明 `vision_radius` 和 `attention_bandwidth`，均允许 0–100 的整数。该文件修改时间为 **2026-09-13T13:07:47+08:00**，晚于 Web 进程启动。
4. 使用同一个 `C:\ProgramData\anaconda3\python.exe` 从本仓库新建只读诊断进程，实际导入路径确认是 `E:\GenerativeAgentsCN\generative_agents\config\game_object_skills.py`，模型包含全部七个属性。构造独立内存四层地图，设置摄像头绑定 `vision_radius=24`、`attention_bandwidth=8` 及本次监测状态，`MapEditorDocumentV2.model_validate` 与地图保存所用的 `normalize_public_world` 均通过，输出保留两个参数。该内存样例不是真实地图持久化或浏览器保存验收。

### 因果链与处理方向

地图保存沿 `ga_studio/resource_api.py:update_map` → `services/maps.py:update_map` → `normalize_public_world` → `MapEditorDocumentV2` → `GameObjectSkillBinding` 校验。在线旧模型禁止额外字段，因此拒绝浏览器提交的新参数；此时尚未进入数据库更新事务。

`web/main.py` 的 `uvicorn.run` 使用单个 worker，未启用 reload。Python 模型在服务进程中保持旧定义；另一方面，`ga_studio/web.py` 通过 `StaticFiles` 提供磁盘上的前端文件，并要求浏览器重新校验缓存，所以刷新页面可以拿到新 JS，却不会更新服务内存里的 Python 模型。这产生了“新前端＋旧后端”的组合。

结论：当前源码没有漏声明这两个字段。本问题的直接根因是此前对象能力实现后，Web 进程未更新，浏览器已加载新版前端。此前进入系统验收前漏核对运行服务是否加载新后端，这是验收准备的遗漏。

诊断结论提出：应安全重启 Web 使其加载现有新代码，再验证在线绑定声明与原浏览器保存路径；不应通过删字段、允许任意额外字段或再补一套重复模型来绕过。定位当轮尚未执行重启，内存校验通过不构成地图保存验收。用户随后明确授权重启，处理如下。
