# Game Object Skill 运行合同

2026-09-13 按用户确认的设计实现：给 Game Object 绑定一个 Skill，就同时启用自主执行、周围感知和交互响应。用户用自然语言描述对象行为，不设置主动/被动模式、触发器或必需脚本。

## 作者使用方式

在地图编辑器的 Game Object 中选择“对象 Skill”。需要多项能力时，在一个根 Skill 的 SOP 中组合子 Skill。常规使用只需选择 Skill；感知范围、注意力、交互距离及请求说明放在折叠的高级参数内。

根 Skill 默认通过大模型执行，自动获得对象允许的公共 MCP，不要求正文先列出工具名。子 Skill 可以用自然语言或可选脚本实现；子 Skill 不获得 `world-act` 提交权限，最终动作由根 Skill 提交。

例如，摄像头 Skill 可以要求“观察附近骑行者及实际经过的路径，按本实验的规则判断是否记录抓拍，保留证据，同一次连续活动不要重复记录”。这些判断由模型按 Skill 执行，内核没有交通违法字典或硬编码抓拍策略。

## 身份、感知与动作

- 对象以稳定 `object_key` 运行，上下文使用 `game_object`，不会注册成公共 Agent，也不会混进人物列表。对象记忆使用 `game-object:<object_key>` 身份空间，不能冒充 Agent 或其他对象。
- `world-perceive` 复用 Agent 的四层语义感知、附近 Agent 位置和活动、附近对象、视野上限和注意力约束。对象另外可以获得本步已执行活动的可见证据，包含事实 ID 和裁剪后的路径片段，不提供未执行计划路径或视野外坐标。
- 固定设施可通过 `world-act` 提交 `ACT`、`WAIT`、`SET_OBJECT_STATE`。对象只能修改自己的状态；绑定 Skill 的对象由其 Skill 判断如何响应操作请求，Agent 不能直接更改它的状态。
- `ACT` 的自然语言 predicate/object 记录设施活动。可指定已感知的 `target_agent_key` 和实际返回的 `evidence_ids`，内核绑定原始证据，不接收模型编造的结构化证据。
- `idempotency_key` 标识同一项不可重复的活动。活动如何分段由 Skill 判断；内核保证同一对象的同一键在跨步和恢复后不能再次提交。不同键并不自动被判为同一次活动，业务判定质量仍需实验评估。
- 根 Skill 每轮最多一次 `world-act`。模型的“已切灯”“已抓拍”或最终回复文本本身不修改世界。模型判断是否合理与动作是否已提交是两个不同的评估维度。

对象自身可以读取完整状态；其他参与者仅看到绑定对象的 `state` 外观标签。内部参数、活动键和私有记忆不因靠近而公开。自然语言交互回复由 Skill 明确决定披露什么。

## 自主执行与交互时序

每 Step 先执行 Agent 的合法世界动作，再按稳定对象 ID 执行每个绑定对象一次，最后冻结并持久化完整 StepResult。每个对象即使没有收到交互也执行；调度不规定 Skill 必须按感知、计划、反思的顺序调用能力。

Agent 的 `INTERACT` 先形成请求事实和稳定请求 ID，不在骑手的身份下执行对象代码。对象轮次收到自己待处理的请求，可以在本轮动作的 `responses` 中指定请求 ID 和回复文本；同一动作既可修改灯色，又可回复真实请求。

回复只投递给原请求者，下一轮进入其上下文且只消费一次；其他 Agent 不获得副本。没有被回复的请求继续保留。当前每轮最多提供 100 个待处理请求，并显示待处理总数。

**时序含义：对象本步修改的状态和回复供下一轮 Agent 使用。** 灯色规则应明确这种离散时间边界，不能把对象阶段刚切换的灯色视为本步之前 Agent 行动时已经存在的灯色。当前系统仍是整数分钟步长，本次没有实现秒级交通动力学。

## 文件协议、记录与恢复

对象根 Skill 在 `skills/registry.json` 的 `object_roots` 声明，条目 kind 为 `object`；递归子 Skill 和资源仍物理复制进实验和 Run。源资源后续修改不影响已有 Run。当前协议不再接受旧 `passive_roots` 表达；需要使用新能力的实验应重新导入形成自包含包，不改写已有封存证据。

对象动作、状态变化和回复都写入含 SPO 与 `structured_payload` 的领域事实。对象 Skill Trace 写入 `SKILL_EXECUTED`，使用 `OBJECT_SKILL_RUNTIME` 来源与 `object_key`；对象不会伪装成 AgentStepResult。

检查点同时保存对象状态、待处理请求、上次动作、最后提交 Step、幂等活动键和连续失败计数；对象私有记忆沿用文件记忆的检查点导出与恢复。恢复保持 run_id，创建新 attempt_id，并从最近提交边界继续。

模型基础设施负责超时、网络重试与取消；SkillRuntime 负责调用预算、子 Skill 深度和重复调用保护。可恢复失败回滚本轮私有记忆与未提交动作，保留请求并记录 WAIT 回退。质量报告单独显示对象问题与 `evaluated_object_steps`，不将对象执行次数混入 Agent 次数。

回放读取对象状态变化的 `object_key` 与 `after`，不重新调用模型判断灯色或抓拍。运行估算同时计入 Agent 和绑定 Skill 的对象数量。

## 验证范围

自动化覆盖自然语言对象默认工具、无人交互自主状态提交、视野外端点之间的可见实际路径、证据身份、权限和私有记忆、交互回复隔离、跨 Attempt 去重、模型文本不直接改世界，以及完整文件包启动、暂停恢复和回放。

模型响应使用可控测试替身，通过真实 SkillRuntime 工具循环和 Runtime 文件提交链执行。这证明机制与合同，不代表已经验证具体大模型的交通判断准确率。交通治理实验的正式地图录入、模型实测、车流与路线成本验证仍独立进行。

本次测试命令、通过数量、文件包恢复证据与扩展旧测试的未通过项见 [实现验证记录](game-object-skill-verification-2026-09-13.md)。
