# 实验包构建 UX 与交互边界

状态：实施基线
版本：4.0
日期：2026-09-03

## 1. 产品定义

Studio 是实验包 IDE，不是实验运行的事实源。公共地图、空间素材、Agent、Crowd、Brain、子 Skill、Game Object 被动 Skill、模型预设和评估器是可复用作者资源；加入实验的动作等同于“复制进实验目录”。

用户在 Studio 之外手写同样的目录也能运行。Web 所有编辑最终都必须落到 `.gaexp` 协议文件，所有运行与回放页面最终都必须读取 Run 目录或 `.garun`。

## 2. 用户看到的三个层次

| 层次 | 用户心智 | 可写内容 | 身份 |
| --- | --- | --- | --- |
| 公共资源库 | 可反复使用的素材架 | Map、Agent、Crowd、Brain、Skill、模型、评估器 | Studio 资源 ID，仅用于选择 |
| 实验工作区 | 一份自带全部材料、可以带走的项目目录 | 包内地图、Agent、Skill、模型和运行配置 | `manifest.json.experiment_id` |
| Run 工作区 | 一次执行及其恢复、审计和回放文件 | 状态、Attempt、Frame、Checkpoint、Trace、Artifact | `run.json.run_id` |

公共资源 ID 不进入 Runtime 的依赖合同。选择完成后，即使公共资源被修改或删除，实验卡片也不能显示“引用丢失”，因为实验已经拥有自己的物理副本。

## 3. 新建实验

向导要求明确选择：

1. 一张地图；
2. 一个 Brain；
3. 零到多个 Agent 或 Crowd；
4. 模型预设；
5. 可选评估器。

系统不提供默认地图。用户点击“创建实验”时，服务端在同一个构建操作中完成：

- 解析地图及全部空间素材；
- 展开 Crowd 为独立 Agent 副本；
- 解析 Brain 的递归子 Skill 闭包；
- 解析所有 Game Object 被动 Skill；
- 复制 Skill Markdown、脚本、地图资源和 Agent 资源；
- 写入包内配置与完整性清单；
- 返回 `experiment_id` 和实验目录。

任一依赖缺失则创建失败，不产生半成品实验记录。界面不询问 Revision，不展示“跟随最新”或“升级到新版本”。

## 4. 实验编辑

### 首页列表交互（2026-09-13）

实验、地图、智能体、人群、技能、大脑和模型使用同一套横向条目结构：名称、用途摘要、关键属性，以及固定在右侧的“打开”和“更多”。页头只保留一个新建入口。删除收进更多菜单，确认时显示真实名称和影响范围。

所有列表固定每页 5 条，使用相同的分页、加载、空结果和失败重试样式。基础配置的搜索位于工具栏左侧；技能类型和模型用途筛选位于右侧。实验保留归档、恢复和分页，不新增搜索、组合筛选、状态计数或保存视图。

列表分别保存分页、搜索、类型和离开时的滚动位置。返回列表重新读取服务端内容，并恢复原浏览范围；延迟响应不能覆盖其他列表或恢复其他页面的滚动位置。地图、技能和模型编辑支持 URL 定位，实验继续导航到独立文档。

实验列表先用可重建的 Studio 目录索引完成归档过滤、排序和分页，再读取当前页最多 5 个实验的摘要。最近 Run 只读取包内 Manifest、状态及身份信息，不在列表中扫描历史 Step、重建质量报告或校验恢复快照；这些工作仍由结果与恢复入口执行。归档包中的状态直接读取 ZIP 成员，不解压完整 Run。

首页首次加载只发起一次列表请求。同页请求合并；当前页有 CREATED、QUEUED、RUNNING 或 FINALIZING 的 Run 时，在上一次请求结束 3 秒后再刷新。离开列表或隐藏页面时停止请求和计时，重新获得焦点时读取一次当前状态。新建、复制、删除和归档后要求一次新的读取，避免复用操作前尚未返回的数据。

基础智能体列表只显示角色摘要和图片配置情况，完整身份、特质与计划在原智能体编辑器中查看。模型按一份配置展示一条，聊天与向量用途共同列出；打开后编辑对应用途，保存一个用途不会删除另一个用途。编辑器内部的地图、技能、成员和模型能力继续复用原实现。

### 工作区入口（2026-09-12）

基础工作区侧栏分为“实验”和“基础配置”。基础配置依次为地图、智能体、人群、技能、大脑、模型。

实验列表中的打开操作导航到独立地址 `/experiments/{experiment_id}`。该文档只显示当前实验的八个入口：实验概览、实验结果、地图、智能体、人群、技能、大脑、模型；顶部持续显示实验名称和独立副本说明。基础配置通过返回实验列表重新进入，编辑器不会在同一文档中切换保存归属。

地图、人群、技能和大脑复用基础工作区的编辑器，实验适配器只读写当前包内文件；图片上传同样写入当前实验。所有修改校验当前内容哈希，过期保存返回冲突，失败保存回滚相关文件及完整性清单。已封存实验可查看和校验，不能保存配置。

基础智能体不包含地图坐标与空间地址；实验智能体保留“初始位置与空间”Tab，使用包内地图验证出生点和语义地址。实验创建时除了展开智能体定义，还将人群分组写入 `agents/index.json` 的 `crowds`，成员只保存包内 `agent_key`。同一智能体可参与多个分组；删除分组保留智能体，删除实验智能体同时从包内分组移除。旧包若没有保存分组，可在实验内用现有智能体创建分组，不回查基础人群推断来源。

技能编辑保留 Markdown、私有脚本、依赖查看与独立试运行。实验内试运行只使用包内技能闭包及聊天模型配置；需要世界或私有记忆 MCP 的调用仍需进入正常仿真。

实验内编辑器直接编辑包内副本：

- 地图页面编辑 `world/world.json` 和包内 assets；
- Agent 页面编辑 `agents/index.json`；
- Brain/Skill 页面编辑 `skills/items/*` 与 `skills/registry.json`；
- 模型页面编辑 `models/models.json`，密钥只选择环境变量名；
- 运行页面编辑 `runtime/simulation.json` 与 `runtime/engine.json`；
- 评估页面编辑 `evaluation/evaluators.json`。

保存地图后由 Studio 重新生成 `world/semantic-index.json`；该文件是实验包内派生索引，不引用公共地图，也不能由 Runtime 回查数据库补齐。

编辑保存后重新计算实验根哈希。公共资源库完全不变化。用户若希望复用实验内改良内容，执行显式“另存为公共资源”；这是一份新资源复制，不建立双向关联。

地图、Agent 或 Skill 可以再次从公共资源库拖入实验。这个动作仍然是一次新的复制：替换哪个包内对象由用户明确选择，不进行版本对比或自动合并。

## 5. 目录与归档

实验工作区始终有两个等价操作：

- “打开目录”：继续编辑普通文件；
- “导出 `.gaexp`”：生成确定性 ZIP，便于传输和保存。

导入 `.gaexp` 时先安全解压和完整性校验，再以清单中的 `experiment_id` 建立导航。文件名仅用于展示。若 Studio 已存在相同 `experiment_id` 的不同内容，必须提示身份冲突，不能偷偷分配新 ID 或按文件名覆盖。

## 6. 运行交互

“开始运行”只做三件事：

1. 用实验包创建新的 Run 目录并生成 `run_id`；
2. 把完整实验包复制到 Run 的 `experiment/`；
3. 让文件化 Runtime 进程获得该 Run 目录。

Studio 进程不把数据库连接传给 Runtime。页面状态读取 `status.json`、`projection.json` 和文件化日志。

操作语义：

| 操作 | `run_id` | `attempt_id` | 输入 |
| --- | --- | --- | --- |
| 新跑 | 新建 | 新建 | `.gaexp` 或实验目录 |
| 暂停后续跑 | 保持 | 新建 | 活动 Run 目录 |
| `.garun` 续跑 | 保持 | 新建 | 校验后安全解压的可写目录 |
| 重跑 | 新建 | 新建 | 原 Run 内嵌实验 |

已完成 Run 的主操作是“重跑”，不是“续跑”。续跑从最后完整检查点的下一 Step 开始；没有检查点时不能伪造恢复。

## 7. 回放交互

实验记录列表由 Studio 的可重建包目录提供。用户选择 `run_id` 后，Web 直接调用文件化 Replay：

- 概览显示 Run、Experiment、Attempt 和来源 Run；
- 时间线按 Step 读取已提交 Frame；
- 任意 Step 状态由 StepResult 归约；
- 地图和渲染资源来自 Run 内嵌实验；
- 对话、Agent 动作和对象变化来自结构化事实。

切换 Run、Attempt 或 Step 时，前端请求必须携带当前 `run_id` 和范围；旧异步响应不能覆盖新选择。回放不显示或执行 Brain，不重新解释记忆，也不读取 Studio 的旧结果投影表。

## 8. Studio 数据库导航

数据库中的实验/Run 记录是以下字段的缓存：

```text
package_kind
package_id
experiment_id
run_id
package_location
display_name
status
content_sha256
```

用户执行“重新扫描包目录”即可清空并重建这些记录。数据库记录与包清单不一致时，先报告冲突，清单优先；不得用数据库字段改写包身份。

## 9. 错误呈现

需要直接展示并定位的错误包括：

- ZIP 路径穿越、符号链接、重复成员或超限展开；
- 清单入口缺失；
- 内容哈希变化；
- Brain、子 Skill 或被动 Skill 闭包不完整；
- 地图四层结构、坐标、语义地址或资源路径无效；
- Agent 初始位置不属于包内地图；
- 模型密钥环境变量未提供；
- Run 的内嵌实验 ID 或哈希不匹配；
- Frame 不连续或与 `status.committed_step` 不一致；
- 恢复点不完整；
- 相同包 ID 出现在多个不同位置。

错误不能退化为一个没有明细的计数。每条诊断至少包含文件路径、字段路径或 Agent/Step 定位。

## 10. 验收标准

1. 创建实验后删除所有选中的公共资源，实验仍能校验和运行。
2. 公共资源修改不改变现有实验根哈希。
3. 实验内修改不改变公共资源。
4. 所有 Brain、子 Skill、被动 Skill 与脚本在 `.gaexp` 中可见。
5. 实验配置和 UI 中不存在 Revision、跟随最新、升级映射或发布锁。
6. `.gaexp` 改名、目录改名不改变 `experiment_id`。
7. `.garun` 改名、目录改名不改变 `run_id`。
8. Runtime/Replay 在没有 Studio 数据库时可新跑、续跑、重跑和回放。
9. Run 内嵌实验删除其原始 `.gaexp` 后仍能重跑。
10. Web 回放只读取 Run 文件，不查询运行事实数据库表。
11. Studio 包目录可以从磁盘清单完整重建。
12. 相同内容重复封装产生相同的归档字节。
